# BUG-002：用任务级基准判断单次调用 → 第一次成功后就再也不干活

> 状态：✅ 已修复 · 记录 2026-10-24 23:00
> 位置：`src/agent/library/atom_drops.js` + `skill_collect.js`

---

## 现象

主服基线拿到 4 个木头后就再也涨不上去（`拿到=4/8`），而挖和走都正常。

测试服上更明显：`skill_collect` 的 `gained` 在 0 和 6 之间跳，不稳定。

## 根因

`collectDrops` 的成功判据是「背包增量 > 0」：

```js
const gained = () => countFn() - baseCount;
```

而 `baseCount` 由调用方传，`task_collect` 传的是**任务开始时的数量**：

```js
const handlers = makeHandlers({
    countFn: countAll,
    baseCount: startCount,     // ← 任务开始时的数量
});
```

于是：任务里捡到第 1 个之后，`countFn() - startCount` **恒为真**，
后续每次 `collectDrops` 一进函数就判定“已经拿到”，立刻返回成功——
**后面挖的全都不会再捡**。

## 为什么难发现

- 报数始终诚实（背包几个报几个），所以看不出“承诺未兑现”
- 表面上“捡到了”，只是数量停在一个固定值不动
- 在测试服（树密集、掉落物直接飞过来）时，靠服务端自动吸附也能拿到一些，
  所以问题被掩盖成“偶发不稳定”

## 修法

**判据基准改成「这次调用开始前」的数量**，而不是任务开始时的数量。
默认在 `collectDrops` 开场自己快照；调用方想显式指定仍可以传 `baseCount`。

```js
// atom_drops.js
let base;
if (Number.isFinite(opts.baseCount)) base = opts.baseCount;
else { try { base = countFn(); } catch { base = 0; } }
```

```js
// skill_collect.js makeHandlers：只在显式给了才传
const opts = { countFn, onStep: onEvent };
if (Number.isFinite(baseCount)) opts.baseCount = baseCount;
```

## 效果

| | 修复前 | 修复后 |
|---|---|---|
| `skill_collect` 的 gained | 0~3（不稳） | **6（两次都稳定）** |
| 主服 5 轮平均拿到 | 6.8/8 | 待测（见 run_opt.log） |

## 教训（写进经验教训）

**「判据的基准要对齐判据的意图」**：
- 想问"这次调用有没有效果" → 基准必须是"这次调用开始时"
- 想问"整个任务有没有进展" → 基准才是"任务开始时"

混用会让判据在第一次成功后永久变真，而它看起来仍然"在工作"。

这是**静默失效**，比报错危险得多。同类风险点：
- 任何"增量 > 0"的判断
- 任何带 `since` / `base` / `start` 的对比
