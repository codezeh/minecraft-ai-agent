## 一、游戏规则（规划必须基于这些）

### 1.1 挖掘

| 规则 | 值 | 来源 |
|---|---|---|
| **能否挖的判定** | `方块中心` 到 `眼睛(脚+1.65)` 距离 **≤ 5.1** | `[源码]` digging.js:221 |
| 我之前的错误 | 用了 4.3，今天改成 4.5 —— **都不对，实际是 5.1** | `[源码]` |
| 挖原木的时间 | 手 3.0s / 木斧 1.5s / 石斧 0.8s / 铁斧 0.5s | `[数据]` 硬度2 |
| 挖树叶 | 0.3s（手），0.1s（斧） | `[数据]` 硬度0.2 |
| 原木需要工具吗 | **不需要**（`harvestTools` 为空，手也能挖） | `[数据]` |
| 石头需要工具吗 | 需要**镐**（木镐以上）；**斧头挖不了石头** | `[数据]` harvestTools 只有 877~902(镐) |
| 基岩 | `diggable: false`，硬度 -1 → 永远挖不了 | `[数据]` |
| 水/岩浆 | 硬度 100，`boundingBox: empty` | `[数据]` |

**对原子的影响**：
- `digBlock` 的前置断言用 **5.1**，不是 4.5
- `NO_TOOL` 判定要用 `harvestTools` 列表 + 手持物品 id，不能只看"是不是斧头"

### 1.2 物理

| 规则 | 值 | 来源 |
|---|---|---|
| **方块不会因失去支撑而掉落** | 原木、石头、木头等都不受重力 | `[数据]` 受重力的只有 sand/gravel/anvil/concrete_powder 等 |
| 受重力的方块 | sand, gravel, anvil, dragon_egg, scaffolding… | `[数据]` |
| 挖掉落方块下方会砸**自己** | 沙子/沙砾掉下来有伤害，其他没有 | 游戏规则 |
| 跳跃高度 | 1.25 格 → 能上 1 格台阶，上不了 2 格 | `[源码]` physics |
| 摔落伤害 | 3 格内不受伤 | 游戏规则 |
| 行走/冲刺速度 | 4.317 / 5.612 格每秒 | `[数据]` |

**对原子的影响**：
- **不需要"砍伐顺序"**（方块不塌），只需要考虑效率
- `digBlock` 要检查"上方有没有受重力的方块"（否则会砸自己 / 或砸坏掉落物）

### 1.3 放置

| 规则 | 说明 | 来源 |
|---|---|---|
| **客户端不做距离校验** | `bot.placeBlock` 只发包，服务端判定 | `[源码]` place_block.js（38 行，无 distanceTo） |
| 放置失败的表现 | `blockUpdate` 500ms 内没触发 → 抛 `No block has been placed` | `[源码]` place_block.js:17 |
| 需要的条件 | 目标格是空气/可替换 · 有相邻的"可依附面" · 手里有方块 | 游戏规则 |
| 不能站在要放的格子里 | 会把自己挤开或失败 | 游戏规则 |
| **`blockUpdate` 会静默丢** | 已实测：放成功了但事件没到 | `[实测]` 今天多次遇到 |

**对原子的影响**：
- `placeBlockAt` 的失败必须**读世界确认**（`blockAt` 看是不是真的变了），不能只信异常
- 错误码要区分：`NO_SUPPORT`（没依附面）/ `OCCUPIED`（格子被占）/ `BLOCKED`（客户端丢事件，重试即可）

### 1.4 交互（`use`）

**这是最容易被"一个泛化原子"搞错的地方** —— 右键在不同方块上作用完全不同：

| 方块类别 | 数量 | 右键作用 |
|---|---|---|
| 容器 | 7 种 | 打开界面（箱子/桶/漏斗/发射器） |
| 工作站 | 12 种 | 打开对应界面（工作台/熔炉/铁砧/附魔台…） |
| 门类 | 4 种 | 开关（门/活板门/栅栏门） |
| 红石开关 | 4 种 | 切换状态（拉杆/按钮/压力板） |
| 床 | 2 种 | 睡觉（需要夜晚+安全） |
| 农作物 | 4 种 | 收割（成熟时） |
| 其他 | 10 种 | TNT 点火 / 钟 / 堆肥桶 / 篝火… |

**对原子的影响**：
`use` 不能是一个泛化原子。必须按方块类别分派，至少拆成：
- `openContainer(pos)` → 返回窗口/容器句柄
- `useWorkstation(pos)` → 返回界面
- `toggleBlock(pos)` → 门/拉杆/按钮
- `sleep(pos)` → 床

### 1.5 实体交互

| 类型 | 右键/左键作用 |
|---|---|
| mob / player | 攻击 |
| villager / wandering_trader | 打开交易界面 |
| horse / pig / boat / minecart | 骑乘（需要鞍/船） |
| animal | 喂食（手持食物）/ 繁殖 |
| sheep | 剪毛（手持剪刀） |
| leashable | 牵引 |

**对原子的影响**：`attackEntity` 只覆盖攻击；交易/骑乘/喂食各自是独立能力，**首版不做**（用户明确说过不要骑乘）。

### 1.6 树叶衰减（对采集有直接影响）

| 规则 | 值 | 来源 |
|---|---|---|
| leaves 的 state | `distance: 1~7`（距最近原木的距离）+ `persistent: bool` | `[数据]` |
| 衰减条件 | `distance = 7`（离原木超过 6 格）且非 persistent → 自动枯萎 | 游戏规则 |
| **不能用来判"人造/自然"** | 实测自然树叶也会 `persistent=true` | `[实测]` |

**对采集的影响**：**原木砍完，叶子会自动消失，不用挖**。

### 1.7 官方插件的能力边界（已验证）

| 能力 | 结论 | 来源 |
|---|---|---|
| `findFromVein` 找整棵树 | ✅ 能用，但**返回重复坐标** | `[实测]` 7 格树返回 40 格（含重复） |
| `collect(blocks)` 一次挖一批 | ⚠️ 能用，但 `getClosest()` **纯按距离** → 先砍底部 → 上面悬空够不到 | `[官方]` Targets.js:34 |
| `GoalLookAtBlock` 走到能挖的位置 | ✅ 能用，**配合 `allow1by1towers` 能自己垫上去**（实测 6 格高差，4.8 秒） | `[实测]` |
| 垫脚需要材料 | ✅ `scafoldingBlocks` 要配，背包里要真有 | `[实测]` |
| 等掉落物 | ✅ 订阅 `itemDrop` 事件 | `[官方]` |
| 背包满自动存箱 | ✅ `emptyInventoryIfFull` | `[官方]` |

## 二、基于规则的原子清单（最终版）

### 2.1 感知（只读，返回数据不返回 ActionResult）

```js
blockAt(bot, pos)                  → Block | null
findBlocks(bot, names[], radius)   → Block[]（按距离排序）
countItems(bot, name)              → number
distanceToEye(bot, blockPos)       → number   ← 统一用「方块中心到眼睛」
findEntities(bot, filter, radius)  → Entity[]
```

**统一约定**：所有距离都用 `方块中心 → 眼睛(脚+1.65)`，与 mineflayer 的 5.1 判定同口径。

### 2.2 动作（7 个，自带前置断言 + 后置校验）

| 原子 | 前置断言 | 后置校验 | 特有错误码 |
|---|---|---|---|
| `moveTo(target, tol)` | 目标可站/可达 | 到达且距离 ≤ tol | `NO_PATH` |
| `digBlock(pos)` | ①`diggable` ②距离 ≤5.1 ③能正确收获 | `blockAt(pos)` 变空气/已变 | `NO_TOOL` `OUT_OF_REACH` |
| `placeBlockAt(pos, item)` | ①手里有 item ②格子是空气/可替换 ③有依附面 ④不站在这格 | `blockAt(pos)` == item（**读世界，不信异常**） | `NO_ITEM` `NO_SUPPORT` `OCCUPIED` `BLOCKED` |
| `equipItem(name)` | 背包含该物品 | `bot.heldItem.name` == name | `NO_ITEM` |
| `openContainer(pos)` | 是容器且距离 ≤5.1 | 窗口已打开 | `NO_TARGET` `OUT_OF_REACH` |
| `useBlock(pos)` | 类别属于"可交互"且距离 ≤5.1 | 状态变化（门开/按钮触发） | `BLOCKED` |
| `attackEntity(entity)` | 实体有效且在攻击范围 | 目标掉血/死亡 | `NO_TARGET` |

**`digBlock` 的 5.1 是今天最重要的修正**：我用了 4.3→4.5 都不对。

### 2.3 决策（纯函数，不碰世界）

```js
resolveTargetName(raw, registry)      → { kind:'single'|'category', names[] }
isProtected(pos, landmarks)           → bool
classifyLog(bot, pos)                 → { tree, why, leaves, artificial }   ← 唯一的"辨别"
planOrder(items, from)                → 排好序的 items
```

### 2.4 复合（只做：枚举 → 循环 → 校验 → 降级）

**统一模板**（`placePlatform` 已经就是这个形状）：

```js
async function runCompound(bot, items, policy, opts) {
  const state = new Map();     // key → 'todo'|'done'|'failed'
  for (const item of orderBy(items)) {
    if (interrupted() || timeout()) break;
    if (await alreadyDone(bot, item)) { mark('done'); continue; }   // 幂等
    for (let attempt = 0; attempt < opts.attempts; attempt++) {
      const r = await executeAtom(bot, item);
      if (r.ok && await verify(bot, item)) { mark('done'); break; }  // 后置校验
      const action = policy[r.code] ?? 'next';
      if (action === 'abort') return report('abort');
      if (action === 'restep') { await restep(bot, item); continue; }
      if (action === 'wait')  { await sleep(300); continue; }
      if (action === 'rescan'){ items = await rescan(); continue; }
      mark('failed'); break;
    }
  }
  return report();
}
```

## 三、每个技能按规则重新定义步骤

### 3.1 `collect`（采集）— 唯一有"辨别"的复合

| 环节 | 内容 | 依据 |
|---|---|---|
| 工具 | 木头**不需要工具**（手也能挖，只是慢 3 倍）；要快就造斧 | `[数据]` harvestTools 为空 |
| 枚举 | 找全部同名原木 → **去重** → 按 x,z 聚列 → 每列算树干高度 | `[实测]` 官方 findFromVein 有重复 |
| 排序 | 距离绝对优先（差>5 格纯按距离，否则比产出） | `[实测]` 按产出排序会绕远路 |
| 查状态 | 还是原木吗 / 黑名单 / 保护区 / **是天然树吗** | `[实测]` classifyLog 97.6% 通过、0 误杀 |
| 执行 | ①`moveTo` 到能挖的位置（≤5.1）②清视线藤蔓 ③`digBlock` ④捡 | — |
| 校验 | 那格是空气了吗 + 背包 count 增加了 | — |
| 降级 | `OUT_OF_REACH`→换站位（含垫脚）·`NO_PATH`→换站位·`BLOCKED`→等300ms重试·无更多目标→扩半径 | — |
| **不需要** | 砍伐顺序（方块不塌）·树型分档（无物理依据）·挖叶子（自动衰减） | `[数据]` |

### 3.2 `placePlatform`（铺平台）— 已是标准模板

| 环节 | 内容 |
|---|---|
| 枚举 | 9 格 → 按距离排序 |
| 查状态 | **幂等**：已是目标方块就跳过 |
| 执行 | `placeBlockAt`，最多 3 次 |
| 校验 | `blockAt` 确认（不信异常） |
| 降级 | `OUT_OF_REACH`/`NO_PATH`/`OCCUPIED`→换站位 · `BLOCKED`/`INTERNAL`→等300ms · `NO_ITEM`/`NO_SUPPORT`→放弃这格 |

### 3.3 `follow` / `goToPlayer`（跟随/找人）

| 环节 | 内容 |
|---|---|
| 枚举 | 玩家位置（visible / lost / recalled） |
| 执行 | 远（>40格）→ 两段规划移动；近 → `moveTo` |
| 校验 | 距离 ≤ 要求 且 能看到人 |
| 降级 | 看不到 → 去最后位置找；走不到 → 重试 2 次 |

### 3.4 其余技能

| 技能 | 结构 | 说明 |
|---|---|---|
| `craftRecipe` | 循环+幂等 | 递归展开中间产物；需要工作台就先放 |
| `smeltItem` | 循环+幂等 | 已有 4 个子函数，只是没串起来 |
| `putInChest`/`takeFromChest` | 循环+幂等 | 逐槽移动 |
| `attackNearest`/`defendSelf` | 单目标循环 | — |
| `goToBed` | 单目标 | 需要夜晚 + 安全 |
| `tillAndSow` | 循环+幂等 | 引水→锄地→播种 |
| `buildHouse`/`buildFromSchematic` | 纯编排 | 调 `placeBlockAt` |
| 查询类 | 只读 | 返回结构化数据，不用 ActionResult |

## 五、字段统一规范

### 5.1 原子返回

```js
{
  ok: boolean,
  code: 'OK'|'NO_TARGET'|'NO_PATH'|'OUT_OF_REACH'|'NO_TOOL'|'NO_ITEM'|
        'OCCUPIED'|'NO_SUPPORT'|'BLOCKED'|'TIMEOUT'|'INTERRUPTED'|'INTERNAL',
  message: string,          // 失败必填，人话
  data: {
    target:  {x,y,z} | null,   // 操作对象
    from:    {x,y,z} | null,   // 起点（移动类）
    dist:    number  | null,   // 方块中心→眼睛（统一口径）
    count:   number  | null,   // 数量变化
    costMs:  number,           // 必有
    extra:   {},               // 原子特有（block 名、tier、attempt…）
  }
}
```

### 5.2 事件

```js
{ phase: 'start'|'item'|'retry'|'skip'|'done', step: 'move'|'dig'|'place'|'pickup', ... }
```

### 5.3 复合返回

```js
{
  ok, code, message,
  data: {
    done: number, want: number, failed: [{target, code, message}], costMs
  }
}
```
