# 复合技能步骤清单（供审阅）

> 目的：把每个复合技能**实际执行的步骤**列出来，标出每步用的是哪个原子、返回字段是什么。
> 你审完之后，我们按"原子统一 + 字段统一"来改。
>
> 数据来源：直接读代码（行号可核对），不凭记忆。

## 零、当前原子清单（6 个）

| 原子 | 文件 | 职责 | 返回 data 字段 |
|---|---|---|---|
| `blockAt` / `findBlocks` / `countItem` / `reachDistanceTo` | `atom_perceive.js` | 查方块、查背包、算距离 | 裸值（不是 ActionResult） |
| `moveTo` / `moveToXZ` / `moveToXZEx` | `atom_move.js` | 走 | `{dist, costMs, partial?, advanced?, tier?}` |
| `digBlock` | `atom_dig.js` | 挖一格 | `{block, pos, costMs}` |
| `placeBlockAt` | `atom_place.js` | 放一格 | `{block, pos}` |
| `equipItem` / `countItem` | `atom_items.js` | 装备/计数 | 裸值 |
| `stopMove` / `lookAt` | `atom_move.js` | 停/看 | `{pos}` |

**已发现的字段不统一问题**：
- `dist` 有的地方是「到目标的水平距离」，有的地方是「眼到方块的 3D 距离」
- `costMs` 有的有、有的没有
- `pos` 有时是 `{x,y,z}` 裸对象，有时是 `Vec3`
- 失败时 `data` 经常是空对象 `{}`，调用方无法区分"哪一步失败的"

## 六、字段不统一清单（这是你说的"字段统一"要解决的）

### 6.1 返回结构

| 现状 | 出现在 |
|---|---|
| `ActionResult` = `{ok, code, message, data}` | 我们的原子 + task_* |
| 裸布尔 `true/false` | skills.js 的 65 个函数 |
| 裸对象 `{x,y,z}` | `atom_perceive.*` |
| `null` / `undefined` | `findBlocks` 无结果 |

### 6.2 `data` 字段命名不一致

| 语义 | 存在的各种叫法 |
|---|---|
| 走的距离 | `dist`（moveTo）、`dist`（hopTo 是水平距离）、`advanced` |
| 耗时 | `costMs`（多数）、无（`digBlock` 部分路径） |
| 位置 | `pos`（裸对象）、`pos`（Vec3）、`at`、`cell`、`position` |
| 数量 | `collected`、`got`、`placed`、`want`、`num` |
| 失败明细 | `failed[]`（platform 有 `{pos,code,message}`）、collect 完全没有 |

### 6.3 `onEvent` 事件类型不统一

| 复合 | 事件类型 |
|---|---|
| `collect` | `progress` / `skip` / `search` / `survey` / `plan-tree` / `plan-skip` / `tool` / `vine-cleared` / `scaffold-cleanup` / `approach-anchor` / `anchor-reached` / `anchor-failed` |
| `hopTo` | `scan` / `plan` / `plan-fallback` / `segment` / `split` / `reroute` |
| `placePlatform` | `placed` / `failed` |
| `follow` | `hop_start` / `hop_done` / `hop_error` / `offline` / `lost` / `found_nothing` |

**12 + 6 + 2 + 6 = 26 种事件类型，没有统一前缀，模型/日志无法通用解析。**

## 七、我建议的统一方案（待你确认）

### 7.1 原子统一到 ActionResult

```js
// 所有原子统一返回
{ ok, code, message, data }

// data 统一字段（只保留这 5 个，其余放 extra）
{
  target:   {x,y,z} | null,     // 操作的对象
  from:     {x,y,z} | null,     // 起点
  dist:     number | null,      // 到目标的 3D 距离（眼到方块/脚到点，文档写明）
  count:    number | null,      // 数量（挖了几个/放了几个/拿到几个）
  costMs:   number,             // 本次耗时（必有）
  extra:    {}                  // 各原子特有字段
}
```

### 7.2 复合统一到「步骤数组」

```js
// 每个复合提供 steps()，返回它要执行的步骤（纯数据，不执行）
export function steps_placePlatform(center) {
  return [
    { atom: 'checkCell',    target: c1, item },
    { atom: 'placeBlockAt', target: c1, item },
    ...
  ];
}
// 执行器统一跑：for (const s of steps) await runStep(bot, s)
```

### 7.3 事件统一

```
{ phase: 'start'|'step'|'retry'|'skip'|'done', step: 'place'|'walk'|'dig', ...}
```
