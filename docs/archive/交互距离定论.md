# 交互距离：三层真相（实测定论）

> 今天我把这个值从 4.3 改到 4.5，两次都基于错误理解。
> 现在用实测 + 源码把三层分清楚，此后不再猜。

---

## 三层各有各的阈值，互相独立

| 层 | 阈值 | 谁在用 | 能不能调 | 实测 |
|---|---|---|---|---|
| **① 服务端** | **基本不校验** | Paper 服务端 | 否（配置） | **6.11 格也能挖成功** |
| **② mineflayer `canDigBlock`** | 5.1 | 辅助函数，`dig` 不调用它 | 是（自己传） | — |
| **③ pathfinder `GoalLookAtBlock`** | **4.5 + 射线必须命中** | 走到能挖的位置时 | **距离可调**，射线不可调 | 今天所有"够不着"都在这层 |

---

## ① 服务端不严 —— 实测 6.11 格成功

测试方法：在精确距离上放原木，直接 `bot.dig`。

```
dx  dy | 实际距离 | 结果
  3  0  |  3.21 格 | ✅
  4  0  |  4.16 格 | ✅
  5  0  |  5.13 格 | ✅   ← 超过 mineflayer 的 5.1
  6  0  |  6.11 格 | ✅   ← 超过更多
  6  2  |  6.06 格 | ✅
```

**结论**：服务端没做严格的距离拒绝。所以「挖不到」**从来不是服务端拒绝**。

## ② mineflayer 的 5.1 是个摆设

`digging.js:218` 的 `canDigBlock()` 用 5.1，但 `bot.dig()`（第 24 行起）**完全不调用它**——直接算 `digTime` 然后发包。

**结论**：5.1 只是个可选辅助函数，不影响实际挖掘。

## ③ pathfinder 的 4.5 + 射线命中 —— 这才是真限制

`goals.js:158` `GoalLookAtBlock`：

```js
this.reach = options.reach || 4.5     // ← 距离阈值，可调
```

`isEnd(node)` 要求**两个条件同时成立**：

```js
// 条件1：距离
if (node.distanceTo(this.pos.offset(0, this.entityHeight, 0)) > this.reach) return false;

// 条件2：从该位置发射线，必须真的打中这个方块
const rayPos = this.world.raycast(startPos, dir, this.reach)?.position;
if (rayPos && rayPos.x === this.pos.x && ...) validFaces.push(...)
return validFaces.length !== 0;
```

### 条件 2 解释了两件今天没想通的事

| 现象 | 原因 |
|---|---|
| **树干被树叶包住就"够不着"** | 射线打到的是树叶，不是树干 → `validFaces` 为空 → 永远不满足 |
| **隔着藤蔓砍空气** | 同上，藤蔓挡了射线 |
| 清掉藤蔓后就能挖 | 射线能打到树干了 |

**所以 `vine_clear` 不是多余的补丁，是必要条件。**

### 条件 2 也解释了为什么 `atom_dig` 只判距离是错的

我今天把 `digBlock` 改成"只看距离"，理由是"MC 挖方块不需要看见"。
**这个结论对服务端成立（①②层），但对 pathfinder 不成立（③层）** ——
因为她要走**过去**，而走过去的目标函数要求射线命中。

---

## 定论：原子应该怎么用这三个数

```
digBlock(pos) 的前置断言：
  距离 ≤ 5.1        ← 用 mineflayer 的值（服务端更松，5.1 安全）
  且 射线能命中该方块（或已清掉遮挡）   ← 因为要配合 GoalLookAtBlock

moveToDigPosition(pos) 的目标：
  new GoalLookAtBlock(pos, world, { reach: 5.1 })   ← 把 4.5 调到 5.1
  ※ reach 调大后，"站在多远"更容易满足，减少来回找站位
```

**关键改动**：`GoalLookAtBlock` 的 `reach` 从默认 4.5 **调到 5.1**，和服务端允许的最大距离对齐。
这样她能站在更远的地方就开始挖，减少「找站位失败」的概率——今天 3 个站位 bug 的直接受益点。

## 附：对其他原子的推论

| 原子 | 距离约束 | 依据 |
|---|---|---|
| `digBlock` | ≤ 5.1 + 射线命中 | ①②宽松，③是实际限制 |
| `placeBlockAt` | 服务端校验（客户端不问） | `place_block.js` 无距离检查 |
| `openContainer` / `useBlock` | ≤ 5.1（服务端会校验右键距离） | 需实测确认 |
| `attackEntity` | 3.0（横扫 ~3.5） | 需实测确认 |

**待实测**：右键交互（开箱/工作台/门）的服务端距离边界，可能与挖掘不同。
