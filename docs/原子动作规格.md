### 0.1 契约

```js
// atom_contract.js
export const CODES = ['OK','NO_TARGET','NO_PATH','OUT_OF_REACH','NO_TOOL',
                      'NO_ITEM','OCCUPIED','NO_SUPPORT','BLOCKED','TIMEOUT',
                      'INTERRUPTED','INTERNAL'];

export function ok(data = {}) {
  return Object.freeze({ ok: true, code: 'OK', message: '', data });
}
export function fail(code, message, data = {}) {
  if (!CODES.includes(code) || code === 'OK') throw new Error('bad code: ' + code);
  if (!message) throw new Error('fail() 必须带 message');
  return Object.freeze({ ok: false, code, message, data });
}
```

只用 `ok()` / `fail()` 构造，原子文件里禁止手写 `{ ok: ... }` 字面量。

### 0.2 四条通用规则

1. 每 100ms 检查一次 `interrupt_code`，命中立刻 `fail('INTERRUPTED')`。
2. 每个原子自带超时，默认：移动 30s、挖掘 `max(2s, digTime*2)`、放置 5s、感知 1s。
3. **不 `console.log`**，只往 `data` 里塞数据；由任务层统一打一行。
4. 原子不重试、不调 LLM、不调别的业务原子（`canReach` 这类纯函数除外）。

### 0.3 边界案例（本项目判定）

| 现有函数 | 判定 | 理由 |
|---|---|---|
| `goToPosition` | 动作原子 | 单一结果（到了/没到），可重试 |
| `goToPositionPlanned` | 复合，冻结 | 同时做规划，与 pathfinder 双 owner |
| `goToPlayer` / `followPlayer` | 复合 | 目标在移动，需要追踪与防抖 |
| `collectBlock` | 复合，且过粗 | 找 + 走 + 挖 + 捡 + 数 |
| `digBlock` / `placeBlock` | 动作原子 | 一格，可复核 |
| `pickupNearbyItems` | 复合 | 多个掉落物 + 移动 |
| `equip` / `discard` | 动作原子 | 单槽位变化 |
| `craftRecipe` / `giveToPlayer` | 复合 | 多步、依赖背包状态 |
| `buildHouse` / `buildStorageWarehouse` | 复合，过粗 | 几十步，失败无法归因 |
| `blockAt` / `findBlocks` / `canReach` / `countItem` | 查询 | 无副作用、不失败 |

### 0.4 查询不返回 fail()

找不到就返回 `null` / `[]`，由调用方判断。「附近没有橡木」是正常情况，不是错误——否则日志和模型都会被带偏。

---

### 0.5 单位与命名（同一件事只能有一个名字）

| 概念 | 键名 | 类型 / 单位 | 反例（现在代码里） |
|---|---|---|---|
| 距离 | `dist` | number，格，1 位小数 | `reachDistanceTo` 是“眼到方块”，`goToPosition(min_distance)` 是“脚到目标”——两个距离含义不同，名字却都像距离 |
| 耗时 | `costMs` | 整数毫秒 | `time` / `duration` / `elapsed` 混用 |
| 方块坐标 | `pos` | `{x,y,z}` 整数 | 有的传 Vec3 有的传普通对象（今天就崩过一次） |
| 实体坐标 | `entityPos` | Vec3，含 `.5` | — |
| 方块名 | `block` | string，无 `minecraft:` 前缀 | 有的带前缀有的不带 |
| 数量 | `count` | 整数 | `num` / `n` / `amount` 混用 |

规则：新代码只用左列；旧函数在迁移时顺手改，不单独开重构。

### 0.6 怎么保证不漂（强制手段，不靠自觉）

1. **构造函数唯一**：`ok()` / `fail()`；原子文件里禁止 `return { ok: ... }` 字面量。
2. **构造即校验**：`code ∈ CODES`，失败时 `message` 非空（上面的实现里已经是运行时抛错）。
3. **执行器兜底**：`typeof r?.ok !== 'boolean'` → 直接抛 `INTERNAL`，抓适配层漏网。
4. **契约测试** `tools/contract_test.mjs`：键集合恰为 `['ok','code','message','data']`；`JSON.parse(JSON.stringify(r))` 深等于 `r`（抓 `undefined` / 函数）；每个 code 都能构造。
5. **静态检查**：`grep -n "return true\|return false" src/agent/library/atom_*.js` 必须为空。
6. **每个原子至少 1 条失败路径测试**（stub bot，不需要服务器）。

不引入 TypeScript 的理由：现在引 TS 会把 6000 行 JS 一次性变成编译错误；先用「运行时断言 + grep + 契约测试」拿到 80% 的效果。

### 0.7 迁移顺序（不原地改）

1. **先修传值**：`runAsAction` 里 `actionFnWithAgent` 现在**没有 return**，技能返回值在命令层就被丢掉了——不修这条，统一字段等于没做。
2. 新增 `atom_*.js`，返回 ActionResult；旧 `skills.js` 一行不动。
3. 执行器是唯一消费者；命令层只拿执行器给的一行报告。
4. 旧调用方走 `asBool(r)` 适配器（唯一转换点），不允许把原子直接塞进 `if (...)`。
5. 复合逐个迁到 atoms，迁一个删一个旧实现。
6. 最后删适配器和旧函数。

## 2. A2 移动

### 2.1 `moveTo(bot, x, y, z, opts)`

```js
const o = { tol: 1, timeout: 30000, canDig: false, maxDrop: 3 };
```

| Movements 选项 | 值 | 理由 |
|---|---|---|
| `canDig` | `false` | 不许她为了走路挖你的建筑 |
| `allow1by1towers` | `false` | 不许叠柱子 |
| `maxDropDown` | `3` | 超过 3 格就绕 |
| `canOpenDoors` | `true` | 开门 |
| `dontMineUnderFallingBlock` | `true` | 不挖沙砾上方 |
| `dontCreateFlow` | `true` | 不放水 |
| `digCost` / `placeCost` | `10` | 抬高代价，能不挖就不挖 |

伪代码：

```js
async function moveTo(bot, x, y, z, opts) {
  if (interrupted(bot)) return fail('INTERRUPTED');
  const t0 = Date.now();
  bot.pathfinder.setMovements(makeMovements(bot, opts));
  const goal = new pf.goals.GoalNear(x, y, z, opts.tol);
  try {
    await withTimeout(bot.pathfinder.goto(goal), opts.timeout);
  } catch (e) {
    bot.pathfinder.setGoal(null);
    if (e.name === 'Timeout') return fail('TIMEOUT', `走了 ${ms(t0)} 还没到`);
    if (/NoPath|No path/.test(e.message)) return fail('NO_PATH', '没有可走的路');
    return fail('INTERNAL', e.message);
  }
  const d = bot.entity.position.distanceTo(new Vec3(x, y, z));
  if (d > opts.tol + 0.5) return fail('NO_PATH', `停在 ${d.toFixed(1)} 格外`);
  return ok({ dist: d, costMs: Date.now() - t0 });
}
```

### 2.2 `stopMove(bot)`

`setGoal(null)` → `bot.clearControlStates()` → 等 300ms 确认。**判据：1 秒内水平位移 < 0.2 格。**

### 2.3 `lookAt(bot, pos)`

`bot.lookAt(pos.offset(0, 1.6, 0), true)`。判据：`yaw` 误差 < 5°（可读 `bot.entity.yaw`）。

### 验收

- 8 方向 ×（15 格、30 格）= 16 次，≥ 14 次 `ok`。
- 走一半发 `!stop`：1 秒内停下，且返回 `INTERRUPTED` 而不是 `TIMEOUT`。
- 目标在墙后 → `NO_PATH`，不抛异常、不刷屏。

## 3. A3 挖掘

### 3.1 前置检查（顺序固定，先便宜的）

1. `!blockAt` → `NO_TARGET`
2. 方块可破坏（非基岩/水/岩浆） → `NO_TARGET`
3. `canReach` → 不满足返回 `OUT_OF_REACH`，message 带实际距离
4. 工具：`bot.pathfinder.bestHarvestTool(block)`，没有合适工具 → `NO_TOOL`
5. 装备：`equipItem(tool)` → `NO_ITEM`

### 3.2 执行

```js
const t0 = Date.now();
await bot.dig(block, true);          // forceLook = true
const gone = await waitUntil(() => !isSameBlock(blockAt(bot, pos)), 1500);
if (!gone) return fail('TIMEOUT', `挖了 ${ms(t0)} 方块还没消失`);
return ok({ pos, block: block.name, costMs: Date.now() - t0 });
```

**不做拾取**。掉落物由任务层处理（B1 负责走过去捡），这样 `digBlock` 保持单一副作用。

### 3.3 失败分支

| 情况 | code | 播报 |
|---|---|---|
| 方块已不存在 | `NO_TARGET` | 「那儿已经没东西了」 |
| 眼睛够不到 | `OUT_OF_REACH` | 「够不着，还差 1.2 格，我得再靠近点」 |
| 没带对工具 | `NO_TOOL` | 「这个要镐子，我没拿」 |
| 挖了没消失（幽灵方块） | `TIMEOUT` | 「挖了但方块还在，像是卡住了」 |

### 验收

- `flat`：20 次 ≥ 18。
- `tree`（原木 + 树叶 + 藤蔓）：10 次 ≥ 7。
- 隔墙挖：`OUT_OF_REACH`，不误报成功。

## 4. A4 放置

### 4.1 前置

1. 目标位置可替换（空气/水/草）→ 否则 `OCCUPIED`
2. 背包有该方块 → 否则 `NO_ITEM`
3. 六个邻居里找支撑面，顺序：下、北、南、西、东、上 → 都没有 `NO_SUPPORT`
4. 支撑方块必须是「能贴的」（排除箱子、门、床、告示牌等可交互方块）
5. `canReach(目标)` → `OUT_OF_REACH`
6. 实体占位检查：目标格与玩家/她自己的碰撞箱重叠 → `OCCUPIED`

### 4.2 执行

```js
await bot.placeBlock(refBlock, faceVec);
const placed = await waitUntil(() => blockAt(bot, pos)?.name === item, 800);
if (!placed) return fail('TIMEOUT', '放了但没变成目标方块');
```

`blockAt` 用非缓存模式，避免幽灵方块误判。

### 验收

- `flat` 放石头：20 次 ≥ 18。
- `ledge`（悬空边缘）：5 次全对。
- 贴墙放：5 次全对。
- 目标格被占：`OCCUPIED`。
- 支撑面是箱子：`NO_SUPPORT`。

## 7. B1 采集（第一个复合，验证整套设计）

```js
async function collect(bot, name, want, { deadlineMs = 8 * 60000 } = {}) {
  const start = Date.now();
  const startCount = countItem(bot, name);
  const blacklist = new Set();           // "x,y,z" 失败过的坐标
  let collected = 0;

  while (countItem(bot, name) - startCount < want) {
    if (Date.now() - start > deadlineMs)
      return fail('TIMEOUT', `时间到了，只拿到 ${collected}/${want}`);

    const cands = findBlocks(bot, name, 64)
      .filter(b => !blacklist.has(key(b.position)));

    if (!cands.length)
      return fail('NO_TARGET', collected ? `附近没更多${name}了` : `附近找不到${name}`);

    const target = pickBest(cands);      // 距离 + 可达性打分
    const near = await moveTo(bot, ...target.position, { tol: 2, timeout: 15000 });
    if (!near.ok) { blacklist.add(key(target.position)); continue; }

    const dug = await digBlock(bot, target.position);
    if (!dug.ok) { blacklist.add(key(target.position)); continue; }

    await waitForPickup(bot, 2000);      // 等掉落物飞过来，或走过去捡
    collected = countItem(bot, name) - startCount;
    report(`[collect] ${collected}/${want}`);
  }
  return ok({ collected });
}
```

关键点：

1. **失败换目标，不结束任务**——这是今天最缺的行为。
2. **blacklist 按任务生命周期**，不写进记忆（避免记忆被坐标污染）。
3. 每块最多 1 次移动重试 + 1 次挖掘重试；两次都失败就换下一棵。
4. 结束只报一行：成功报数量，失败报「差几个 + 为什么」。

## 8. B2 跟随

500ms 一个 tick，按距离分档：

| 距离 | 行为 |
|---|---|
| > 30 格 | `moveTo(player, tol=2, timeout=10s)`，并暂停 `item_collecting` 等抢 goal 的 mode |
| 8–30 格 | `moveTo(player, tol=3, timeout=3s)` |
| < 4 格 | 不动，`lookAtPlayer` |
| 玩家 5 秒不在线 | 上报一次「我先在这等你」，停止跟随 |

**防抖**：只有「目标移动超过 3 格」或「上一条路径走完」才重设 goal。今天 `GoalChanged` 十次，大概率就是每个 tick 都重设 goal。

## 10. 日志格式

一行一件事，任务结束再汇总：

```
[task collect#7] 3/8 oak_log@(-111,75,-223) ok d=1.9 1.1s
[task collect#7] 4/8 skipped@(-113,78,-233) code=NO_PATH
[task collect#7] done 6/8 TIMEOUT 8.0m
```

禁止把 `findBlocks` 的逐块判断、pathfinder 的重规划过程写进给模型的输出。模型只拿到最后一行 + 失败原因。

| `!place(item, x, y, z)` | B3 |
| `!stop()` | 取消所有任务 |

提示词只改三处：

1. `$COMMAND_DOCS` 换成 6 条任务说明（token 大幅下降）。
2. 加一句结果格式：「做完只说一句：几个、在哪、成没成；没成说差什么。」
3. 加一句歧义处理：「不确定要几个/在哪，先问一句，别猜。」

## 13. 迁移与回滚

1. 开工前：`git checkout -b companion-v2`，打 tag `before-companion-v2`。
2. `settings.js` 加 `companion_mode: true`，新路径全部走 `atoms/` + `tasks/`；旧命令保留，作为过渡期的薄壳。
3. 每阶段结束打 tag：`b0-contract`、`b1-perceive`……任一阶段出问题，`git checkout <tag>` 回退。
4. `companion_mode: false` 时行为与今天完全一致——这是回滚开关，不是长期双轨。
5. S1–S3 全过之后，再删旧代码（`collectBlock` 的重试补偿、`heatmap` 在路径里的调用、不用的 54 条命令）。删除清单单独列，不提前动。

## 14. 复用

### 14.1 复用矩阵

| 原子 | 被谁用 |
|---|---|
| `moveTo` | follow / comeTo / collect / placePlatform / 送东西 / 逃跑 / 回床 |
| `digBlock` | collect / 挖隧道 / 清地 / 收菜 |
| `placeBlockAt` | platform / 墙 / 放箱子 / 搭桥 |
| `equipItem` | dig（换工具）/ place（换方块）/ 战斗 |
| `say` | 所有任务的收尾播报 |
| 查询族 | 所有复合的判定 + 测试断言 |

### 14.2 加新功能的三种情况

| 情况 | 例 | 新增原子 |
|---|---|---|
| 组合已有 | “跟我去矿洞挖铁” = follow + collect | 0 |
| 缺一个能力 | “把东西放进箱子” = moveTo + useBlock + 转移 | 1 |
| 缺一类能力 | 战斗 / 种植 | 1–2 |

规则：新功能超过 2 个新原子就先停——说明缺的是一类基础能力，补那一类，不要给每个功能各加一个专用原子。

### 14.3 复用退化的三种病

| 病 | 症状 | 处方 |
|---|---|---|
| 参数不够 → fork | `moveToFast` / `moveToSafe` | 参数对象 + 默认值，不新增函数 |
| 返回不够 → 绕过 | 复合里直接 `bot.dig(...)` | 补 `data` 字段；改契约要全层同步 |
| 调用太麻烦 → 不用 | 复合里自己写 5 行 setup | Movements / Goal / 超时 / 中断内置在原子内部 |

### 14.4 参数上限

原子参数 ≤ 5 个（含 options）。超过说明它其实是两个原子。

### 14.5 测试也复用

同一套场景库（flat / wall / tree / pit / ledge / water）能测所有原子和复合；新增原子不需要新场景，除非它引入了新的世界交互。
