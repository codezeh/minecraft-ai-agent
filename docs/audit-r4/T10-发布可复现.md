## 3. 产物指纹（`MANIFEST.json`）

### 3.1 字段

```jsonc
{
  "schemaVersion": 2,
  "generatedAt": "2026-11-07T18:44:31Z",
  "source":   { "root": "web/", "files": 24,
                "hash": "sha256:9cc25c06…f7d24",
                "inputs": ["src","index.html","vite.config.ts","tsconfig.json","package.json","package-lock.json"] },
  "artifact": { "files": 9, "hash": "sha256:9f3fb849…ceb" },
  "entryAssets": ["assets/index-DM8l7HNO.js","assets/index-Wa3kEFxm.css"],
  "files": { "…": "…sha256…" }
}
```

- `source.hash` = 24 个源码输入按 `相对路径\0文件sha256` 排序后的整体 sha256 ⇒ **产物绑定到"哪一版 web/ 源码"**；
- `artifact.hash` = 9 个产物同法 ⇒ 产物内容指纹；
- 交叉校验：`index.html` 实际引用的 `/console/...` 必须与 `entryAssets` 一致，且都在 `files` 里。

### 3.2 干净克隆里的三方一致性（实跑）

```
pwsh scripts/release.ps1 -VerifyOnly          （在干净克隆里跑）
PASS  9 个产物文件与清单逐条一致
PASS  产物目录没有清单未记录的野文件
PASS  index.html 的 2 个入口引用都能在产物里找到
PASS  源码指纹 sha256:9cc25c06…（24 个输入文件）
PASS  产物指纹 sha256:9f3fb849…（9 个产物文件）
PASS  产物与 web/ 源码指纹一致（产物确实是这份源码构建出来的）
PASS  产物指纹与清单一致
PASS  入口引用与清单一致
ALL PASS: 8 passed, 0 failed
```

⇒ 干净克隆里"产物 ↔ 清单 ↔ 源码"三方一致；**改了 `web/` 却不重新生成产物 = 这条直接红**（审计说"属侥幸"的那个缺口被堵上）。

### 3.3 一个必须交代的发现：旧产物不可复现

原入库产物是 `assets/index-Bh1enPsf.js`；用 **HEAD 的 `web/` 源码**（工作树当时另有一条线在改 `web/src/stores/agents.ts`，所以用 `git worktree add` 开干净树 + `npm ci`）重新构建，得到的是 `assets/index-DM8l7HNO.js`。
逐字节 diff 显示差异在 **压缩器的标识符重命名**（`ye`→`_e`、`ge`→`me`）与由此变化的 chunk 名 —— 即旧产物**不是**由当前 HEAD 源码构建出来的（构建本身在同一环境下是确定的：连续两次 `npm run build` 产物 md5 完全一致）。

处置：本次以 HEAD 源码树重建产物并入库，`source.hash` 记的就是这棵树。**副作用要说清**：`web/` 线若在 T10 之后合并新改动，必须重跑 `pwsh scripts/release.ps1 -SkipDocker` 并一起提交 `web-dist/`，否则 `-VerifyOnly` 会红（这正是设计意图，不是 bug）。

过程中修掉的三个**实测**缺陷（都会让"一键"在这台机器上根本跑不起来）：

1. Windows PowerShell 5.1 把原生命令写到 stderr 的内容变成 `NativeCommandError` **终止**执行（docker/npm 正常工作时也写 stderr）⇒ 调用处局部把 `ErrorActionPreference` 降为 `Continue`，成败只看退出码；
2. `-DockerExe 'wsl -e sudo docker'` 时，**显式给出**的 Windows 路径也要翻成 `/mnt/<drive>/…`（原来只在默认分支翻）；
3. `MANIFEST.json` 有中文 `note`，PS 5.1 默认按 ANSI 读 ⇒ `ConvertFrom-Json` 抛异常 ⇒ 改 `-Encoding UTF8`。

另：脚本文件必须是 **UTF-8 with BOM**，否则 PS 5.1 按 GBK 解析中文，直接语法报错（本仓 4 个老脚本都是 BOM）。

## 5. 缺产物时"必须显式失败"（验收第 2 条）

两种失败模式都实跑过，且报错文本能指向修复动作：

**(a) 整个 `web-dist/` 不存在** → docker 自己的语义（`BUILD_EXIT=1`）

```
Step 15/17 : COPY web-dist ./web-dist
COPY failed: file not found in build context or excluded by .dockerignore: stat web-dist: file does not exist
```

**(b) 目录在、但少一个产物（"镜像能构建成功、运行期才 404"的那种静默失败）** → 我们自己的报错（`BUILD_EXIT=1`）

```
ERROR[T10] 清单里有、镜像里没有的文件: assets/index-DM8l7HNO.js
The command '/bin/sh -c set -eu; cd /app/web-dist; node --input-type=commonjs -e '…'' returned a non-zero code: 1
```

构建期校验覆盖的 4 类错，逐条用篡改过的 `web-dist` 验过（都是 `EXIT=1` + 可读消息）：

| 篡改 | 报错 |
|---|---|
| 删一个 asset | `清单里有、镜像里没有的文件: …` |
| 往 asset 尾部追加 1 字节 | `产物内容与清单不一致（被手改或漏拷）: …` |
| 塞一个清单未记录的 chunk | `产物里有清单未记录的野文件（多半是上一版残留）: …` |
| 删 `MANIFEST.json` | `MANIFEST.json 缺失：产物没有清单…请在仓库根运行 scripts/release.ps1。` |
