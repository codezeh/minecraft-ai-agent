# T14 其余 S2/S3（杂项与前端）— 修复记录

对应任务：`t14 [t14-misc]`；来源：`00-结论与优先级.md` §7 的 S2/S3 剩余项。

## 1) `history.appendFullHistory`：O(n²) + 一次截断永久停写

- 原实现：每次（每 5 条）`readFileSync` 全量 → `JSON.parse` → `push` → `writeFileSync` 全量写回。
  写第 N 条成本 O(N)，整场 O(N²)；且 read/parse 异常被 `catch` 吞成一行日志 ⇒
  文件被截断/写坏后**每次都在同一个坏文件上失败**，全程记录永久停写且看不出来。
- 现实现：只在第一次建文件（`[\n]` 骨架），之后**只改尾部**：退掉结尾 `]` → 追 `,\n{...}` → 补回 `]`。
  文件**仍是合法 JSON 数组**，`histories/*.json` 的既有消费方/备份脚本不用改。
- 异常不吞：写失败时本批留在 `_fullHistoryPending`（下次一起重试）、`console.error`、记 `fullHistoryError`；
  只有 `FULL_HISTORY_CORRUPT`（结尾不是 `]`）才换新文件自愈，其它错误继续在同一文件重试。
  不向上抛的原因：`history.add()` 有 9 处 fire-and-forget，抛出即 unhandled rejection 会带走进程。
- 与 `model-layer` 的分界：只动 `appendFullHistory` 段（其 `summarizeMemories` 的 H4 改动未触碰）。

## 2) `memory_bank` 截断方向

`capSize()` 原来 `keys.slice(0, 120)` 保留**最旧**、丢**最新**（刚 `!rememberHere` 的坐标最先被淘汰）。
改为保留**最新** 120 条（`keys.slice(-MAX_BANK)`），并在真的丢弃时记一条 warn。

## 3) `self_prompter.startLoop` 无 try/finally

一次异常后 `loop_active` 永远停在 `true`（`update()` 的自动重启判据 `!loop_active` 恒假 ⇒ 目标循环永久不再启动），
而 `state` 仍 ACTIVE（界面/存档都说"在跑"）。现在：`catch` 记日志 + 计数，`finally` 无条件复位
`loop_active`/`interrupt`；连续 `MAX_LOOP_ERRORS=3` 次才置 STOPPED（不假装 ACTIVE），
成功跑完一轮清零计数。

## 4) `speak.js` 的 catch 不重置 `isSpeaking`

`continueQueue()` 的 catch 只打日志不复位 `isSpeaking` ⇒ 一次异常后闸门永久卡 true，
之后所有 TTS 只入队没人播（**永久静音**）。现在 catch 里复位 + `pumpNext()` 重新拉泵；
`processQueue` 入口把 `text` 统一收成字符串（`txt.trim()` 不再会 TypeError）。

## 5) `vision_interpreter`：`[LLM_ERROR]` 进上下文

`analyzeImage()` 原来把模型层失败标记当成"图像分析"拼进 `Image analysis: "..."`。
现在 `isFailedReply()` 命中即返回 `null`（错误文本同样不返回），由 `_withAnalysis()`
整段省略 —— 宁可不给视觉结论，也不给一句假的/失败的结论。

## 6) `act_fish` / `modes.unstuck` 的 `Promise.race`

计时器从不清（收竿/脱困成功后仍挂 15~30 秒）、超时后底层仍在后台跑、且 unstuck 超时还会
`say('我出来啦~')`（假好消息）。两处改为本地 `raceWithTimeout()`：`finally` 清定时器、
超时**以返回值告知**；`fishOnce` 超时后 `bot.deactivateItem()` 收底层，unstuck 超时后
`bot.pathfinder.stop()` 并如实播报（不再喊成功）。

## 7) `web/src/stores/agents.ts: refreshTerrain` 绕过离线闸

`say()`/`agentAction()` 走 `emitControl()`（断线拒发），但 `refreshTerrain()` 仍裸 `socket.emit`，
断线期间事件会进 `socket.sendBuffer`，重连时"迟到的地形请求"被真发出去（WEB-001 同类）。
现在入口先判 `isOnline()`，未连接就直接返回 `{ok:false, reason}` 并写 `lastError`。

## 8) t21 收口：视觉链路读 `status`（A5 报告"缺口 C"）

t14 只做到「`promptVision` 返回的字符串以 `[LLM_ERROR]` 开头 ⇒ 不用」。t2 落地 `ModelResult`
（`status` + `content`）后，`vision_interpreter.js` 仍把返回值当字符串用，于是
`truncated`（半截画面描述）、`cancelled`、`timeout` 与"正常内容"**同形**，仍可能进上下文。
现在 `_visionAnalysis()`：

- **优先调带类型的新出口** `promptVisionResult()`：只有 `status === STATUS.OK` 才用 `content`；
  `truncated` / `error` / `cancelled` / `timeout` 一律返回 `null`（日志留 `status` + `errorCode`）。
- **兼容期**退回旧字符串出口 `promptVision()`，但必须过 `isFailedReply()` / `isTruncatedReply()` /
  `isNoCodeReply()` 判断；新出口存在但返回的不是带类型结果时同样落到这条路径。
- 两条路径都过 `_cleanAnalysis()`：`[LLM_ERROR]` / `[LLM_TRUNCATED]` / `[NO_CODE]` 任一出现即整段丢弃。
- `_withAnalysis()` 是最后一关：`null`/空/含内部标记的正文一律不拼，只留"看哪儿"的事实。

单测：`tools/r4_misc_web_unit.mjs` 第 ⑦ 节（12 条断言）覆盖 `status=error / truncated / ok`、
旧出口三种标记前缀、以及"带标记正文直接塞给拼句函数"的终检。
