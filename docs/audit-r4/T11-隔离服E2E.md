## 1. 一条命令做了什么

```powershell
pwsh scripts/e2e.ps1 -Scenario all     # claims + restart
pwsh scripts/e2e.ps1 -Scenario claims  # 只跑抢单
pwsh scripts/e2e.ps1 -Scenario restart # 只跑重启恢复
# 排查用：-KeepRun（保留运行目录）、-SkipReset（不重置）、-BootTimeoutSec 300
```

每个场景的流程：

1. **建一次性运行目录** `tmp/e2e/<scenario>/`（先删再建，所以永远从零开始）
   - `server.properties` ← `test-template/server.properties`，其中 `__E2E_RCON_PASSWORD__` 换成**每次随机**的 24 位口令
   - `world/` ← `test-template/world`（干净超平坦，无玩家/建筑）
   - `libraries/ versions/ cache/` ← **junction** 到 `server-test/`（Paper 这三样 158MB，只读复用）
2. **起服**：`tools/e2e_server_ctl.mjs` spawn java，等日志出现 `Done (`，再 RCON `list` 确认真能下指令
3. **跑场景**（见 §3）
4. **停服**：RCON `stop` → 等 java 进程自己退（这样世界才会正常落盘）；超时才 kill **自己那个 pid**
5. **重置**：删掉运行目录里的世界 → 从模板重拷 → 与模板逐文件 sha256 比对（重置生效的证据）
6. **汇总**：逐条 `[scenario] PASS/FAIL`，退出码 0/1

## 3. 两个场景的判据

### 3.1 `claims`（`tools/e2e_claims_live.mjs`）

判据与 `tools/t37_claims_contention_live.mjs` **逐条对齐**，对 container / station / entity 三类 key 各跑四步，再做实体 TTL 回收：

| # | 断言 | 实测 |
|---|---|---|
| ① | A 预约成功，且**直连 sqlite** 查库有 1 行（owner=A，until 在未来） | PASS（`{"ok":true,"rows":[{"owner":"claimA","until":…}]}`） |
| ② | B 抢同一 key → `ok:false` 且 `code=CLAIM_CONFLICT`，conflicts 点名该 key | PASS（`conflicts:["container:6200,-60,8800"]`） |
| ③ | 查库：该 key 仍只有 A 那 1 行（B 没偷偷落行） | PASS |
| ④ | **反向对照**：B 换**不同坐标**的同类 key → 必须成功（防"恒冲突"假通过） | PASS（`container:6205,-60,8800`） |
| ⑤ | entity 泄漏：kill 怪 → 等 TTL → claims 行被清理 | PASS（`before:1 → after:0`） |

合计 **13/13**。

### 3.2 `restart`（`tools/e2e_restart_live.mjs`，两阶段）

`stage`（第一次起服后）：forceload → 铺平台 → 放箱子（钻石×7 / 原木×33 / 铁锭×4）+ 熔炉（铁矿×1 + 煤×8）→
用**真实 `History.save()`** 写 bot 记忆 → 用真 bot 复核箱子确实写进去了 → `save-all flush` → 落盘期望值 JSON。

然后外层**真停服 → 真起服**，`verify` 阶段断言：

| 断言 | 实测 |
|---|---|
| 箱子内容跨重启完好（真 bot 开箱，逐项比对 id+数量） | PASS `3 种物品逐项一致` |
| 熔炉产物跨重启保留（真 bot 读产物槽） | PASS `output=iron_ingot|1` |
| 熔炉确实工作过且状态保留（煤 8→7 + 产物在 + 进度区间自洽） | PASS `煤 8→7（燃烧过）、产物=iron_ingot|1、progress=null` |
| bot 记忆可读回（真实 `History.load()`，含 codeVersion 版本闸） | PASS 命中标记 `E2E-MEMORY-KEEP-…` |
| 记忆里的地点库 `memory_bank` 还在 | PASS |

合计 **13/13**（含 8 条流程类断言）。

## 4. "重置生效"是怎么证明的

不是"看起来干净了"，而是**逐文件 sha256 比对**：`Get-WorldFingerprint` 对世界目录做 `相对路径 → sha256`
的指纹（跳过 `session.lock`），断言两次：

- `起服前世界 = 模板世界`（保证起点干净）
- `重置后世界 = 模板世界`（保证跑完复位）

两条在每次运行里都 PASS，见 §5 的日志。

## 6. 过程中修掉的四个**实测**坑（都会让"一条命令"跑不通）

1. **Paper 读到 stdin EOF 会自己停服**：`Start-Process java -RedirectStandardOutput …` 时 stdin 立即 EOF，
   短场景（几十秒）侥幸能过，claims 跑几分钟就"跑到一半服务端没了"（现象：RCON 突然 `ECONNREFUSED`，
   日志停在启动段）。→ 由 `e2e_server_ctl.mjs` spawn java，stdin 用**永不写入也不关闭**的管道。
2. **守护器被外层控制台带走**：`Start-Process node …` 起的守护器会随 `powershell -File` 收尾消失 →
   改用 `cmd /c start /b` 让它脱离控制台，并用 `server.pid` 文件精确追踪 java pid。
3. **PowerShell 5.1 把原生 stderr 当终止错误**：node/docker 正常写 stderr 就抛 `NativeCommandError` →
   调用处局部降 `ErrorActionPreference`，成败只看退出码。
4. **PS 5.1 传内联 JS 给 node 会拆参数**（`node -e "…"` 里的双引号）→ 落成 `tools/e2e_rcon.mjs` 文件调用；
   另外 `tools/e2e_rcon.mjs` 的注释里曾出现 `server*/server.properties`，`*/` 提前结束块注释导致
   **语法错误**（表现也是"RCON 一直连不上"）。
