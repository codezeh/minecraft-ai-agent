# T02 · 模型返回值类型化（ModelResult）

> 对应 A5 §3「方案 A：`ModelResult` 迁移」（架构收敛项 1）。执行：model-layer（t2）。
> 口径：**已实测** = 本次真跑命令并贴出输出；**静态确证** = 逐行读过代码。

## 0. 交付了什么（一句话）

模型调用的返回值从"一根三义同形的字符串"变成 `ModelResult{content,status,finishReason,usage,errorCode,errorMessage,elapsedMs,attempts}`；
prompter 内部统一走该类型，**字符串派调用点在迁移期行为逐字不变**（`toString()` 兼容 + 旧方法名保留）；
6 个此前没有截断检测的适配器改为由 `finishReason` 产出 `status=truncated`；`last_convo_truncated` 不再只写不读；`usageTotals()` 有了真实生产消费者。

## 1. 契约（新文件 `src/models/result.js`）

```js
new ModelResult({ content, status, finishReason, usage, errorCode, errorMessage, elapsedMs, attempts })
```
- `status ∈ {ok, truncated, error, cancelled, timeout}`；非法值回落 `ok`（不让脏数据带偏状态机）
- 派生判据：`ok` / `truncated` / `failed`(error|cancelled|timeout) / `hasContent`(ok|truncated) / `isNoCode`
- **`content` 的不变量：只放能给人看、能进 history 的正文，永不携带 `[LLM_ERROR]` / `[LLM_TRUNCATED]`**
- 过渡兼容：`toString()` 刻意重现旧标记语义（error→`[LLM_ERROR] …`；truncated→`正文[LLM_TRUNCATED]`），`toJSON()` 只吐业务字段

配套函数：
| 函数 | 作用 |
|---|---|
| `toModelResult(raw, meta)` | **桥**：老字符串 → 结构化（A5 §3.3 步 0） |
| `isOutputLimit(finishReason)` | `length` / `max_tokens` / `model_length` / `MAX_TOKENS` 四家取值的唯一收敛点 |
| `inferErrorCode(text, err)` | RATE_LIMIT / TIMEOUT / AUTH / CONTEXT_LENGTH / NETWORK / CANCELLED / BAD_RESPONSE（**同时认中文中止文案**，否则自家 `模型请求超过总期限` 会被归成 BAD_RESPONSE） |
| `assertModelResult(r, where)` | 不变量断言：结构合法 + content 无标记 + error 必有 errorCode |
| `coerceModelResult(r, where)` | 断言 + 兜底：非法结果降级成 error，**不让断言把 bot 打挂** |
| `noteModelResult` / `modelResultTotals` / `formatModelTotals` | 分布计数与一行可写日志的对账行 |

## 3. A 项：6 个适配器的截断检测（此前**完全没有**）

| 适配器 | 截断字段 | 实测 |
|---|---|---|
| groq | `choices[0].finish_reason` | 结构化提级 → `status=truncated` |
| cerebras | `choices[0].finish_reason` | 同上 |
| mistral | `choices[0].finishReason`（`length`/`model_length`） | 同上 |
| ollama | `done_reason`（`length`） | 同上 |
| huggingface | SSE 最后一个 chunk 的 `finish_reason` | 同上（流式也能拿到） |
| replicate | **无此字段** | `finishReason:null`，**如实标注"检测不到"**，不另编字符串标记 |

判据只在 `result.js:isOutputLimit()` 一处，适配器只负责把原值填进 `finishReason` ⇒ 不再"各自编标记"。
usage 也在同一批里结构化（`normalizeUsage()`，`_shared.js` 新增，`recordUsage` 同步复用）。

## 4. B 项：`last_convo_truncated` 死标志 —— 选「接消费者」

- **做法**：标志保留但其值改由 `ModelResult.status` 派生，并由 `prompter.logTotals()` **真正读出来**打进日志；
  `promptConvoResult()` 每次调用都会 `noteModelResult()` 计数，`logTotals()` 在**记忆落盘**（低频、天然对账点）时输出一行：
  `[llm] totals calls=… ok=… truncated=… error=… cancelled=… timeout=… avgMs=… | usage calls=… prompt=… completion=… missing=… lastConvoStatus=… lastConvoTruncated=…`
- **为什么不删**：`review2_regression_unit` 把"剥离标记后仍保留结构化诊断"钉成了硬断言；删标志等于把那条可观测性约定一起删掉。
- **同时收益**：`usageTotals()` 从"0 个生产调用点"变成"有真实消费者"（A5 §6.2 的成本可算问题）。

4. `noCodeReply()` 的 `[NO_CODE]` 信号在类型化后仍是"content 里的约定"（`ModelResult.isNoCode` 提供判据），没有升格成独立 status；升格会牵动 coder 的两道判据，留待步 3 一并处理。
