# T5 任务板止血（A5-8 / S2）：心跳不看停止标志 → paused 单仍续租

> 修复范围：`mindcraft/src/agent/library/board_scheduler.js`、`board_client.js`
> 验收用例：`mindcraft/tools/board_scheduler_unit.mjs`（⑩-①…⑤b）、`board_lease_expire_unit.mjs`（⑨-a…c）

## 病根（审计 §6.5）

`_runJob` 的 `setInterval` 心跳只看"finally 有没有到"，不看停止/paused 状态；
`BoardClient.heartbeat()` 同样无条件发 `board:heartbeat`。而 `_runJob` 卡住的最长来源
正是 30 分钟模型调用 / 10 分钟动作超时 ⇒ 面板上单子已 `paused`，租约仍在续 ⇒ 别人拿不到。

补充的机制事实（本次实测确认，决定了修法）：

- `board_store.heartbeat()` 只校验 `lease.owner === bot`，**不看 state** ⇒ paused 单照样能续租；
- `board_store.expireLeases()` 的扫描条件是 `state IN ('claimed','running')` ⇒
  **paused 的单等多久都不会被回收** ⇒ 光"停掉心跳、等它过期"在 paused 上并不成立；
- `control.applyStop(PLAYER)` 走的是 `board.update(patch{state:'paused', lease:null})`，
  而 store 的 `PATCHABLE` 白名单里**没有 `lease` 这个字段**（只有 `lease_owner/lease_until`）
  ⇒ 暂停并没有真的清租约 —— 这正是"paused 但租约还归自己"的成因之一。

结论：修复必须是 **①停止续租 + ②停手时主动摘租约/放预约**，二者缺一不可。

## 修法

### board_scheduler.js

- 新增显式停止状态与方法：`stop(reason)` / `resume()` / `stopRequested` / `stopped`。
  与 `setAutoClaim(false)` 明确区分：后者是"不领新单、手上这张照跑"（06 §14），
  前者是"手上有单也停"。
- 新增判据 `LEASE_RENEWABLE_STOP_REASONS`（**只有 `brief` 允许续租**，按 07 §4 的 STOP_REASONS 逐档）
  与 `LEASE_RENEWABLE_JOB_STATES`（只有 `claimed/running`，白名单写法）。
- 心跳三拍：`_shouldRenewLease()`（本地：显式停止 / 停止原因变化 / 本地镜像状态）
  → `_authoritativeStopKind()`（向服务端复核；镜像看不到"别人停的"）
  → 正常续租。任一判定不该续 ⇒ 关定时器 + `_releaseOnStop()`。
- `_stopKindFromState()` 返回 `paused` / `cancelled` / `lost`，并区分语义：
  `paused` 只摘租约（单留在 paused，可恢复）；`cancelled` 摘租约 + 放预约（终态）；
  `lost` 只放预约、不再写库（不洗别人的单）。
  ★ 这里必须用字面量 `'paused'/'cancelled'`：本文件 import 的 `JOB_STATE` 来自 `control.js`，
  那张表**没有** `cancelled`（全表在 `board_store.JOB_STATE`，而 agent 侧不能 import 它，会拖进 node:sqlite）。
- `tick()` 在 `_stopRequested` 时返回 `reason:'stopped'`（不领单、不 resume）；
  残局回收（requeueStaleBrief）仍照做。
- `_runJob` 收尾：`_leaseDropped` 命中时**不许 finish**；另外权威状态为 paused/cancelled/lost
  时也跳过 finish（与 T31 第6条①的 paused 守卫同族）。

### board_client.js

- 新增 `stop(reason)` / `resume()` / `markJobStopped(id, kind)` / `markJobResumed(id)` /
  `stoppedJob(id)` / `heartbeatBlockedBy(id)`，以及 `_stoppedJobs` 逐单簿记。
- `heartbeat()` 前置判据：整端停止 或 逐单簿记 ⇒ 直接返回 `HEARTBEAT_SKIPPED`，**零网络**；
  服务端回传状态非 claimed/running 时 `_noteJobState()` 记一笔，下一拍起停租。
- 簿记写入点覆盖三条真实链路：`setState(paused|cancelled)`、`update({state:paused|cancelled})`
  （= `control.applyStop` 走的那条）、`heartbeat` 的响应；`claim()` 成功与 `setState(ready)` 撤销簿记。
- 新增 `releaseLease(id)`：用 `update({lease_owner:null, lease_until:null})` 只摘租约不动状态
  （不能用 `setState(paused)`：`paused → paused` 是非法转移）。
- `HEARTBEAT_SKIPPED` 不走 `contract.fail()`：`CODES` 是封闭词汇表（要动 contract.js，不属本条范围），
  改用一个形状一致的自洽返回值，同时导出常量便于外部判据。

新增用例覆盖（全部数调用次数/看库字段，不靠"看起来对"）：

| 用例 | 断言 |
|---|---|
| ⑩-① | paused 后心跳次数**停住**、`update` 带 `lease_owner=null`、单仍 paused、无 finish |
| ⑩-② | 停租后租约到期回收：ready + assignee 清空 + attempts+1 → 别的 bot 能领到 |
| ⑩-③ | cancelled 同样停租+释放，状态保持 cancelled（不被 finish/resume 复活） |
| ⑩-④ | `sched.stop(shutdown)` 后 tick 返回 `stopped`，不领新单 |
| ⑩-⑤ | 客户端 `heartbeat()` 在暂停/取消/整端停止后返回 `HEARTBEAT_SKIPPED` 且**零网络** |
| ⑩-⑤b | 反证：resume 后心跳恢复（没有修成"永不续租"） |
| ⑨-a | 主动摘租约后单留在 paused（可恢复），paused 期间别人领不到，resume 后原持有者能接着做 |
| ⑨-b | 反证：不主动摘 → `expireLeases` 不扫 paused ⇒ 僵尸租约 |
| ⑨-c | 反证：claimed/running 照旧续租 ⇒ 租约永不过期 ⇒ 别人领不到 |

## 边界与遗留（不在本条文件范围）

- **接线**：生产上"玩家 !stop"已经能生效（`applyStop` → `board.update(paused)` → 客户端簿记 →
  心跳停），因为簿记覆盖了 `update` 这条路径；但 `scheduler.stop()` / `client.stop()`
  目前**没有生产调用方**（进程退出、死亡路径在 `mindserver`/`agent.js`/`control.js` 里，
  不属本条文件范围）。建议后续在退出/死亡路径显式调用（一条线，几行）。
- **`control.applyStop` 的 `patch.lease = null` 被 store 白名单丢弃**（`PATCHABLE` 只有
  `lease_owner/lease_until`）—— 属 `board_store.js`/`control.js` 的范围，本条的
  `releaseLease()` 是绕开它的修法，但根因仍在。
- 工具链 lint 棘轮当前 +71 `require-await` 来自其他实现线新增的 tools 文件
  （`agent_cancel_late_reply_unit` / `control_plane_guard_unit` / `r4_misc_web_unit` / `r4_model_hemo_unit`），
  本条两个测试文件新增 0 条（本段局部 `eslint-disable require-await`，与文件既有风格一致）。
