**第 16 条尤其讽刺**：`CODES` 里 38 个码，`NO_DATA` 明写"目标格未加载，读不到方块"，而 `act_place` 用了 `NO_TARGET`。
**「码不够用」和「码用错了」是两件事** —— 前半晚修的多是"码没说清是哪一种"，这条是"**对的码存在却没人用**"。
→ 说明 `CODES` 除了"注册够不够"，还要做**使用审计**：不是"有没有这个码"，而是"**该用它的地方有没有人在用别的码**"。

**共同点：查日志 / 做注入 / 看中位数 / 查库 / 回退实现，30 秒能定性的事，靠推测就会得出方向错误的修法。**

### 由此立下的五条方法纪律

1. **判定条件必须是可执行布尔**，不能是"看起来像证据的文本"（atoms 的冒烟曾 4 个命令全崩却显示 6/6）
2. **验"东西搬没搬动"要用与实现无关的地面真相**（RCON `data get block`），不能用同一个被污染的 mirror
3. **假件太松 = bug 藏得深**（假窗口藏了 3 个 deposit bug、假板不校验 skill 藏了 obtain 的 bug）
4. **bench 场景必须每轮重建**，否则 5 轮不是 5 个独立样本（`r1` 挂而 `r2..r5` 全过 = 警报）
5. **"不知道"绝不能写成"知道它没有"** —— `enemiesLeft` 返回 `null` 不返回 `0`；列无数据不当虚空；`unreadable` 不塌缩成 `no-tool`

**shelter 这一路逼出三个真问题**（每个都是"假绿"型）：
1. **1 层墙 = 把她压头上** —— 内空只有 1 格高、她身高 1.8，顶圈正好压在头顶。与 B1 活埋同类。→ **省块数只能从"不铺地板"和"3×3"省，不能从她身高里省**
2. **出格判定用 AND** —— `Math.abs(dx)>1 && Math.abs(dz)>1`，单方向跳时 `dz` 恒 0 → 谓词永远假 → 等满超时。改成 OR + 导出纯函数
3. **`NO_TARGET` 用错码** —— `blockAt` 返回 null 是"chunk 未加载"，该用 **`NO_DATA`**（`CODES` 第 22 条本来就有！）

### 性能大修（A 系列，2026-11-03 下午 —— **已全部完成**）

起因是 water-cross 从"稳定 27s"退化成 15~82s 波动。取证定性为**行为层**（`pillar-attempt` 27/18/13/11/0 对应 49/45/30/31/15.5s，`scan3d`/`plan3d` 恒 2~4）。
顺着查下去，发现是 **M6 漏了 3/4**：`swimStep` 动作本体建好了（32 条测试），但**没接进导航** —— `path_3d` 不产 `swim` 边、`executor` 没有 `swim` 分支。**游泳能力是死的。**

三项修复：

| 项 | 做了什么 | 效果（真机实测）|
|---|---|---|
| **A4 swim 接入** | `path_3d` 落点是水 → 产 `swim` 边；`executor` 加 `swim` 分支调 `swimStep`（**不交给 pathfinder**，因为 pathfinder 每 tick 自设控制键会把按住的跳改掉）；落点判据按 action 区分 | **water-cross 30415 → 9618ms（快 3.2 倍）**，`pillar-attempt` **54→0**、`clear-feet` **22→0**，从 16~82s 波动收敛到稳定 |
| **A5 stepInto 接入** | `executor` 一处 `walk` 分支：试 `stepInto`（传 `targetFeetY`）→ 成功走 / 失败回落 `moveToXZ`。**无闸、无状态、无新 helper** | **walk-flat ↓27%**、**digdown ↓23%**、**climb-ladder ↓37%**、gap-bridge ↓12% |
| **A2 ctx 全局预算** | 子单预算放 `ctx.jobBudget`，`strat_*` 拆单时从共享预算扣 | 解决"4 次 `obtain` 可到 120 张"的隐患；跨调用共享、**跨执行独立**（由 `makeCtx` 对象生命周期保证）|

**三处根因，都在"边界口径"上：**

1. **`y` 口径（A5 的真根因）** —— `act_step.js` 要**脚位**（它读 `cell.y - 1` 判脚下），而 `path_3d` 的 `step.y` 是**面位**。直接喂 `step.y` → 判据读错一格 → **每步都 `UNSAFE`、位移 0.00**。
   这就是 A5 三次尝试都失败的真正原因 —— **不是判据写错、也不是场景特殊，是传参从一开始就错了**。
   换算只有 `executor.js:115` 的 `targetFeetY = step.y + 1` 一处（决策 1B）。

2. **`stepInto` 的 timeout 是猜的（A5 第二层）** —— 撞墙时**撞满 1600ms 超时**（实测 1610/1614/1614ms），而走得通只要 **114~219ms**。实测后调成 500ms（2.3 倍余量）→ `dig-through` 从 20626 回到 19172ms。

3. **"先占后查"（A2）** —— 预算检查写在 `plan.push()` **之后** → `limit=12` 实测用掉 13 张。**先占后查 = 永远超一次，必须 pre-check。**

**两个"为旧根因加的保险反而成伤害"的实例：**

- **A5 的 STUCK 闸（没写）** —— `insideCell` 修掉"假成功"后，死循环已从结构上不可能发生。我加的"连续 3 次失败且位移<0.1 → STUCK"**防的是已经不存在的病因**，结果**误杀 `gap-bridge`（5/5→0/5，总数 45→40）**。
  → **教训：修掉根因之后，为旧根因加的"保险"必须重新评估 —— 否则它会变成新的伤害源。**
  → STUCK 闸不写，理由：要区分"被动等待（要搭桥/要挖）"和"真卡死"需要可靠判据，**现在没有；而没有它也不会死循环**。
- **`fallRisk` 会拦死游泳** —— 它按"落差 > 4 格 → UNSAFE"判，深水会中招。已用"**`swim` 步不做 `fallRisk`**"防住（**没有全局放宽**，否则"走到水边掉进深水"会变安全）。

**三条新纪律（都来自这一轮）**

## 六、要用户操作的三件事

### 1. 重启 bot（让权限生效）

`profiles/my-local.json` 已配 `"permissions": { "owner": "HEAVENZEH" }`（该文件在 `.gitignore`，只改本地）。

- **heavenzeh**（小写）→ 其他玩家（**规范说明：离线模式下大小写是两个人的名字**，不是 bug）

### 2. 网络开关（`config/network.json`）

```bash
node tools/server-net.mjs show            # 看配置 vs 实际
node tools/server-net.mjs apply --dry     # 预演
node tools/server-net.mjs apply           # 写入（先备份）
```

当前状态：**主服 `bind=all` + 白名单（只放 HEAVENZEH）、测试服 `localhost` + 无白名单**。

> ★ **关键认知：真正的安全边界是白名单，不是绑定地址。**
> 离线模式（`online-mode=false`）下客户端不做 Mojang 验证，任何人都能冒用 op 名字进服。
> 开了 `white-list` 之后只有名单里的人能进，冒用就没用了。
> 所以「绑所有网卡 + 白名单」既安全又不牺牲局域网/手机可用性。

**测试服必须不开白名单** —— `bench`/`atom_all` 每轮新建 `ma<时间戳>` bot，开了会被全挡住。

### 3. 决定两件规范层面的事

- **来源顺序对金属不理想**：04 §6.3 是 `箱子 > 合成 > 熔炼 > 采集`，所以 `iron_ingot` 走"铁粒合成"（craft）而不是"熔炼铁矿"（smelt）。按规范合法，但通常更难。**要改需你拍板改 04 §6.3**
- **`flow_shelter` 的 1×1 内空 vs 封顶**：现在的修法是"先出后封"。若你想要更大的内空（`params.size` 已暴露 3..7），块数会涨
