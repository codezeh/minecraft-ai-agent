evidence: |
  **token 的两处"残留"：文件退出后不删、URL 里的 `?token=` 设完 cookie 也不清。
  单独看都很轻，合起来是"凭据在磁盘和浏览器里各留一份"。**

  ## 一、token 文件从不清理
  ```
  $ grep -nE "unlink|rmSync|rm\(" mindcraft/src/mindcraft/mindserver.js
  （无输出）
  ```
  ⇒ mindserver 退出（正常 `shutdown` 或崩溃）后，`mindcraft/.mindserver-token` **留在原地**，
  内容仍是这一次的 token。影响分两种：
  - 一般情况下**无害**：token 每次启动重新 `makeToken()`（`mindserver.js:79`），旧值作废。
  - 但一旦有人为了让 `stop-all.mjs` 之类能用而**固定** `MINDSERVER_TOKEN`
    （F-WEB-205 的修法正会引导这么做），这个文件就变成**永久的、明文的凭据**，
    且带 F-RT-001 说的 ACL 问题。

  ## 二、`?token=` 设完 cookie 后不重定向，token 留在地址栏与浏览器历史
  `mindserver.js:99-105`：
  ```js
  app.use((req, res, next) => {
      const fromQuery = typeof req.query?.token === 'string' ? req.query.token : null;
      if (fromQuery && fromQuery === handshakeToken && !hasAuthCookie(req.headers.cookie, handshakeToken)) {
          res.setHeader('Set-Cookie', authCookieHeader(handshakeToken));   // 换成 HttpOnly cookie
      }
      next();                                                              // ← 但 URL 不变
  });
  $ grep -nE "redirect|location" mindcraft/src/mindcraft/mindserver.js
  （无输出 —— 没有 302 把 ?token= 从地址栏抹掉）
  ```
  设计本意是好的（"把 ?token= 换成 HttpOnly cookie"），但**只换了一半**：
  cookie 换好了，URL 里的明文 token 还挂在地址栏上。而 `start-panel.ps1:213`
  `Start-Process $panelUrl` 打开的正是这个带 token 的地址 ⇒ **浏览器历史里存一条完整 token**，
  且该书签/历史会随浏览器账号同步到其它设备（若用户开了同步）。

  ## 三、Referer 面：当前为 0，但缺策略时不能保证
  面板页面只加载同源资源（`/console/assets/*`），所以今天**没有**把 token 通过 Referer 带出去的路径。
  但 `Referrer-Policy` 响应头缺失（我在 D5 的 F-WEB-204 报过），将来任何人加一个 CDN 字体/图标，
  完整的 `?token=…` 就会进第三方日志。这条属"将来会踩"，一并记在这里。
exploitability: |
  攻击者：能读浏览器历史的人（共用电脑、浏览器配置同步、拿到设备的人）；
  或对"残留 token 文件"有读权限的本地账户（叠加 F-RT-001）。
  能达成什么：拿到一次启动周期的 token ⇒ 指挥 bot / 改设置 / 停服（若该实例还在跑）。
  拿不到什么：token 每次重启就换，历史里的旧 token 在重启后作废

  影响半径：单实例生命期内的完整控制。
suggested_fix: |
  1. **设完 cookie 就 302 到无 token 的同一路径**（3 行，最有效）：
     ```js
     app.use((req, res, next) => {
         const fromQuery = typeof req.query?.token === 'string' ? req.query.token : null;
         const authed = hasAuthCookie(req.headers.cookie, handshakeToken);
         if (fromQuery && fromQuery === handshakeToken && !authed) {
             res.setHeader('Set-Cookie', authCookieHeader(handshakeToken));
             // 把 token 从地址栏/浏览器历史里抹掉：换完 cookie 立刻跳回干净 URL
             const clean = req.originalUrl.replace(/([?&])token=[^&]*&?/, '$1').replace(/[?&]$/, '');
             return res.redirect(302, clean || '/');
         }
         if (!authed && /* 需要鉴权的路径 */) { /* 见 F-WEB-201 的 401 */ }
         next();
     });
     ```
     注意：`start-panel.ps1` 打开的 URL 会跳一次，**体验不变**（一次额外 302）。
  2. **退出时删 token 文件**：在 `shutdown` 处理器与 `process.on('exit')` 里
     `try { unlinkSync(TOKEN_FILE) } catch {}`（要放在 `createMindServer` 作用域内）。
     崩溃时删不掉是正常的，但正常关服能删掉就够 —— 这条价值在"减少残留"而非"保证无残留"。
  3. **补 `Referrer-Policy: no-referrer`**（与 F-WEB-201/204 的响应头一起加）。
  4. README 记一句：不要 bookmark/share 带 `?token=` 的面板地址。
