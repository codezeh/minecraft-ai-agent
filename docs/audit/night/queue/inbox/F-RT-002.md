evidence: |
  **我们自己把"重新打开 F-SEC-205 那个洞"的方法写进了 start.bat 的提示里，而且照做的
  用户不会看到任何异常 —— 因为那条通道只在"stdout 被重定向到文件"时才危险，而
  `启动面板.bat` 正是这么干的。**

  ## 一、指引原文（start.bat，工作区在途版本已含 F-REG-001 的修法）
  ```bat
  echo   Panel needs a token. Read it from: mindcraft\.mindserver-token
  echo   Then open: http://localhost:8080/?token=^<the value in that file^>
  echo   (Or set MINDSERVER_PRINT_TOKEN=1 before starting to print it once.)   ← 这一句
  ```

  ## 二、那个开关确实会把完整 token 重新打回 stdout（实测）
  ```
  $ MINDSERVER_PRINT_TOKEN=1 node -e '(await import("./src/mindcraft/mindserver.js")).createMindServer(false, 18093)'
  [mindserver] ★ 调试模式（MINDSERVER_PRINT_TOKEN=1）完整值: <UUID>
  [mindserver] ★ 可直接打开: http://localhost:18093/?token=<UUID>
  ```
  对照（不设开关）：
  ```
  [mindserver] 握手 token 已生成: <指纹>(len=36)
  [mindserver] 完整 token 位置: …\.mindserver-token（或环境变量 MINDSERVER_TOKEN）
  ```
  ⇒ 开关一开，F-SEC-205 **原样复活**。

  ## 三、危险组合：这个开关 + 面板的 stdout 重定向
  `scripts/start-panel.ps1`：
  ```powershell
  19:$mcOut  = Join-Path $logDir 'mindcraft-console.log'
  188:    Start-Process -FilePath $node -ArgumentList 'main.js' `
  189:        -RedirectStandardOutput $mcOut `            ← mindcraft 的 stdout 全进这个日志
  ```
  `Start-Process` 默认**继承父进程环境**。所以只要 `MINDSERVER_PRINT_TOKEN` 落在用户级环境里
  （`setx MINDSERVER_PRINT_TOKEN 1`，或者有人按 start.bat 那句提示设了"永久"），
  之后**每一次用面板启动**都会把完整 token 写进 `logs/mindcraft-console.log` ——
  正是 F-SEC-205 要修的那个落盘位置，一字不差地回到原点。
  而用户完全无感：面板照常打开（甚至更"方便"，因为不用找文件了）。

  ## 四、为什么这条不是"理论上的误设"
  - 这句提示是**我们主动写进 start.bat 的**（为了让 start.bat 用户能拿到 token，见 F-REG-001）；
    一个刚被告知"面板要 token、你又找不到"的用户，最顺手的动作就是照括号里那句设一个环境变量。
  - Windows 上"设一次就一直有"是默认语义（`setx` 写注册表），没有"只这一次"的暗示。
  - 判据链：`MINDSERVER_PRINT_TOKEN=1` + `Start-Process -RedirectStandardOutput` = 日志里有 token。
    两个条件都不需要有人做错事，只需要有人照提示做。

  ## 五、附带一条同类风险（同一开关、另一条通道）
  `MINDSERVER_TOKEN` 被 mindserver 写进 `process.env`（`mindserver.js:81`），而
  **agent 子进程继承该环境变量**（`auth_gate.js:23` 注释自己写着这条设计）。
  若某个子进程崩溃时 dump 环境（Node 默认不 dump，但任何第三方库 `console.error(process.env)` 都会），
  token 就跟着进日志。当前我 grep 过 `src/`，**没有**任何地方打印 `process.env` 全量
  （`grep -rn "process.env)" src/` 无命中），所以这条只是"别这么写"的前置提醒，不是现存漏洞。
