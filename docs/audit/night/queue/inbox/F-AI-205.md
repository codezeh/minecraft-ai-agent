# 说明：这是**两个"各自合理"的修复组合出来的新故障**，不是任何单个提交的错。
# 发现时点：复核 `6f46182`（F-AI-201 fail-closed）时，顺着"没配 owner 会怎样"往下推，撞到这条。

evidence: |
  **一个"有人设过、但当前 profile 不认主人"的 goal，会变成每 2 秒一次 LLM 调用、且玩家叫不停的循环。**

  五跳链条，每一跳都实读过代码：

  **第 1 跳：goal 跨重启存活，且连作者一起存**
  `src/agent/history.js:144-149`
  ```js
  self_prompting_state: this.agent.self_prompter.state,
  self_prompt: this.agent.self_prompter.isStopped() ? null : this.agent.self_prompter.prompt,
  self_prompt_author: … this.agent.self_prompter.author ?? null,
  ```

  **第 2 跳：恢复后，自提示回合按那个 author 定级**
  （`agent.js` 原注释：`自提示回合 → 设 !goal 的那个人（self_prompter.author），不是 'system'`）

  **第 3 跳：fail-closed 之后（`6f46182`），若 profile 现在没有 owner**
  `src/agent/permissions.js:148-154`
  ```js
  if (owner) { … }          // owner 为空 / 空串 / 打错名字 ⇒ 进不来
  // 5) 没配主人：默认拒绝
  return LEVEL.OTHER;       // ⇒ 所有命令（**含 !endGoal**）全部被拒
  ```

  **第 4 跳（决定性）：命令被拒，但 `used_command` 仍被置 true**
  `src/agent/agent.js:672-676`
  ```js
  let execute_res = await executeCommand(this, res, perm);   // 被拒时返回 '[权限] 拒绝 …'
  console.log('Agent executed:', command_name, 'and got:', execute_res);
  used_command = true;                                       // ← **无条件置 true，不看是否被拒**
  ```

  **第 5 跳：`used_command = true` ⇒ 循环永不自停**
  `src/agent/self_prompter.js:78-91`
  ```js
  let used_command = await this.agent.handleMessage('system', msg, -1);
  if (!used_command) { no_command_count++; if (no_command_count >= 3) { …STOPPED } }
  else { no_command_count = 0; await new Promise(r => setTimeout(r, this.cooldown)); }  // cooldown=2000
  ```

  **叠加的三个放大器（都是既有问题）**：
  - `settings.js:49 "max_commands": -1` ⇒ 单轮命令数 Infinity；
  - 自提示的提示词明写 `Your next response MUST contain a command` ⇒ 模型几乎每轮都会发命令；
  - 按量计费中转站（`profiles/my-local.json: url: https://api.llmgo.net/v1`）⇒ 直接是钱。

exploitability: |
  **不是远程攻击，是"用户自己会踩的坑"，但后果是持续计费 + 无法用命令停止。**

  触发条件（三选一，都很现实）：
  1. 用 `my-local`（owner=HEAVENZEH）设过 `!goal` → 之后切到 `deepseek` / `defaults/*`（实测 owner 全为 null）；
  2. profile 里 `owner` 打错一个字、或写成 `" "`（`permissions.js` 明确把空串当"没配"处理，且有单测覆盖这个判据）；
  3. 把配置分享给别人、对方没改 owner。

  一旦触发：
  - 每 2 秒一次 LLM 调用，**永不停止**（因为每轮都"用了命令"——虽然全被拒）；
  - 玩家在游戏里 `!endGoal` 也叫不停（`!endGoal` 是 TRUSTED ⇒ 在 OTHER 级同样被拒）；
  - 只能改/删 `memory.json`，或把 owner 补回去。

  拿不到什么：不越权、不 RCE（命令确实全被拒了 —— **拒是对的，问题只是循环没停**）。

suggested_fix: |
  **三选一，推荐第 1 条（最小、最准）。三条一起做最稳。**

  **①（推荐）"被权限拒绝"不算"用过命令"** —— `src/agent/agent.js` 命令分支：
  ```js
  let execute_res = await executeCommand(this, res, perm);
  used_command = true;
  if (typeof execute_res === 'string' && execute_res.startsWith('[权限]')) {
      // 权限拒 = 这条命令**没有真的执行** ⇒ 不该算"用过命令"，
      // 否则自提示循环会被永久喂活（F-AI-205）
      used_command = false;
  }
  ```
  > 效果：自提示回合里"权限拒绝"等同于"没命令" ⇒ 连续 3 轮即 STOPPED，正是想要的语义。

  **②（治本，改动大）给 `self_prompter` 加 `max_turns` + 总时长上限**（即长期 blocked 的 `F-AI-202 ③`），
  且 `update()` 的自动重启必须尊重同一上限。

  **③（最保守，防的是"恢复"这一侧）** `history.js` 恢复 goal 时校验作者等级：
  若 `resolveLevel(该 author)` 低于 TRUSTED，则**不恢复 goal**（`self_prompt = null`）并打一行日志说明
  "因 profile 未认主人，已丢弃上次的目标"。
