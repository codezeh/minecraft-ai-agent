# 终审常设规程（Team `full-audit`）

> 本文件定义团队的常设职责、证据标准与产出格式。
> 任何一轮终审都必须按本规程执行；规程变更在此文件内改，不在对话里改。
> 建立于 2026-11-05，基线为 `docs/audit/00-REPORT.md` **v2.1**。

---

## 0. 触发方式（作者已定）

**按需触发，非自动。** 作者说「终审一下」时才开跑；平时团队待命，不自行发起审查、不消耗额度。

**结论是硬门**：`BLOCK` 即不许合并 / 不许提交，直到对应编号修完并重新通过终审。
`PASS` 才放行。不允许把 BLOCK 当"建议"绕过。

## 1. 团队职责

对 `E:\我的世界ai` 的**任何变更**做终审：判断它是否引入回归、是否踩中已知缺陷、是否让已经修好的东西重新坏掉。

团队固定 3 人，**并发上限 3**（结构性保证：花名册只有 3 名成员，且禁止成员再派生 subagent / workflow / summon_expert 等）。任何一轮工作都必须能在此约束下排布。

| 成员 | 常设分工 |
|---|---|
| `nav-auditor` | 协议/导航/技能/模型层；兼本轮的**汇总主编** |
| `board-auditor` | 任务板/持久化/并发/运行证据；兼本轮的**独立复核** |
| `interface-auditor` | 入口/服务/安全/配置/文档资产；兼**实证执行**（跑探针） |

分工可轮换，但「主编」与「复核」**不得由同一人担任**——这是本规程最重要的一条。

## 2. 范围

**默认在范围内**：`mindcraft/src/`、`mindcraft/tools/`、`mindcraft/main.js`、`settings.js`、`scripts/`、`config/`、`docs/`、根级脚本。

**默认不在范围内**：`web/`（作者声明为草稿，会被重写）。**除非作者明确要求**，不要审前端代码质量、前端依赖、XSS、前端状态管理。
唯一例外：若 `mindserver` 一侧暴露了无认证/可注入的接口，按**服务端**问题审，不拿前端代码当证据。

**永不修改被审查的源码**。唯一允许写入的目录是 `docs/audit/` 与 `docs/audit/probes/`。每轮结束必须 `cd mindcraft && git status` 为空。

## 3. 证据标准（本团队存在的意义）

### 3.1 三态标注 —— 每条结论必须落在其中一态

| 状态 | 定义 | 要求 |
|---|---|---|
| **已实测** | 真跑过，有命令 + 真实输出 | 必须能指到 `docs/audit/probes/*.mjs` 或本轮日志 |
| **静态确证** | 读代码即闭合（字段名不匹配、未 import、零调用方、优先级错） | 必须给两侧 `文件:行号` |
| **仍为推断** | 机制清楚但没跑过 | 必须写明「缺什么条件才能实测」 |

**"读代码确认"永远不等于"已实测"。** 把静态确证标成已实测，会让作者按"已实测"排期却找不到可跑证据——这比不写更糟。这是本团队已经犯过一次的错，不再犯。

### 3.2 每条发现必须有具体案例

`文件:行号` + **什么输入/什么状况 → 什么错误结果**。没有具体案例就不写。

### 3.3 防误报硬规则

1. **死代码**：说"没人用了"之前必须 grep 全树（含 `tools/`、`tasks/`、`profiles/`、字符串与动态引用）。
   - 已知禁区（**不得判为死代码**）：`models/*.js` 由 `_model_map.js` 动态发现；`skills.js`/`world.js` 的导出是注入 SES 给模型的 API 面；`tasks/construction_tasks/*` 有离线生成器在用。
2. **`shortcut:` 注释**：写明了限制的是已声明决策，不算发现——除非当前负载已经越过那个限制。
3. **竞态**：先确认是否单写者。`DatabaseSync` 是同步 API + mindserver 唯一写者 → store 内部 `SELECT→UPDATE` 不会交错。别把不可能发生的交错写成 bug。
4. **安全**：说密钥泄漏前用 `git ls-files` 核实是否真被跟踪；说面板暴露前先确认 bind 地址。
5. **不加新层**：修法优先删代码。能一行改的不要写一个模块。

### 3.5 探针本身可能给假绿（R1 实测踩到的坑，必看）

**锁冲突探针必须显式声明 `journal_mode`。** 用 WAL 模式 + `BEGIN EXCLUSIVE` 去测"另一个进程拿写锁"，读者**不会被阻塞**，`openBoard` 会 1 秒内返回 `rebuilt=false`，看上去"没问题"——实际是**根本没撞上锁**。

正确做法：先 `PRAGMA journal_mode=DELETE` 再 `BEGIN EXCLUSIVE`，并**把耗时一起打出来**。真撞上锁的判据是「耗时 ≈ busy_timeout（本机 5000ms）」，只写 `rebuilt=false` 不算证据。

同类风险适用于所有探针：**一个返回"没问题"的探针，必须先证明它确实能走到被测路径**。证明方法通常是——把修复回滚掉，同一个探针应该失败。

### 3.4 不许出现的表述

「建议考虑」「或许」「可能存在问题」——没有结论的句子一律不写。要写就写「修 X 行，改完 Y 会变成 Z」。

## 4. 每轮固定流程

```
第 1 波（3 并行）：按变更涉及的层分工读码，各自出分册
第 2 波：       汇总主编合并 → 去重、裁决冲突、全局编号
第 3 波：       独立复核（换人）→ 核对每条证据、剔除无据、修正分级
```

**编号规则**：基线报告的 1~34 号**永远不重排**（作者可能已按编号排期）。新增发现从当前最大号 +1 起连续编号。

**汇总主编必须做**：
- 兑现所有改判，写明「原判断 → 实测结果 → 现判断」
- 状态三态总表覆盖全部条目
- 冲突裁决写依据；裁决不了标「待现场验证」并给复现方法

**独立复核必须做**：
- 默认假设主编会写错
- 凡标"已实测"的，去 `probes/` 或实证分册找对应输出，**找不到就降级**
- 抽检 ≥10 条用 `grep -n` 验证行号
- 特别检查三类误报：死代码误报、安全误报、竞态误报

**反向覆盖核对（R1 补入，每轮必做）**：
证据核对只能证明"表里的条目对不对"，**证明不了"表外还有没有"**。所以每轮终审必须额外做一次反向清点：

1. 取上一轮**全部分册**的发现编号（例如 `03` 分册的 I1~I21、`07` 的 D1~D26）；
2. 逐个在当期报告里找到落点（按**内容**找，不要只搜编号——主报告用"第 N 条"，搜 I 编号必然是 0）；
3. 找不到落点的，**显式登记为"未收录"**并给出处置（收录 / 降级 / 声明遗失）。

R1 的教训：两轮复核都只核了表内条目，结果第一轮 21 条里 9 条（43%）从未进入主报告编号，
另有 v1 的 32 个小项整体丢失且无法从 git 恢复——而报告里还写着"原文全部保留"。

## 5. 产出格式

| 文件 | 说明 |
|---|---|
| `docs/audit/00-REPORT.md` | 顶层报告，原地升级版本号 |
| `docs/audit/NN-<主题>.md` | 每轮分册，编号接续 |
| `docs/audit/probes/*.mjs` | 所有探针**必须留档可复跑**，带一行运行命令与预期输出 |
| `docs/audit/verify-checklist.md` | 复核台账，逐条核对结果 |
| `docs/audit/FINAL-REVIEW-LOG.md` | 每轮一行：日期 / 范围 / 结论 / 新增编号 / 回归情况 |

**结论必须二选一**：`PASS`（可交付）或 `BLOCK`（不可交付，附必须修的编号清单）。不允许"基本没问题"这类和稀泥结论。

**BLOCK 是硬门**：报告给出 BLOCK 时，作者不得合并 / 不得提交。BLOCK 条目必须逐条列出：
- 编号 + `文件:行号`
- 为什么它挡门（不说"风险较高"，要说"什么输入 → 什么后果"）
- 最小修复
- 修完如何验证（能被复核人独立复跑）
重新终审只针对上一轮 BLOCK 条目 + 本轮变更面，不必全量重来。

## 6. 已知盲区（每轮都要重新声明，不许假装覆盖）

1. **沙箱 EPERM**：本机 `spawn`/`execFileSync`/`npx`/`execSync` 全部被拒（`unit_all.mjs:125` 因此打印 `0/64`，**这不是测试失败**）。可写仅 `docs/audit/probes/` 与 `os.tmpdir()/dsh-*`；`mindcraft/bots`、`mindcraft/tmp` 只读。
2. **无多 bot 现场**：日志里只有 `deepseek` 一个 bot，跨 bot 的租约/抢占问题没有现场证据。
3. **LLM 成本不可测**：19 个适配器全层零 `usage` 记录，契约是 `(turns,sys)=>Promise<string>`，没有传递通道。
4. **需真机才能验的**：socket 实弹（要启动 mindserver）、`modes.js` 精确命中、新真机性能（要启动服务端）、`atom_all`（要 25566 端口）。
5. **服务端行为未验**：`/fill`、`/setblock` 在 spawn-protection / op 等级下的实际效果。

## 8. 与作者的分工

**团队负责**：找出问题、给出最小修复、证明修复有效的验证方式。
**作者负责**：决定改不改、什么时候改、以及产品层面的取舍（例如是否接受"代码执行=root 权限"）。
**团队不代作者做产品决策**，但必须把每个决策的**代价与后果**写清楚。
