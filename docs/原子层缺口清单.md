## 缺口 1：`canStand`（这格能不能站）—— 最高优先

**证据**：`task_collect.js:33-85`，`standableAt`(10 行) + `findStandSpot`(35 行) 共 **45 行手写**。

**为什么该是原子**：
- 「能不能站」是所有移动的前置条件，不是采集专属
- 现在它只服务 collect；`place` 需要它（不往脚下放）、`platform` 需要它（选落点）、
  `hop` 需要它（找落脚点）却各自另写一套
- 已有实测规则：`standableAt` 允许「下方是树叶」，而树叶会消失导致摔落被踢（R3-08）——
  这个判断必须只有一处，否则修了一处漏三处

**形态**：
```js
canStand(bot, pos) -> { ok, data: { standable, why, support: 'block'|'leaves'|'none' } }
findStandSpot(bot, targetPos, opts) -> { ok, data: { pos, distEyeToBlock } }
```

## 缺口 2：`collectDrops`（捡掉落物）—— 高

**证据**：`task_collect.js:88-178`，`waitPickup` + `collectDrops` 共 **62 行**。
`skills.js:920` 还有一个 `pickupNearbyItems`，**同一件事两套实现**。

**为什么该是原子**：
- 挖任何方块都会掉东西（不只是砍树）：挖矿、砍树、收作物、挖石头
- 现在 collect 一份、skills 一份，且 collect 那份删掉了「跳几下」补丁后只剩三段，逻辑简单
- 掉落物是**实体**，`query` 已经能定位实体了 —— 组合基础已经具备

**形态**：
```js
collectDrops(bot, origin, opts) -> { ok, data: { count, want, failed: [...] } }
```

## 缺口 3：`isSafe` / `safetyCheck`（这里危险吗）—— 高（安全相关）

**证据**：
- `skills.js:5206` `isSafeHere`
- `skills.js:5165` `markDanger`
- `heatmap.js` 里还有一套 hazard 逻辑（1504 行里的一部分）
- `modes.js:79` 自己判断「低血量 + 刚受伤」

**为什么该是原子**：
- 四个地方各自判断危险，标准还不一样
- 这是**安全相关**：判断错了她会走进岩浆、跳下悬崖
- 但要注意：这可能是复合层而不是原子（要查多个方向 + 血量 + 周围实体）

## 缺口 4：`lookAt`（看向）—— 中

**证据**：`atom_move.js:257` 有 `lookAt`，但**没有测试**，且被 `place` / `attack` 内部各调一次。

**为什么单独提**：陪玩场景里「看着玩家说话」是真实需求，现在只能靠别处顺手调。

**形态**：`lookAt(bot, target)` 支持 `{kind:'entity'|'point'|'block'}`，复用 `query` 的解析。

## 缺口 5：`waitFor`（等某个状态变化）—— 中

**证据**：几乎所有原子都有各自的轮询循环：
- `atom_dig` 的 `waitGone`（80ms × N）
- `atom_place` 的 `waitForBlock`
- `atom_use` 的 `waitFor`
- `atom_attack` 的主循环

**为什么该收敛**：四个实现都是「每 Xms 检查一次 predicate，超时返回 null」。
其中一个（`atom_use`）**踩过 false 被当成"未完成"的 bug**，其余三个没这个 bug 纯属运气。

**形态**：
```js
waitUntil(predicate, { timeoutMs, intervalMs = 80, interruptible: true }) -> { ok, data: { waitedMs } }
```

### `isSafe` 修掉的两个缺陷（本轮最有价值）

原 `skills.isSafeHere` 有两个会**漏报危险**的问题：

| 缺陷 | 后果 | 修法 |
|---|---|---|
| 液体采样只扫 ±4 格、步长 2 | 5~10 格外的岩浆被判"安全" → **两个真相**（规划器绕开，检查说安全） | 采样 + 枚举两条路都走 |
| `collectHazards` 的圆点是 **bot 自身** | 查远处位置时答案完全错 | 改用目标位置作圆心 |

实测（`atom_safe.mjs`）：6 格外的岩浆 `liquids=0`（采样没看到）但 `nearHazards=1`（枚举发现）。

**定位声明**：这是【预检】不是【保证】。`safe:true` 只表示"没有已知风险"，
不覆盖脚下塌陷/活塞/水下呼吸。API 带 `note` 明示。

### `lookAt` 的后置校验

`bot.lookAt` 在目标被挡时会**静默不转**，所以读 yaw/pitch 确认：
正东 `yaw=-1.57`、天顶 `pitch=1.57`、脚下 `pitch=-1.57`，全部实测通过。
实体看**头部**（`height*0.85`）而不是脚——看脚像在盯地面。

### 本轮修掉的 3 个真 bug

| # | bug | 现象 | 根因 | 修法 |
|---|---|---|---|---|
| 1 | **外部瞬移后坐标 NaN** | tp 后 `position={x:NaN,y:-60,z:NaN}` | mineflayer 物理引擎下一 tick 用「旧位置+瞬时位移」重算并 apply（`physics.js:81`） | `src/sim/position_guard.js` |
| 2 | **外部瞬移后 onGround 永久 false** | 挖方块永不触发，报模糊的「挖了 1.5 秒没挖完」 | tp 后客户端认为悬空、速度 0，物理引擎不自纠 | `atom_dig` 按**脚下方块**判定，不信标志位 |
| 3 | **`countFn` 抛错让原子崩掉** | `atom_drops` 直接 node 崩 | 判据函数由调用方提供，没兜异常 | 降级 `INTERNAL` + 说明"判据不可用" |

第 2 条的教训：**只信标志位不够，要读世界**。
