# 字段标准（v1）

> 配套 [原子动作规格-v2.md](原子动作规格-v2.md)。这份只管一件事：**同一个概念只有一个名字、一个口径**。
> 制定：2026-10-24

---

## 0. 为什么要定这个

现状是同一个字段名有三种含义：

| 文件 | `dist` 实际是什么 |
|---|---|
| `atom_dig` / `atom_container` | 眼睛 → 方块中心 |
| `atom_move` | 脚 → 目标点（剩余距离） |
| `atom_attack` | 脚 → 实体位置 |

上层只要看到 `dist` 就得回去查是哪个原子返回的。复合技能一多，这种"隐含语境"必然出错。

---

## 1. 三个原则

| # | 原则 | 说明 |
|---|---|---|
| P1 | **名字带参照点** | 距离不叫 `dist`，叫 `distEyeToBlock` / `distFeetToTarget`。宁可长，不可猜 |
| P2 | **位置只有一种形状** | `{x,y,z}` 整数方块坐标，或 `{x,y,z}` 浮点实体坐标，**永不用 Vec3**（跨模块传递会变成隐式依赖） |
| P3 | **数量只有一种名字** | 已完成 `count`、目标 `want`。不许出现 `collected`/`got`/`placed`/`num` |

---

## 2. 字段表

### 2.1 位置

| 字段 | 类型 | 口径 | 取代 |
|---|---|---|---|
| `pos` | `{x,y,z}` 整数 | 方块坐标（已取整） | `at` / `cell` / 裸 `pos` / Vec3 |
| `entityPos` | `{x,y,z}` 浮点 | 实体坐标（可带小数） | 各处 `e.position` 直接传出 |

**规则**：方块坐标必须取整。曾经因为传了带小数的坐标给 `bot.blockAt`，报过
`pos.floored is not a function`（交接文档 §7.2）。

### 2.2 距离（拆成三个名字）

| 字段 | 口径 | 出现在 |
|---|---|---|
| `distEyeToBlock` | 眼睛 → 方块中心 | dig / place / container / use |
| `distFeetToPoint` | 脚 → 目标点 | move |
| `distFeetToEntity` | 脚 → 实体位置 | attack |

**为什么不用 `dist`**：上表三种口径都叫 `dist` 时，调用方无法从返回值判断
"这个 4.2 是够得着还是没走到"。名字里带参照点，看代码就不用查文档。

### 2.3 数量

| 字段 | 类型 | 口径 | 取代 |
|---|---|---|---|
| `count` | number | 已完成的数量 | `collected` / `got` / `placed` / `dropped` |
| `want` | number | 目标数量 | `num` / `target_num` |
| `left` | number | 剩余（如背包剩余该物品） | 保留，语义明确 |

### 2.4 进度与结果

| 字段 | 类型 | 口径 |
|---|---|---|
| `costMs` | number | **本层自身**耗时（不含调用方重试） |
| `partial` | boolean | 只用于 move：超时/失败但有推进 |
| `advanced` | number | 只用于 move：推进了多少格（配合 `partial`） |
| `killed` | boolean | 只用于 attack |
| `existed` | boolean | 只用于 place：目标已经是该方块 |
| `closed` | boolean | 只用于 closeContainer |
| `failed` | `[{pos, code, message}]` | 复合层的失败明细 |

### 2.5 步骤（复合层用）

| 字段 | 类型 | 口径 |
|---|---|---|
| `step` | number | 在复合技能里的序号（1 起） |
| `phase` | string | `plan` / `move` / `dig` / `pickup` / `cleanup` / `report` |

### 2.6 其余（各原子专属，不许推广）

| 字段 | 用于 | 说明 |
|---|---|---|
| `block` | dig / place / use / container | 方块名 |
| `item` | equip / drop / place | 物品名 |
| `kind` | container / use / attack | 容器类别 / 交互类别 |
| `slots` `containerSlots` `expectedSlots` `slotConsistent` | container | 槽位构成（见下方注） |
| `title` | container | 窗口标题 |
| `hpLeft` | attack | 剩余血量（**常常是 undefined**，见注） |
| `tool` | dig | 用了什么工具 |
| `state` | use | 门 open / 床 sleeping / 作物 harvested |

---

## 3. 三条必须记住的实测约束（不是设计选择）

| 约束 | 证据 |
|---|---|
| `window.slots.length` = 容器槽位 + **36**（背包27+快捷栏9） | 测试服实测：箱子 = 63 |
| monster 的 `entity.health` 恒为 `undefined` | mineflayer 不暴露 `Health` metadata |
| 方块坐标必须取整再传给 `bot.blockAt` | 否则 `pos.floored is not a function` |

---

## 4. 迁移方式（不动行为）

### 4.1 分两步，不一次改完

| 步 | 做什么 | 风险 |
|---|---|---|
| **兼容期** | 返回值**同时**带旧名和新名（`dist` + `distEyeToBlock`），调用方逐步迁 | 零（旧代码照常跑） |
| **收口期** | 全部调用方迁完后删旧名，并在 `contract_audit` 里加"禁止旧名"检查 | 低（已无调用方） |

**不直接改名**：`task_collect` 等 690 行的调用方一次改完，出问题无法定位。
兼容期让每一处迁移都能单独验证。

### 4.2 检查机制

`tools/contract_audit.mjs` 增加：

1. 原子返回的 `data` 键必须在 §2 表内（表外键 → fail）
2. 出现被取代的旧名（`collected`/`got`/`at`/`cell`）→ fail
3. 距离字段必须匹配原子类型（dig 返回 `distFeetToPoint` → fail）

### 机器检查已落地

`tools/audit_rules.mjs` 新增第 5 层 `fieldAudit`（进 preflight）：

- `ok({ dist: ... })` → fail
- `{ x, z }` 未标 `posXZ` → fail
