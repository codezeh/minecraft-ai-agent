> 配套 [改进规划.md](改进规划.md) §5。前四轮把**原子层**（13 个，177 用例）和**规则/字段/接口三份标准**建好了。

## 0. 一句话目标

复合技能拆成 **`plan()` 产出可检查的步骤序列** + **`run()` 逐条执行**，
失败能报到 `step N / atom / code`。

```
现在：collect 失败了（哪一步？不知道，翻日志）
目标：step 7 / digBlock / OUT_OF_REACH（直接定位）
```

## 2. 设计

### 2.1 两个纯函数 + 一个执行器

```js
// 1) 规划：纯函数，无副作用，可单测、可打印、可人工检查
planCollect(bot, { blockNames, want, near }) -> {
  steps: [
    { step: 1, atom: 'moveTo',    args: { target: { kind:'point', pos } },
      expect: 'arrived', onFail: [{ code:'NO_PATH', action:'replan' }] },
    { step: 2, atom: 'digBlock',  args: { target: { kind:'block', pos } },
      expect: 'gone',    onFail: [{ code:'OUT_OF_REACH', action:'restep' }] },
    ...
  ]
}

// 2) 执行：只按序列跑，不重新决策
runSteps(bot, steps, { onStep }) -> {
  ok, code, message,
  data: { doneSteps, failedStep, count, want, failed: [{pos,code,message}] }
}
```

**为什么 plan 必须是纯函数**：它要能被打印、被 diff、被单独测。
"计划"如果依赖执行中途的状态，就没法人工检查——那不叫计划，叫执行。

### 2.2 步骤的字段（进字段标准）

| 字段 | 含义 |
|---|---|
| `step` | 序号，1 起 |
| `atom` | 原子名（`moveTo` / `digBlock` / `collectDrops`…） |
| `args` | 传给原子的参数（遵循原子接口标准） |
| `expect` | 后置期望，用于"读世界"校验 |
| `onFail` | 降级表：`[{code, action}]`，`action ∈ retry / replan / restep / skip / abort` |
| `phase` | `plan` / `move` / `dig` / `pickup` / `cleanup` / `report` |

### 2.3 执行器的行为（必须明确，否则会变成第二个 collect）

| 情况 | 行为 |
|---|---|
| 原子返回 ok | 继续下一步 |
| 原子返回 ok + partial（move 专属） | 视为"推进了"，重新规划剩余步骤 |
| 原子失败，`onFail` 有匹配 code | 执行对应 action |
| 原子失败，`onFail` 没有匹配 code | 记为 failed，跳到下一个"同类步骤"或整体失败 |
| `bot.interrupt_code` | 立刻停，返回 `INTERRUPTED` + 当前 step |
| 超过 deadline | 停，返回 `TIMEOUT` + 当前 step |

**执行器不许猜测**：它只按 `onFail` 表行动。表里没写的降级 = 不做降级（报上去让上层决定）。

## 5. 判据：什么时候算"复合层做对了"

不是行数变少，而是这三件事能做到：

1. **同一个 bug 只修一处**（现在是三条挖掘路径，修一处忘两处）
2. **报错定位到步骤**（现在是一句"采集失败"）
3. **能单独测一个步骤**（现在只能整场跑）

---

## 6. 提取成原子的判断标准（本轮边做边用）

| 情况 | 归属 |
|---|---|
| 纯查询/判断，无副作用，别处也会用 | **原子**（如 `classifyLog`、`isProtected`） |
| 编排多个原子、需要降级/重试/换目标 | **复合（L2）** |
| 带 deadline、黑名单、进度汇报 | **任务（L3）** |

**判断口诀**：这一块**单独跑有没有意义**？能单独跑、能单独测 → 原子；必须串起来才有意义 → 复合。
