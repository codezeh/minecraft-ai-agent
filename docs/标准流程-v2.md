# 标准流程（实操版 v2）

> [改进规划.md](改进规划.md) §3 定的是**理论骨架**。这份是跑完一整轮之后，
> 用真实经历校准出来的**实操版**：哪步最值钱、哪步最容易跳过、跳过了会怎样。
> 制定：2026-10-24 · 依据：P0 → 原子层(13) → 复合层(collect 落地) 全过程

---

## 0. 一句话

**先证事实，再定契约，再量基线，再一次只改一层，最后记账。**
五步里任何一步跳过，返工成本都会翻倍——下面每条都有代价记录。

---

## 1. 五步闭环（实操版）

| 步 | 做什么 | 产物 | 跳过会怎样（实测） |
|---|---|---|---|
| **1 证事实** | 任何"游戏规则"先找出处：注册表 / 源码 / 探针 | `rules/game_rules.json` 一条 | 凭空写"树会塌"→ 白写 110 行 `tree_strategy.js`；交互距离调了三次都不对 |
| **2 定契约** | 先定字段/接口/步骤形状，再写代码 | 标准文档 + 一张字段表 | 先写代码后统一字段 → 14 处调用方返工，`dist` 三种含义搅在一起 |
| **3 量基线** | 改之前先跑一遍拿数字 | `tmp/bench/*.jsonl` | 没有基线 → "改完感觉快了"但实际更慢；8 轮测试全在同一个死点空转 |
| **4 改一层** | 一次只动 L1 / L2 / L3 中的一层 | 代码 + 该层测试 | 原子和复合一起改 → 报错说不清是谁的错 |
| **5 记账** | 数字、日期、证据落盘 | `验收记录.md` + 规则表 + 经验教训 | 三天后忘了"6.11 格"是哪个脚本测的，只能重测 |

## 2. 每步的具体做法

### 2.1 证事实（最容易被跳过，代价最大）

**做法**：写任何判断前先问"这条规则的出处是哪一级？"

| 级别 | 来源 | 例子 |
|---|---|---|
| R1 注册表 | `bot.registry` 运行时派生 | `stone.harvestTools` = 6 种镐 |
| R2 库源码 | 引 文件:行号 | `GoalLookAtBlock` 默认 reach 4.5（`goals.js:160`） |
| R3 探针实测 | 跑脚本、落日志 | 服务端挖方块不校验距离（6.10 格仍成功） |

**没有出处的规则不许进代码**。机器检查：`preflight` 第 3 层扫裸常量，必须带 `// rule:Rx-xx`。

**这一轮的收益**：
- 发现 3 条"文档里写的规则"是错的（`harvestTools` 是 undefined 不是空、`spreadplayers` 不安全、出生点不是森林）
- 发现 2 个真 bug 的根因（NaN 传播、`onGround` 卡死）

### 2.2 定契约（省时间最多的一步）

**顺序**：字段表 → 接口表 → 步骤形状 → 才开始写实现。

| 契约 | 管什么 | 落点 |
|---|---|---|
| 字段标准 | 返回什么（`distEyeToBlock` 而非 `dist`） | `字段标准.md` |
| 接口标准 | 怎么传进去（`{kind,pos}` 而非三个数） | `原子接口标准.md` |
| 原子规格 | 每个原子的前置/后置/错误码 | `原子动作规格-v2.md` |
| 步骤形状 | 复合层怎么串（`step/atom/args/expect/onFail`） | `复合层改造规划.md` §2 |

**判断"契约好不好"的三个检验**：
1. 同一个概念只有一个名字？
2. 同名在成功/失败时是同一个意思？（`block` 双义就是反例）
3. 上层能不能只看返回值判断状态，不用回去查代码？

### 2.3 量基线（最容易被"我觉得"替代）

**必做**：至少 10 轮（本文实测 5 轮已能区分 60% 和 80%），记录：
`pass / 报数 vs 背包增量 / 耗时 / 失败码直方图 / 起点坐标 / 附近可选目标数`

**判据必须是确定性的**：`报数 == 背包增量`。不是"看起来成功了"。

**这一轮的收益**：
- 第一次拿到真实数字：**3/5（60%）**，而"验收记录"里曾写 9/9
- 发现失败全是同一个根因（站树叶 → 摔 → 被踢）

### 2.4 改一层（防止"说不清是谁的错"）

**分层红线**：

| 层 | 只做 | 禁止 |
|---|---|---|
| L1 atom | 一次尝试、前置断言、后置读世界 | 循环找目标、重试、考虑 deadline |
| L2 skill | 编排原子、产出步骤序列 | 直接调 `bot.dig` / `bot.pathfinder` |
| L3 task | deadline、降级、黑名单、汇报 | 实现挖掘/寻路细节 |

**边做边问**：这块该不该提成原子？判据只有一条——**单独跑有没有意义**。
能单独跑、能单独测 → 原子；必须串起来才有意义 → 复合。

**这一轮的收益**：顺手把 `classifyLog` / `isProtected` 提成原子，`task_collect` 少了 68 行。

### 2.5 记账（决定下次能不能接着干）

三处必记：

| 记在哪 | 记什么 |
|---|---|
| `验收记录.md` | 数字 + 证据文件路径（不写"感觉"） |
| `game_rules.json` | 新验证的规则（带 `evidence` 字段） |
| `经验教训.md` | 坑的现象→根因→对策 |

**记账的判断标准**：三天后能不能只凭这条记录重跑一次？不能就是记得不够。

## 3. 每轮必跑的三条命令

```bash
node tools/preflight.mjs      # 四层：导入 / 冒烟 / 规则审计 / 新模块申报
node tools/atom_all.mjs       # 原子 + 复合全套
node tools/bench_s2_main.mjs 3  # 主服真实地形（改行为才需要）
```

**`preflight` 的四层是四种不同的错**：

| 层 | 抓什么错 | 曾经抓到 |
|---|---|---|
| 1 导入 | 模块引用不存在 | 漏 import 导致 `MEMBER_CODE_VERSION` 崩 |
| 2 冒烟 | 函数体内未定义 | `resolveCollectTarget` 未定义 |
| 3 规则 | 裸常量没出处 | 14 处硬编码（5.1/1.62/4.5） |
| 4 申报 | 新模块没登记 | 3 个新原子没申报 |

**第 3、4 层是这一轮新建的**，它们把"约定"变成了"提交前错误"。

## 4. 最容易犯的五个错（都犯过）

| 错 | 表现 | 对策 |
|---|---|---|
| **跑偏层级** | 修原子时追进复合层，两头都没做完 | 开工先写"本轮只碰哪一层" |
| **凭记忆下结论** | 以为 F3 能看别人坐标、以为 `harvestTools` 是空对象 | 每条结论找出处 |
| **断言写错方向** | 「必须返回 NO_PATH」掩盖了"不可达却报 ok"的真 bug | 断言写「不许谎称 X」而不是「必须返回 Y」 |
| **测试假设环境干净** | 测试服被打脏 → "修一个坏一个" | 每个测试自带干净场地 + 独立区域 |
| **恢复代码带回已删内容** | `git show` 把用户要求删的补丁又带回来两次 | 恢复后全文搜已删关键词 |

## 5. 判断"这一轮做完了"的标准

不是"代码写完了"，是这五条同时成立：

1. `preflight` 四层全绿
2. 该层测试全过（原子：`atom_all`；复合：`skill_*`）
3. 行为不退化（同一 bench 对比改前数字）
4. 新模块已申报、新规则已入库
5. 验收记录里有**可复跑的数字**，不是形容词

---

## 6. 什么时候该停手重来

出现这三条中的任一条，说明方向错了，停下重定契约：

| 信号 | 说明 | 这一轮的例子 |
|---|---|---|
| 同一文件打补丁超过 2 轮 | 契约不对，不是代码不对 | `collect` 24 小时改 12 次 |
| 需要"猜机制"才能修 | 缺事实，回去做探针 | 交互距离调三次 |
| 修一个坏一个 | 测试或契约有问题 | 原子测试互相污染 |

---

## 7. 一句话总结

**这一轮真正的产出不是"采集能用了"，而是四件事：**

1. 一套**规则有出处**的机制（17 条规则 + 裸常量审计）
2. 一套**字段/接口有标准**的机制（两份标准 + 机器检查）
3. 一套**能定位到步骤**的结构（13 原子 + plan/runSteps）
4. 一份**坑的清单**（15 类，带证据）

采集只是第一个被这套机制覆盖的东西。下一个功能（follow / platform）应该**照着 §2 的五步走**，而不是照着 collect 抄代码。
