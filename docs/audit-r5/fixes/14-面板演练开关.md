# 14 · 给面板加演练开关（`-DryRun` / `MC_PANEL_NO_SPAWN`）

> 日期：2026-11-09 01:53–02:25 (+08:00) · 提交 t34 · 工作目录 `E:\我的世界ai`
> 起因：T32 取证报告的**结构性 finding** —— `start-panel.ps1` 没有演练模式，导致"验证面板入口"必然在**生产目录起服**（20:42 事故就是这么来的）。
> 证据：[`docs/audit-r5/evidence/fix/14-panel-dryrun.txt`](../evidence/fix/14-panel-dryrun.txt)

## 0. 一句话

`scripts/start-panel.ps1` 现有**演练模式**：`-DryRun` 或 `MC_PANEL_NO_SPAWN=1` 任一成立 ⇒ 走完全部前置检查（JDK/Node/server.jar/旧 java/端口/目录），
但**一个进程都不 spawn**（java / node(vite) / 浏览器全覆盖），只打印"将要执行的命令 + 工作目录 + 端口"，然后 `exit 0`。
实测：`exit 0`，三处 spawn 全部打印，`server/logs/latest.log` 与 `logs/server-console.log` 的 **size 与 mtime 一字未变**，25565/25575/8080 无监听。

## 7. 以后怎么用 dry-run 验证面板（给团队的一段操作说明）

```powershell
# ① 最常用：完整冒烟（检查编码/语法/依赖/路径/端口，不产生任何副作用）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\start-panel.ps1 -DryRun
#    看三件事：
#      · 有没有 [DRYRUN] 之外的 ParserError / 找不到 xxx
#      · 三处 [ctx] 的 cwd 是不是你期望的目录（server / mindcraft）
#      · [ctx] 里 logs\latest.log 上次写入时间 —— 若显示"刚刚"，说明这个目录刚被人起过服

# ② 通过 .bat 验证（模拟用户双击入口，但走演练）
$env:MC_PANEL_NO_SPAWN = '1'
.\启动面板.bat        # 等价于双击，但不起服；看完记得 Remove-Item Env:\MC_PANEL_NO_SPAWN

# ③ 生产启动（**不要带 -DryRun**，也确认环境变量没设）
.\启动面板.bat
```

**纪律（与 T32 §8 呼应）**：
1. 任何"验证面板入口"的动作**一律先 `-DryRun`**；只有需要端到端确认时才真跑，且真跑前先记录 `server/logs/latest.log` 的 mtime 作为基线。
2. 真跑后核对：`server/logs/latest.log` 是否变大、`server/world/session.lock` 是否被更新、`server/whitelist.json` 是否变成 2 字节（= 被清空）。
3. **任何测试服一律 `cwd=tmp/<场景>/`**，从 `test-template` 重拷配置与世界，端口另择（25580/25590）。
