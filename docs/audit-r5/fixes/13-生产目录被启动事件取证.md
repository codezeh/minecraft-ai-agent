## 5. `whitelist.json` / `ops.json` 复核

### 5.1 结构 + uuid 独立复算（我重算，不引用 Lead 结论）

```
recomputed : 3f680b9f-53a9-34c1-900a-6ba8f0262175
expected   : 3f680b9f-53a9-34c1-900a-6ba8f0262175
MATCH      : true

whitelist.json raw = [{"uuid":"3f680b9f-53a9-34c1-900a-6ba8f0262175","name":"HEAVENZEH"}]
ops.json raw       = [{"uuid":"3f680b9f-53a9-34c1-900a-6ba8f0262175","name":"HEAVENZEH","level":4,"bypassesPlayerLimit":true}]

whitelist 结构 [{name,uuid}] : true
ops 结构 [{bypassesPlayerLimit,level,name,uuid}] : true
whitelist/ops 的 uuid == 复算值 : true / true
```

复算方法（与 Minecraft 一致）：`md5("OfflinePlayer:" + name)`，第 7 字节置 `version=3`、第 9 字节置 `variant=RFC4122`。
脚本：`tmp/r5-forensic/uuid-check.mjs`（不依赖任何第三方库）。

### 5.2 ⚠️ 离线 uuid 的**时效性警告**（务必写进用户须知）

现在这两条记录用的是**离线模式 uuid**（`online-mode=false` 时由"名字"算出来的固定值）。
**一旦把 `server.properties` 的 `online-mode` 改成 `true`**，Mojang 会为该玩家签发**另一个完全不同的 uuid**（真实账号 uuid），
于是 `whitelist.json`/`ops.json` 里这条 `3f680b9f-…` 将**匹配不上任何人** ⇒ 玩家会被白名单挡住、op 也失效。
切换时**必须**在控制台重新执行：`whitelist add HEAVENZEH` 与 `op HEAVENZEH`（或停服后按新 uuid 重写这两个文件）。

### 5.3 清空事实与"补前副本"

```
$ cat tmp/r5-收口/whitelist.json.before-restore   → []
$ cat tmp/r5-收口/ops.json.before-restore          → []
```

⇒ Paper 在缺文件时生成 `[]`；这次启动把原内容覆盖成空数组（**这是本次事件唯一的真实数据损失**）。

### 6.3 结构性原因（这是本报告要单列的 finding）

**`scripts/start-panel.ps1` 没有"演练模式"**：它没有 `-WhatIf`/`-DryRun`/`$env:MC_PANEL_NO_SPAWN` 之类开关，
`[1/4] Minecraft 服务器` 那一步就是无条件 `Start-Process -FilePath $java … -WorkingDirectory (Join-Path $root 'server')`（第 189-191 行）。

于是任何人**想验证"面板入口能不能用"**（R5-001 的验收要求），唯一办法就是**真的在生产目录起一次服** ——
这正是 20:42 事故的成因。**t12 修好 BOM 之后，`启动面板.bat` 从"解析即失败"变成"真的会起服"，事故概率反而升高**。
> **建议单列缺陷**：`start-panel.ps1` 增加 `-DryRun`（或 `MC_PANEL_NO_SPAWN=1`）：把 `Start-Process` 换成打印命令 + 退出 0，
> 让"验证入口"不再需要触碰生产目录。

## 8. 防复发：一条 30 秒可判定的检查 + 一条硬纪律

### 8.1 判定"有没有人在生产目录起过服"（推荐用日志 mtime，而不是看 java 进程）

```powershell
# 判据：Paper 只把日志写到自己 cwd 下的 logs/latest.log。
#       所以「生产日志的 mtime 晚于上次已知的良好时间」= 有人在 server/ 起过服。
$live = Get-Item 'E:\我的世界ai\server\logs\latest.log'
$panel = Get-Item 'E:\我的世界ai\logs\server-console.log'
"production latest.log : {0}" -f $live.LastWriteTime
"panel redirect log   : {0}" -f $panel.LastWriteTime
# 基线（本次事件后）：2026-11-08 20:42:46 —— 之后任何一次变化都意味着又被起过服
```

**为什么不能只看 java 进程/命令行**（本次实测反例）：查证期间机器上有 java 进程
`java -Xms512M -Xmx1024M -XX:+UseG1GC -jar E:\\我的世界ai\\server\\server.jar nogui` ——
**它指向生产 jar，但 `server/logs/latest.log` 的 mtime 一直没变（仍 20:42:46）**，
说明它的 `cwd` 在别处（`tmp/` 下的测试实例，直接用绝对路径引用生产 jar）。
⇒ **判据要用 `cwd`/日志落点，不能用 `-jar` 路径**。

配套的启动前断言（放在任何"我要起服"的脚本最前面）：

```powershell
$cwd = (Get-Location).Path
if (Test-Path (Join-Path $cwd 'server.properties') -and (Join-Path $cwd 'logs') -like '*\server\logs') {
    throw "拒绝在仓库的 server/ 生产目录起服：请改用 tmp/<场景>/（从 test-template 重拷）"
}
```

### 8.2 纪律（写进团队约定）

1. **任何起服验证，`cwd` 必须是 `tmp/<场景>/`**，配置从 `test-template/server.properties` 重拷、`server-port`/`rcon.port` 另择（如 25580/25590），世界从 `test-template/world` 拷。
2. **禁止为了"验证面板入口"而跑真实 `启动面板.bat`** —— 它固定 `cwd=server/`、固定 25565/25575。
   要么给 `start-panel.ps1` 加 `-DryRun`/`MC_PANEL_NO_SPAWN=1`（本报告 §6.3 的 finding），
   要么只在**明确许可的窗口**里跑，并在跑之前记录 `server/logs/latest.log` 的 mtime 作为基线。
3. **跑完必须核对**：`icacls`/`Get-ChildItem server -Recurse | ? LastWriteTime -gt $baseline` 应只出现 Paper 正常写的文件；
   一旦出现 `whitelist.json` / `ops.json` 变成 2 字节，立刻停手并按 §7 恢复。
4. **本事件的可复现信号**（三条同时出现 = 一定在生产目录起过服）：
   `server/logs/latest.log` 变大 + `logs/server-console.log` 变大 + `server/world/session.lock` mtime 更新。
