## 1. R5-012：`err.stack` 恒 `undefined`

### 1.1 缺陷原貌（`src/agent/action_manager.js`，改前 422-427）

```js
await this.stop(stopReason);
err = err.toString();          // ← err 从 Error 变成**字符串**

let message = this.getBotOutputSummary() +
    '!!Code threw exception!!\n' +
    'Error: ' + err + '\n' +        // ← err.toString() 已含 "Error: " 前缀
    'Stack trace:\n' + err.stack+'\n';   // ← 字符串没有 .stack ⇒ undefined
```

两处后果：
1. `Stack trace:` 后面**恒为字面量 `undefined`** —— 模型/面板拿到的失败消息永久丢堆栈；
2. `'Error: ' + err.toString()` 拼出 **`Error: Error: boom`** 双前缀。

（上一轮 `07-lint-nonstyle.md` 已把它判为 REAL-DEFECT；本轮把它修掉。）

### 1.2 修复（最小改动，只动 catch 块内 3 行 + 注释）

```diff
+            // ★ R5-012（2026-11-08）：**别再把 err 覆盖成字符串**。
+            //   原来这里是 `err = err.toString()`：err 从 Error 变成字符串，
+            //   下一行却还读 `err.stack` ⇒ 恒 undefined，模型拿到的永远是
+            //   "Stack trace:\nundefined"（诊断能力归零，排障时看不到真因）；
```


而任务书给的文件名是 `fix-r5-012-unit.mjs`（**连字符**）⇒ **不在发现范围内**。后果不是"少跑一个测试"这么轻：

### 6.2 修法：改名走约定，而不是加白名单（选 a）

```
git mv tools/fix-r5-012-unit.mjs tools/fix_r5_012_unit.mjs    # 实际为 mv（该文件当时还未跟踪）
```

为什么选改名而不是 `EXTRA_OFFLINE` 白名单：
- **零登记成本**：以后谁写新探针，只要按 `*_unit.mjs` 命名就自动进网；白名单需要有人记得去登记（那就是又一处"会烂的名单"）。
- **与 `unit_all.mjs:31` 的既有主张一致**：注释里写的就是"自动纳入、新增脚本零登记成本"。
- 代价可控：只有一处自引用需要跟着改（见 6.3）。

### 6.3 改名引出的唯一次要改动（不是放宽断言）
