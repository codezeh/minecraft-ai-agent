## 1. A 项：`scripts/stop-panel.ps1` 从不透传退出码

### 改前

全文只有第 14/15 行的 `exit 1`（前置检查：找不到 node / 找不到 stop-all.mjs），
真正的停止结果 `$stopCode` 只用来**打印提示**，脚本最后一行是 `Read-Host '按回车关闭'`：

```

Read-Host '按回车关闭' | Out-Null
```

⇒ PowerShell 进程以最后一条语句的结果结束 ⇒ **恒 0**。用户屏幕上写着"[ERROR] 拿不到握手 token""关服没有成功"，但 `停止面板.bat` / 计划任务 / 快捷方式看到的都是"成功"（t12 实测 `BAT_EXITCODE=0`）。

### 改后（diff，+7 行，全在文件末尾）

```diff
 Read-Host '按回车关闭' | Out-Null
+
+# ★ t20 A：把停止结果码透传给**进程退出码**。以前本脚本以 Read-Host 结束，
+#   PowerShell 进程恒返回 0（t12 实测：屏幕上写着“[ERROR] 拿不到握手 token”“[ERROR] 关服没有成功”，
+#   但停止面板.bat / 计划任务 / 快捷方式看到的都是“成功”）。
+#   stop-all.mjs 码义：0=已停或本来就没跑，2=拿不到 token，3=握手被拒，4=关服没成功。
+if ($null -eq $stopCode) { exit 1 }   # stop-all 根本没跑成（异常路径）也不能当成功
+exit $stopCode
```

要点：
- `exit` 放在 **`Read-Host` 之后**（用户仍然能看到错误、按回车再关窗），但码取自**前面已存好的 `$stopCode`**，不受 `Read-Host` 影响 —— 符合任务里"Read-Host 之前先把码存好，最后 exit 用存的变量"。
- `$null -eq $stopCode` 兜底为 1：万一 try 块在赋值前就抛了（异常路径），不能默默当成功。
- `ParseFile` 校验：`ERRORS=0`。

## 3. C 项：token 重建后自动收口 ACL —— ✅ **已施加并实测**

> t20 时本项因 `mindserver.js` 归 vault-dev 而暂停；t24 由 captain 交回后**已施加**。
> vault-dev 的改动（顶部 import 块 + `attachVaultApi()` + 两处调用点，7 条 `/api/vault/*` 路由）**一字未动**。

### 为什么必须从产品代码修（复发机制，t11/t12 实测）

`.mindserver-token` 每次启动都由 mindserver **重新创建**，新建文件会**重新继承父目录 ACL**
（`mindcraft/` 对 `Authenticated Users` 有 `(RX)`）⇒ 运维侧 `harden-credentials-acl.ps1 -Apply` 的一次性加固必然复发
（实测：回归 `22/0` → 起一次 mindserver → `20/2`）。

### 锚点定位（不用行号）

行号会漂（本轮实测：改动前 token 在 **614**，插入 helper 后漂到 **664**），所以按锚点找：

```js

try {
```

### 改动（相对 vault 落定后的基线，只新增 3 处：import + helper + 1 行调用）

```diff
@@ 顶部 import
+// t20-C（R5-收口）：token 文件落盘后要收口 NTFS DACL。只用 execFile(argv)，**不用 shell**。
+import { execFile } from 'child_process';

@@ 模块顶部（__dirname 之后）
+const SLASH = String.fromCharCode(47);      // 不写裸斜杠字面量，避开 preflight 规则
+
+function hardenTokenFileAcl(file) {
+    if (process.platform !== 'win32') return;
+    try {
+        const icacls = path.join(process.env.SystemRoot || 'C:\\Windows', 'System32', 'icacls.exe');
+        const who = process.env.USERNAME;
+        if (!who) { console.warn('[mindserver] token ACL 收口跳过：取不到 USERNAME'); return; }
+        execFile(icacls, [file, SLASH + 'inheritance:r'], { windowsHide: true }, (e1) => {
+            if (e1) { console.warn(`[mindserver] token ACL 断开继承失败（不影响启动）：${e1?.code ?? e1}`); return; }
+            const grants = [file, SLASH + 'grant:r', who + ':(F)', '*S-1-5-18:(F)', '*S-1-5-32-544:(F)'];
+            execFile(icacls, grants, { windowsHide: true }, (e2) => {
+                if (e2) { console.warn(`[mindserver] token ACL 授权收紧失败（不影响启动）：${e2?.code ?? e2}`); return; }
+                console.log(`[mindserver] token 文件 ACL 已收口（非继承，仅当前用户/SYSTEM/Administrators）：${file}`);
+            });
+        });
+    } catch (e) { console.warn(`[mindserver] token ACL 收口异常（不影响启动）：${e?.message ?? e}`); }
+}

@@ 写 token 处
     writeFileSync(TOKEN_FILE, handshakeToken, { encoding: 'utf8', mode: 0o600 });
+    // t20-C：新建文件会继承父目录 ACL ⇒ 立刻收口（异步、失败只 warn，不阻塞启动）
+    hardenTokenFileAcl(TOKEN_FILE);
```

设计要点：`execFile(icacls, argv)` **不开 shell**（与本仓 spawn+argv 口径一致，无注入面）；先断继承再授权；非 win32 直接 return；任何失败只 `console.warn`，**绝不影响启动**；幂等（每次重建 token 都收口一次）。

### 风险

- `USERNAME` 与真实运行账户不一致（服务账户/域账户）时 `/grant:r` 可能授错人或失败 → 只 `warn`，不会锁死；
- 非管理员上下文下 `/inheritance:r` 通常仍可（改自己拥有的文件 ACL），失败则保持原样；
- 最差情况：写 token 成功、两次 icacls 都失败 ⇒ 退回现状（继承 ACL）+ 一条 warn，不比改之前更差；
- 仍**不是**权限边界：同一账户下的进程本就能读 token（`auth_gate.js` 顶部已写明这一层只解决"别进日志"和"别让别的本机账户读"）。
