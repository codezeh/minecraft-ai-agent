## B. RCON 仍只对本机（防火墙）

### B.1 为什么必须用防火墙

Paper 1.21.8 **没有独立的 rcon 绑定参数**，RCON 只能跟 `server-ip` 走（`scripts/deny-rcon-25575-in.ps1` 头部已写明）。
所以"开 25565 给局域网"必然连带把 25575 也开到所有网卡 ⇒ 必须用防火墙拦 25575 入站。
Windows 防火墙**不检查 loopback**，bot 走 `127.0.0.1:25575` 照常工作。

### B.2 脚本执行（如实：CANNOT-RUN，但规则已在位）

```
$ powershell -NoProfile -ExecutionPolicy Bypass -File scripts/deny-rcon-25575-in.ps1

  [错误] 需要管理员权限。
         请右键本文件 → "以管理员身份运行"，或在管理员 PowerShell 里执行：
         powershell -ExecutionPolicy Bypass -File .\scripts\deny-rcon-25575-in.ps1
--- exit: 1 ---
```

**诚实说明**：当前 shell **不是管理员**（实测 `IsInRole(Administrator)` = `False`），所以这个脚本**无法新建/重建**规则，
它按设计 fail-closed（打印错误 + exit 1，没有假装成功）。

**但规则已经存在**（应为此前轮次 t16 的成果），所以"RCON 只对本机"这个**目标状态是满足的**：

## C. 离线主人会话窗口 720 → 60

### C.1 改动（只改一个数值）

```diff
--- a/mindcraft/settings.js
+++ b/mindcraft/settings.js
@@
-        //                     离线服日常可用；窗口越短越安全（默认 720 分钟 = 12 小时）。
+        //                     离线服日常可用；窗口越短越安全（**当前 60 分钟 = 1 小时**，t27 由 720 调小）。
         "offline_owner_mode": "session",
-        "offline_session_minutes": 720
+        "offline_session_minutes": 60    // 用户要求调小（t27）：720(12h) → 60(1h)，兼顾安全与可用
```

- **只改这一个数值**；`offline_owner_mode` 保持 `"session"`（**没有**改成 deny —— 用户还要用主人权限）。
- 顺带把紧邻的那句"默认 720 分钟 = 12 小时"改成现值，否则注释立刻又过时。

### C.2 为什么选 60（而不是 120）

用户原话是"调小"。60 分钟 = 1 小时：一次“进服 → !claim → 建房/搬家”的连续游玩通常在一小时内完成；
而参考代码里的兜底默认是 720（12 小时），60 把暴露窗口压到 **1/12**。若日后觉得频繁要 claim，改回 120 只是一行。
