## 4. `settings.js` 的"不许毁注释"实测

| 指标 | 改动前 | 写入 90 后 | 改回 60 后 |
|---|---|---|---|
| 行数 | 79 | 79 | 79 |
| `//` 注释行数 | **55** | **55** | **55** |
| `import('./settings.js')` | ok | `ok = 90` | `ok = 60` |
| 其他键 | — | 全部原样（`git diff` 只有那一个 literal 变化） | 逐字节回到基线 sha256 |

实现（`config_center.js` 的 `patchSettingsText`）：按行首锚定只替换 `"key": <literal>` 里的 literal，
**行尾逗号与注释留在匹配范围外**；并且要求该键在文件里**恰好出现 1 次**，否则拒绝盲改（`CONFIG_WRITE_FAILED`）。
写完整文件后 `import()` 验一次能否加载，加载不了就**回滚**并把备份保留。

**诚实的副作用（写进文档，不藏）**：因为是"只改值不动注释"，如果把某个**带解释性注释**的值
改成与注释不符（比如把 `offline_session_minutes` 长期改成 90，而注释还写着"当前 60 分钟 = 1 小时"），
注释会变**陈旧**。这是"绝不用 JSON 序列化重写"必然的代价 —— 相比之下，丢掉 55 行注释
（其中包含"为什么默认关 allow_insecure_coding"这类关键解释）是更糟的选择。
本轮验收里 90 只是临时值，最后已改回 60，所以注释与值重新一致。

### 6.1 一次真实的"假红"—— 记下来，别下次再浪费时间

第一次跑 `gate:full` 得到 **exit=1**，红项是：

```
❌ llm_usage_unit  (exit 4294967295)
133/134 个脚本通过，4 个跳过
```

`4294967295` = `-1`（进程被信号终止/超时杀掉）。日志停在
`Awaiting Replicate API response...` 之后没有再输出，说明是**跑着跑着被 unit_all 的
180s 超时杀掉**，不是断言失败。

单独跑同一个脚本：

```
$ node tools/llm_usage_unit.mjs
ALL PASS: 123 passed, 0 failed
exit=0 耗时=11s
```

⇒ 11 秒 vs 180 秒上限，余量巨大；失败与本次改动**无关**（我没碰 `src/models/**`），
是当时多张单并发跑门禁造成的瞬时抖动。第二次跑 `gate:full` 即 **exit 0**。
**结论口径**：偶发的 `exit 4294967295` 先单独复跑该脚本，再判断是不是并发抖动 ——
别把它当成"改了代码导致的失败"，也别直接放宽超时。

## 7. 设计取舍（给后面改这块的人）

1. **后端才是校验边界**：前端滑块的 min/max 只是提示，`PUT` 一定重新校验（实测 `keep=999` → 400）。
2. **先备份再写**：`config/*.json` 与 `settings.js` 改写前都复制成 `<文件>.bak-<时间戳>`；
   备份失败就**不写**（宁可保存失败，也不让现场没有退路）。写入用 tmp + rename 原子替换。
3. **JSON 保留换行风格**：`config/*.json` 在 Windows 上是 CRLF。第一版直接 `JSON.stringify`
   写回会把整文件变成 LF —— 内容没变但 sha256 全变，等于"改一个值重写整个文件"。
   现在按原文件探测 EOL 再写：改 `keep` 7→8→7 之后 sha256 **逐字节回到基线**（实测）。
4. **生效方式只有一个真相**：`GROUP_META` 在 `config_center.js` 里，接口把它带给前端；
   前端不再自己写一份"需重启"的文案。
5. **危险项两处拦**：`allow_insecure_coding` 开关本身红框 + 点开弹二次确认 + 保存前再确认；
   后端在 false→true 时打一条 `warn` 日志留痕（谁在什么时候打开了本机 root）。
6. **不重复做密钥输入**：模型与密钥组只有说明 + 跳转「凭据」页 + 只读 `model/profile`。
