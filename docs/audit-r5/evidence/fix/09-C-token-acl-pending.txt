## 3) 拟施加的改动（设计，尚未写入仓库）
   a) 顶部 import 追加：`import { execFile } from 'child_process';`
   b) 在 writeFileSync 成功分支之后调用一个本地函数（不 await，失败只 warn）：
      ```js
      // 用 String.fromCharCode(47) 拼出 "/"，避免源码里出现裸反斜杠/斜杠字面量被 preflight 规则扫到
      const SLASH = String.fromCharCode(47);
      function hardenTokenAcl(file) {
          if (process.platform !== 'win32') return;
          const icacls = path.join(process.env.SystemRoot || 'C:\\Windows', 'System32', 'icacls.exe');
          const who = process.env.USERNAME;
          // 1) 去掉继承（只留显式 ACE） 2) 只保留 当前用户 / SYSTEM / Administrators
          const rArgs = [file, SLASH + 'inheritance:r'];
          const gArgs = [file, SLASH + 'grant:r', who + ':(F', '*S-1-5-18:(F', '*S-1-5-32-544:(F'];
          execFile(icacls, rArgs, { windowsHide: true }, (e1) => {
              if (e1) return console.warn(`[mindserver] token ACL 断开继承失败（不影响启动）：${e1?.code ?? e1}`);
              execFile(icacls, gArgs, { windowsHide: true }, (e2) => {
                  if (e2) return console.warn(`[mindserver] token ACL 授权收紧失败（不影响启动）：${e2?.code ?? e2}`);
                  console.log(`[mindserver] token 文件 ACL 已收口（非继承，仅当前用户/SYSTEM/Administrators）：${file}`);
              });
          });
      }
      ```
   c) 在写 token 的 try 里成功分支末尾调用 `hardenTokenAcl(TOKEN_FILE);`

## 4) 安全与兼容性要点
   - `execFile(icacls, argv)`，**不用 shell:true**（与仓库既有 spawn+argv 口径一致，无注入面）；
   - `who` 取自 `process.env.USERNAME`（icacls 认名字；域名前缀可省略，同名不歧义时可用）；
   - 非 win32 直接 return；icacls 失败只 `console.warn`，**绝不**影响启动（任务要求）；
   - 不引入新依赖（node 内置 child_process）；
   - 顺序很重要：先 `/inheritance:r` 再 `/grant:r`，否则继承来的 AU ACE 仍在；
   - 幂等：每次启动重建 token 后都会重新收口一次，天然幂等。

## 5) 拟定的验收脚本（待落定后执行）
   1) `icacls mindcraft\.mindserver-token` 记录基线（应为非继承三条）
   2) 删掉 token（或直接起服让 writeFileSync 覆盖）→ 起一个最小 mindserver（一次性 MC_BOTS_ROOT + 非 8080 端口）
   3) 再 `icacls` → 期望：无 `(I)` 继承条目，只有 当前用户/SYSTEM/Administrators 三条
   4) `node scripts/tests/acl-regression.mjs` → 期望 exit 0，且**不需要**手动 -Apply

## 6) 风险
   - 若 `USERNAME` 与实际运行账户不一致（服务账户/域账户），`/grant:r` 可能授错人或失败 → 只 warn，不会锁死；
   - 若在非管理员上下文，`/inheritance:r` 仍可（改自己拥有的文件 ACL 一般允许），失败则保持原样；
   - 极端情况：`writeFileSync` 成功但两次 icacls 都失败 ⇒ 退回现状（继承 ACL），并在日志留 warn —— 不回归更差。
