## 2. 各条细节（只写"实测到了什么"，不复述读码）

### ① 明文泄漏 — SECURE

- 写 canary 后**关库**再扫，避免"文件还在 sqlite 页缓存里没落盘"的假阴性。
- `journal_mode = delete` ⇒ 不存在 `-wal`/`-shm`（**任务书点名要查的那类缺陷不成立**）。
- 扫描面：库本体字节、3 个边车路径、仓库内 **121 个 `*.log`**、`tmp/` 400 个文件、`bots/` 400 个文件、`evidence/vault-attack/` 下除 `logs/`、`tmp/` 外全部文件 ⇒ **0 命中**。
- 对外结构：`listSecrets()` 只回 `name/hint/updatedAt/updatedBy`（`****503a (34 字)`），`status()` 只回计数。
- 唯一拿到明文的地方是**进程环境变量**——这正是设计（见 ⑧）。

> **诚实记录（本轮踩到的自证陷阱）**：第一版探针把完整 canary 打进 stdout，而 stdout 被重定向到 `logs/`，而探针又递归扫自己的目录 ⇒ **自己命中自己**，误报 VULNERABLE（`logs/t-vault-1-plaintext.log` 里那一版）。已修：只打 canary 前缀 + 扫描时排除 `logs/`、`tmp/`。**这类"证据污染证据"的坑，安全测试里最常见。**

### ②/③ 认证加密与 AAD — SECURE

- 7 个篡改用例全部 `VAULT_DECRYPT_FAILED`，**没有一个返回内容**（不是"返回垃圾"）。
- AAD 实测：把 `OPENAI_API_KEY` 的 `(nonce,ct,tag)` 整行搬到 `ANTHROPIC_API_KEY` 名下（先用随机 nonce 腾位避开 UNIQUE），`getSecret('ANTHROPIC_API_KEY')` 抛错 ⇒ 跨行挪用被拦。
- 附带发现（防守更好）：`secrets.nonce UNIQUE` 让"简单互换"在**写入阶段**就失败。

### ④ nonce — SECURE

- 用**审计触发器**（只存在于探针的临时库，不是改产品代码）留档每次写入的 nonce，含被 UPSERT 覆盖掉的历史值 ⇒ 54 个全唯一、长度 12B、相邻汉明距离无一异常偏低（不像计数器）。

### ⑤ KDF — SECURE

- 错口令与"库被改坏"**同错误码**（`VAULT_BAD_PASSPHRASE`），REST 上都是 401 ⇒ 不构成口令 oracle。
- 计时：正确 48.4ms / 错误 46.9ms（scrypt 都跑完才判），没有"提前返回"。
- salt 16B、两次 init 不同、持久化后可重开。
- **KDF 降级不可行**：把库里的 `n` 改成 1024、`r/p` 改成 1 之后，`unlock` 仍成功 ⇒ 说明派生用的是**代码常量**而不是库内值（若读库内值，这条会变成"攻击者可把 32768 降成 1024 再爆破"）。

### ⑥ 注入 — SECURE

- 10 个恶意名字全部 `VAULT_BAD_NAME`；值里的 `'; DROP TABLE secrets; --` 原样存取、表存活。
- 静态：7 条 `prepare()` 里**模板插值 0 条**，5 条带 `?`（其余是不带参的 DDL / `COUNT(*)`）。

### ⑦ 未解锁绕过 — 门禁 SECURE / env 旁路 WEAK

- 库层 5 条路径全 `VAULT_LOCKED`；`tryGetSecret` 锁定时返回 `null`（不偷偷开库）。
- REST 锁定态：`items/lock` 的 GET/PUT/DELETE 全 **409**，`status` 是唯一 200；**无 token 全 401**。
- `init` 即解锁 → `PUT/GET` 可用且**不回明文**；`lock` 之后立刻回到 409（含注入环境变量的撤回）。
- **env 旁路实测成立**：带 `MC_VAULT_PASSPHRASE` 起进程后**不调 unlock** 就能 `GET /api/vault/items` 拿到 200 ⇒ WEAK（但文档已明示，见 §3 W-1）。

### ⑧ 进程边界 — SECURE

- 注入前后 `tmp/ bots/ logs/` **新文件数 0**（没有"写临时文件再读"这种偷懒）。
- 子进程确实从 env 拿到明文（`长度|前3位 = 30|sk-`），**argv 里没有**（`args.push` 只有 name/count/port/…）。
- spawn 的 env 表达式是 `{ ...process.env, MINDSERVER_PID }` —— 只加一个 pid，不拼键值。
- 静态扫 3 个文件 4 类"把 env/明文打进日志"的模式：**0 命中**。`secrets_vault.js` 的日志只打名字/条数/错误码。

### ⑨ ACL — SECURE

`icacls` 实测：只剩 `Administrators(F)`、`SYSTEM(F)`、`当前用户(F)`；**`Authenticated Users` 已不在**。唯一的继承项是 `Mandatory Label\Low Mandatory Level:(I)(NW)`（完整性标签，来自本机沙箱，不是访问授权）。

### ⑩ unlock 限流 — 抗爆破 SECURE / 可用性 WEAK

见下节 W-2。

## 3. 两条 WEAK 的详细评估

### W-1 `MC_VAULT_PASSPHRASE` 等于"免解锁"（已文档化）

**实测**：`带 MC_VAULT_PASSPHRASE 启动后 GET items → 200（读到了！）`

**风险**：口令从"只在人脑里"降级为"在这个进程的环境里"。同机同账户的任何进程（Process Explorer / 任务管理器导出 / 某些 `/proc` 视图）都能读到，等于**绕过了整个 unlock 门**。另外它让"面板上锁"变成假锁：上锁只清 KEK，重启后 env 又自动解锁。

**是否算缺陷**：**不算 VULNERABLE** —— 文档 `docs/vault-保管库.md:80` 原文已写明"⚠️ 这是便利选项，不是安全选项……把它等同于『把口令写在启动脚本里』"。这是**明确的设计取舍**，不是遗漏。

**最小建议**（不改行为，只减少误用）：
1. `/api/vault/status` 增一个字段 `unlockSource: 'manual' | 'env'`，面板在 env 来源时把"上锁"按钮置灰并提示"当前由 MC_VAULT_PASSPHRASE 自动解锁，上锁重启后会失效"。
2. 文档 §"上锁"处补一句同样的话。

### W-2 unlock 限流的可用性副作用（**本轮唯一真缺口**）

**实测**：第 1–5 次错口令 → `401`；第 6 次起 → `429`；**同一窗口内用正确口令 → `429`**。

**根因**（`mindserver.js`）：`unlockRateLimited()` 是**全局计数**（不按 IP/连接分桶），且在**校验口令之前**就返回：一旦 `count >= 5`，正确的口令也进不去；计数只在 `now - firstAt > 60s` 时重置（成功解锁**不会**清零）。

**影响**：持有握手 token 的攻击者（token 会出现在日志/截图/共享终端里——这正是限流存在的理由）每 60 秒故意打错一次，即可让管理员**永久**无法解锁。机密性不受影响（不泄漏任何东西），但可用性可被长期剥夺；而且 `lock` 之后 agent 拿不到新 key，"面板重启 agent"会静默退回 keys.json。

**最小修复**（3 行内，不动密码学）：
```js
// 1) 正确的口令必须能通过：把"限流判定"放到"口令校验之后"，或在成功分支里清零计数
//    最省事：成功时 UNLOCK_FAILS.count = 0; UNLOCK_FAILS.firstAt = 0;
// 2) 若要保留 DoS 防护：按来源分桶（socket 的 remoteAddress），别用全局单例
```
优先级：**低**（需要 token，属"本机可信客户端"内部威胁），但既然限流本身就是为"token 泄漏"准备的，这个副作用值得一并修掉。

## 4. 我**没有**当成漏洞的东西（避免凑数）

| 现象 | 为什么不算 |
|---|---|
| 能解密的系统必然能把明文交给调用方（`exportAllSecrets` / `getSecret`） | 这是功能本身；边界在"谁能调"（已由解锁门 + 锁定态 409 守住） |
| 明文进 agent 子进程的环境变量 | 设计如此且文档写明可见性；落地只走 env、无文件、无 argv、无日志（⑧ 已实测） |
| `MC_VAULT_PASSPHRASE` 自动解锁 | 文档明确的便利选项（W-1，按 WEAK 记但不要求修） |
| `tryGetSecret` 锁定时返回 null（不抛） | 给 `keys.js` 做优先级回落，语义是"没有就用下一个来源"，不是"绕过锁" |
| `GET /status` 在锁定态仍 200 并回 `count` | 面板要显示"锁着，里面有几项"；不含任何 name/value |
