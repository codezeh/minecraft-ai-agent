## 1. 扫描（脚本，不是肉眼）

`tools/scan_tmp_isolation.mjs`（本次新增，可复用/可挂 CI）

判据是**两条同时成立**：① 出现固定 tmp 路径（字符串字面量 `tmp/xxx` 或 `join('tmp','xxx')`）；
② 同文件里有 `rmSync(` / `rm -rf`。任一隔离手段（`mkdtempSync` / `os.tmpdir()` / `process.pid` / `randomUUID`）出现即视为已隔离。

★ **扫描器自己先被验过**：本仓因为「注释里的样本被当成真命中」「正则被控制字符弄坏」
已经栽过好几次，所以它**先剥注释再匹配**（带引号状态机，不认识 `//` 是注释还是字符串里的一部分就会错），
并自带 `--selftest`：

```
$ node tools/scan_tmp_isolation.mjs --selftest
✓ 自检通过：注释里的样本被忽略、代码里的真样本 3 处全中、字符串里的 // 没误判
```

自检夹具里同时放了：**行注释里的假样本**、**块注释里的假样本**、**代码里的两个真样本**、
以及一行 `'a//b' + 'tmp/in-string'`（验证"字符串里的 `//` 不许把后面的代码吃掉"）。

## 5. 一件必须说清的事：**清理在 Windows 上经常删不掉**

验收要求"改完必须 finally 清理，且清理失败不许让测试变红"——这两条都做到了
（`try { rmSync(DIR, ...) } catch {}`），但真实现状是：

```
$ # 直接验证：刚用完的 sqlite 目录能否立刻删
rm 失败： EPERM, Permission denied
```

**根因**：`node:sqlite` 的句柄要等**进程退出**才关闭，而 `rmSync` 跑在退出之前 ⇒ EPERM。
所以每个测试会在 `%TEMP%` 留一个目录，**进程退出后立刻可删**。

我**没有**把这件事藏起来，而是让它可观测 —— 扫描器加了 `--leftovers`：

```
$ node tools/scan_tmp_isolation.mjs --leftovers
残留测试目录：79 个，合计 0 KB（在 C:\Users\zeh\AppData\Local\Temp）
  ★ 说明：清理这一步在 Windows 上常因 node:sqlite 句柄未关而 EPERM；
    这些目录在**进程退出后**即可删除，体积很小，不是仓库内容。
  · C:\Users\zeh\AppData\Local\Temp\board-b3-test-69wSTD
  …
  （加 --purge 可尝试现在删除）
  ⚠ --purge **只在没有测试在跑时用**：它不区分"正在被并发运行的测试所用"的目录。

$ node tools/scan_tmp_isolation.mjs --leftovers --purge
  --purge：已删除 79/79 个
$ node tools/scan_tmp_isolation.mjs --leftovers
残留测试目录：0 个（干净）
```

★ 一个**值得说清的细节**：残留其实是**空目录**、合计 **0 KB** ——
`rmSync` 把里面的文件删掉了，只在"删目录本身"这一步 EPERM（句柄还在）。
所以它不是"越跑越占空间"的问题，而是"临时目录里多出一些空壳子"，
`--purge` 79/79 一次清光（实测）。

把它放在**系统临时目录**而不是仓库内，也是这次改造的附带好处：以前那个固定目录在 `mindcraft/tmp/` 里，
现在即便残留也不会脏工作区（`git status` 干净）。

**若要"真清理"**，有两条路（本轮没做，因为都要碰测试内部，超出"最小改动"）：
1. 各测试在自己末尾 `db.close()`（`openBoard` 返回句柄，测试里都持有 `db`）；
2. 由 `unit_all` 在**子进程退出后**扫描删除（子进程已退出 ⇒ 句柄已关 ⇒ 能删）。
