## 四、裁决：`server.properties` 不入库

**事实**：`server/server.properties` 含 `enable-rcon=true`、`rcon.port=25575`、`rcon.password=<32 位，大小写+数字+符号全含>`。

**裁决：排除（已写入 `.gitignore`）。理由：

1. **这是真口令，不是占位符**。32 位、四类字符齐全，说明是刻意生成的高熵口令。git 历史是**只追加**的：一旦提交，删文件、`git rm` 都抹不掉对象，只能 `filter-repo` 重写历史。为一个 1.5 KB 的配置文件引入「永久性历史污染」，收益和风险不成比例。
2. **「本机使用」不是长期保证**。本仓库现在没有远端，但仓库一旦被拷贝、上传、或以后加了远端，「当时是单机」这个前提就失效了——而泄漏是在那一刻才暴露的，届时已经晚了。把秘密挡在入库这一步，成本是 0；事后补救成本极高。
3. **回滚损失可控**。这不是唯一副本：同目录下已有 `server.properties.bak-2026-11-02030312`，`server-test/server.properties` 是可直接对照的第二份，Paper 缺失时会重新生成默认值。真正易漂移、且**值得回滚**的项（`paper-global.yml`、`paper-world-defaults.yml`、`spigot.yml`、`bukkit.yml`、`ops.json`、`whitelist.json`）**都已入库**——Rcon 之外的配置漂移仍有版本可查。

**这与报告路线图的字面表述（"`git log` 能看到 … 与 `server.properties` 的第一次提交"）不一致，是有意偏离**，理由如上。若队长判断仍要纳入，一行即可（本机操作）：

```bash
git add -f server/server.properties     # -f 覆盖 .gitignore
```

但**建议先轮换 `rcon.password`**，或把口令拆到不入库的 `server.properties.local` 里——否则上面的理由 1、2 依旧成立。

**关于「§3 假绿」的本次复核结论（静态，可复现）**：

- `mindcraft/tools/preflight.mjs:183` 的两个正则各混入一个 `0x08`（退格）字节作前缀：
  `/fail\(\s*'([A-Z_]+)'/g`、`/code:\s*'([A-Z_]+)'/g`。要求字面退格才匹配 ⇒ **永不命中** ⇒ `used2` 恒空 ⇒ `missing2` 恒空 ⇒ 恒打印 `✓ 错误码审计通过`。
- `:933` 另有一处 `0x08`，但只坏了三条备选中的一条，另两条完好，故那条常驻红灯**不是**它造成的（与报告第 26 条的实测一致）。
- `:192-193` 新加的 `t99` 护栏只挡「扫到 **0 个** src 文件」这一种空转，**挡不住「正则永不匹配」**——所以 §3 仍是假绿。
- 复核命令：`grep -c $'\x08' mindcraft/tools/preflight.mjs` → `2`；`grep -n $'\x08' ...` → 第 183、933 行。

**为什么这条链路没复跑**：`npx` 在本沙箱 EPERM（报告 t11 已实测），且跑 preflight / unit_all 会在 `mindcraft/` 工作树内产生产物，与「禁止改动 mindcraft 内任何文件、其 `status` 必须仍干净」直接冲突。**动 `mindcraft/` 的验证属于后续任务的职责**，不在 T01 范围内。
