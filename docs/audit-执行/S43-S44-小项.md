## S43-① `bot.on('error')` 注册了两处 → 同一次错误打两遍

**改前**（按符号名定位，行号已因本轮改动位移）：
- `async start()` 里一处：能区分致命与否（`Duplicate` / `ECONNREFUSED` → `onDisconnect`），否则 `log(... [LoginGuard] Connection Error ...)`；
- `startEvents()` 里第二处：只有 `console.error('Error event!', err)`。

两处都在**同一个 bot 对象**上，`startEvents()` 在 spawn 时被调一次（全仓唯一调用点），
所以任意一次 `error` 事件都会走**两条**路径 → 日志翻倍，且「纯打印」那份会把
「致命判定」那份的输出淹掉。

**改后**：只留一处（在 `start()`），并把被删那份的价值并进来——
`console.error(`[${name}] bot error:`, err)` 打出 err 本体（带堆栈），
然后仍按 `fatal` 分流。`startEvents()` 里只留一行注释指向唯一注册处。

## S43-② 调用点裸调 `_setupEventHandlers` → unhandled rejection + 顺序竞争

**报告原文说「`_setupEventHandlers` 是 async 但没有 await」——这一句不准确**，实测该方法是**真 async**：

```
$ grep -c await 该函数体内   → 3 处
  await handleEnglishTranslation(message)
  await this.self_prompter.handleLoad(...)
  await this.handleMessage('system', init_message, 2)
```
（也是因此 eslint 的 `require-await` **没有**点名它。）

真正的问题在**调用点**（`spawn` 处理器里）：`this._setupEventHandlers(save_data, init_message);` 是
**fire-and-forget**。后果两条，都比"少打一行日志"严重：
1. 它内部任何一处抛错 → 变成 **unhandled rejection**。外层那个 `try { ... } catch (error) { ... process.exit(0) }`
   **抓不到 promise 的 reject**，Node 只打一行 warning，进程继续在「事件处理器没装好」的状态下跑；
2. `startEvents()` 与 `task.initBotTask()` / `setAgentGoal()` 会和它**并发**（顺序不确定）。

**改后**：`await this._setupEventHandlers(save_data, init_message);`
⇒ 异常落进外层 `catch (error)`（那里本来就有 `console.error('Error in spawn event:', error)` + 干净退出）。

## S44 `selectAPI` 在 `profile.model` 缺省时崩

**改前**（真实复跑，把 HEAD 版本放回原位跑一次再恢复）：
```
改前 {"api":"deepseek"}                       → THROW TypeError: Cannot read properties of undefined (reading 'replace')
改前 {}                                       → THROW TypeError: Cannot read properties of undefined (reading 'includes')
改前 {"api":"deepseek","model":"deepseek-chat"} → {"api":"deepseek","model":"deepseek-chat"}   （正常）
```
注意：报告说崩在 `.includes`，那只在**连 api 都没写**时成立；
报告点名的 `{"api":"deepseek"}`（**合法**写法，用该 api 的默认模型）实际崩在 **`.replace`**（`:73`）。
同一类缺陷、两个崩点，都修。

**改后**：进入函数先把 `profile.model` 归一成字符串——
非字符串（undefined / null / 数字 / 对象）统一置 `''` 并打一行 debug（非字符串时打 warn）。
空串让 `startsWith`/`includes` 全为假、`replace` 原样返回，末尾 `model_name === "" ? null : …`
把 model 置 `null` ⇒ 走供应商默认模型。三个真实场景：
```
改后 {"api":"deepseek"}                       → {"api":"deepseek","model":null}   → createModel 得到 DeepSeek(model_name=null) → 供应商用 deepseek-chat
改后 {}                                       → THROW Error: Unknown model:      （明确报错，不再是 TypeError）
改后 {"api":"nope"}                           → THROW Error: Unknown api:        （非法 api 仍明确报错，没被空值保护吞掉）
改后 {"model":"local/llama3"}                 → {"api":"ollama","model":"llama3"}（老的 local→ollama 兼容没受影响）
```
