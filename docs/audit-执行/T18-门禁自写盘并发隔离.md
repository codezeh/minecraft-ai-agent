## 一、病灶（board 在 T17 查出，我复核确认）

```
tools/preflight.mjs:171   name: 'preflight_tmp',                       ← 固定 bot 名
tools/preflight.mjs:1272  const { rmSync } = await import('fs');
tools/preflight.mjs:1273  try { rmSync(join(ROOT, '../../bots/preflight_tmp'), …) } catch {}
```

`history.load+save` 这条冒烟测试用**固定** `name: 'preflight_tmp'`，而 `History` 会把
`botsRootOf()/${name}/…` 落盘 → 目录固定落在 **`bots/preflight_tmp/`**（所有 preflight 进程共用）；
文件末尾那句 `rmSync` 再把这个**共用**目录删掉。

**两个进程同时跑 preflight ⇒ 先跑完的那个删掉另一个正在用的目录。**

这正是 T15/T17 在**测试层**修掉的同一病灶，只是它在**门禁层**。
而门禁层的假象比测试层更毒：它让所有人学会"重跑一下就好"，然后真正的回归被重跑掉。

## 二、复现情况（如实记录：**机制确证，但当前不产生红色失败**）

### 2.1 直接并发跑，exit code 上看不出来

```
$ node tmp/t18_repro.cjs 3          # 两进程同时跑 preflight，×3 轮
第 1 轮  ✓ A=0 B=0（未观察到互删）
第 2 轮  ✓ A=0 B=0
第 3 轮  ✓ A=0 B=0
=== 3 轮中 0 轮出现异常 ===
```

**如实说明**：`exit code` 层面**复现不出来**。原因是 `History` 的 `load()` 容错性很强
（`history.js:36` `mkdirSync(…, {recursive:true})` 会自愈），且**没有任何断言依赖那个文件持久存在**。
所以互删不会变成 `✗`，而是被冒烟测试的兜底分支降级成 `~ 非致命`（T02 定的判据只对
`ReferenceError` / 缺模块判失败）——**表现为"静默漏测"，不是"假红"**。

> 这一点必须写清：**不能因为"跑不出红"就说缺陷不存在**。
> 也**不能为了凑一个红色证据去伪造断言**（任务明确要求）。

### 2.2 从文件系统层面确证"互删"真的发生

用 5ms 采样器记录 `bots/preflight_tmp` 的出现/消失，并与两个进程的起止时刻求交：

```
$ node tmp/t18_repro4.cjs
时间轴（ms，相对同时启动）：
  A: 0 → 3586  exit=0
  B: 11 → 3592  exit=0
     15ms  preflight_tmp absent
   1900ms  preflight_tmp present
   3563ms  preflight_tmp absent          ← 目录被删

目录在 3563ms 被删除；此刻仍在运行的进程: A+B
⇒ **确证互删**：一方收尾删掉了另一方正在使用的目录。
```

**决定性证据**：目录在 **3563ms** 被删，而 **A（3586ms 结束）与 B（3592ms 结束）此刻都还在跑**。
这不是"窗口太窄"的推测 —— 是有时间戳的实测重叠。

### 2.3 修复后同一探针的结果

```

  A: 0 → 3290  exit=0
```

## 四、改法与理由：**用 `mkdtempSync` + `MC_BOTS_ROOT`，不是加 pid 后缀**

### 4.1 先确认有没有 board 那种"不能搬位置"的约束

任务提醒：board 的 `tools/.tmp_mut` 变异体是**按目录深度改写相对 import** 的，不能随便搬。

**这里没有那个约束**，实测确认：
- `History` 的落盘路径完全由 `botsRootOf()/${name}/…` 拼成（`history.js:33/36/75`）；
- `botsRootOf()` 认 `MC_BOTS_ROOT`（`bot_paths.js:41-45`，T17 已改造）；
- 所以临时目录**想放哪就放哪**，不涉及任何相对 import 的深度改写。

### 4.2 为什么选 mkdtemp 而不是 `-${process.pid}`

| 方案 | 隔离性 | 残留 | 评价 |
| --- | --- | --- | --- |
| `bots/preflight_tmp_${pid}` | 进程间唯一 | 进程被 kill 时**残留**在 `bots/` 里 | 够用，但仍在仓库内留垃圾；且 pid 会复用，久跑可能撞上旧残留 |
| **`mkdtempSync(os.tmpdir())`（采用）** | 进程间唯一 + 每次调用唯一 | 落在系统临时目录，进程被 kill 也只是系统临时文件，**不污染仓库** | **更彻底**：从"给共享路径加后缀"变成"根本没有共享路径" |

选 mkdtemp 的核心理由：**pid 后缀只是把冲突概率降低，而 mkdtemp 是把冲突变成不可能** ——
它每次调用都拿到一个全新的、操作系统保证唯一的目录。而且顺带解决了"进程被 kill 后仓库里留垃圾"。

### 4.3 具体改法

```js
['history.load+save', async () => {
    const m = await import(pathToFileURL(join(ROOT, 'history.js')).href);
    const { mkdtempSync, rmSync } = await import('node:fs');
    const { tmpdir } = await import('node:os');
    const root = mkdtempSync(join(tmpdir(), 'mc-preflight-'));   // ← 本次调用独占
    const prevRoot = process.env.MC_BOTS_ROOT;
    process.env.MC_BOTS_ROOT = root;                             // ← 把 History 的落盘重定向出去
    try {
        const h = new m.History({ name: 'preflight_tmp', … });
        h.load();
    } finally {
        if (prevRoot === undefined) delete process.env.MC_BOTS_ROOT;   // ← 恢复，不泄漏给后续阶段
        else process.env.MC_BOTS_ROOT = prevRoot;
        try { rmSync(root, { recursive: true, force: true }); } catch { }   // ← 只删自己的
    }
}],
```

同时**删除**文件末尾那句全局 `rmSync(bots/preflight_tmp)`，并留下注释说明为什么不能留
（留着就等于把"互删"重新装回去）。

**三个设计细节值得说明**：

1. **`try/finally` 而不是裸调用**：`h.load()` 抛错时也必须恢复环境变量 + 删临时目录，
   否则一次失败会污染后续阶段 / 留垃圾。
2. **恢复 `MC_BOTS_ROOT`**（而不是一直设着）：别的层也可能调 `botsRootOf()`，
   把冒烟测试的临时根泄漏出去会让它们写到一个即将被删的目录里。
3. **`name` 保留 `'preflight_tmp'` 不变**：因为它现在只在**本次独占的 root 内部**使用，
   不再需要唯一化 —— 少改一处就少一处漂移。

## 六、边界与残留

1. **本次只修「门禁自写盘」这一类。** 测试层的固定路径（`bots/<agent>/…` 共用）归 T17，
   已在 `a4e244a` 落地；本补钉不碰。

   删固定路径正是要治的病。需要的话由人手动清一次（`rm -rf bots/preflight_tmp`）。
3. **复现脚本放在 `tmp/`**（`tmp/t18_repro.cjs` / `t18_repro4.cjs`），按 T90 §7.7 的纪律
   它们**不是可交付证据**（`tmp/` 被 gitignore）。本文档已把关键输出逐字抄录进来，
   关键结论另有常驻守护：`tools/scan_tmp_isolation.mjs --check` 会持续监控这一类。
