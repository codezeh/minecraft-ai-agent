## 二、改了什么

### 第 10 条
- `skills.js`：`import { ok } from './contract.js'`。
- `step_runner.js`：循环结束前加**收窄**判据 —— `failed.length && doneSteps === 0` 时
  `return fail(first.code, '全部 N 步都失败了（一条也没做成）…')`。
  只要有过一步成功，仍按 `ok` 返回（部分成功是真实结果，交调用方看 `failed` 数组）。
- **附带**：`tillAndSow` 作弊分支里两句 `placeBlock(...)` 没有 `await`（就是报告 39 条里属于本文件的 2 条浮空 promise）→ 改为逐句 `await` 并如实报 `PLACE_FAILED`。

### 第 33 条
- `goToGoal` 的 `Promise.race` 增第三支 `interruptPoll`：每 200ms 查 `bot.interrupt_code`，命中 `pathfinder.stop()` 并 reject（`err.code='INTERRUPTED'`）；`finally` 里 `clearInterval`。
- `useDoor`：`while (bot.pathfinder.isMoving() && !bot.interrupt_code)`
- `goToBed`：`while (bot.isSleeping && !bot.interrupt_code)`

### 第 13 条
- `surveyArea(bot, radius = 24, …)`（默认 64 → 24）
- `terrain3d.scanSphere` 入口硬夹：`const SCAN_MAX_RADIUS = 32; const r = Math.min(SCAN_MAX_RADIUS, Math.max(2, Math.floor(radius)))`
- `map_query.js`：`const scanR = Math.min(32, Math.max(16, spanBlocks))`（日志里也报 scanR，不再报未夹的值）

### 第 9 条
- **① owner 每次唯一**：`nav_core` 新增 `resolveNavOwner(bot)` —— 有任务单用 jobId；否则 `adhoc:${++_adhocSeq}`。
- **嵌套 vs 并发**（重要设计）：最初我用 `WeakMap<bot, …>` 判断"是否已在导航段内"，**测试第 ⑤ 条当场把它打红**——同一个 bot 上两个**并发**调用会命中同一个 key，被误判成"嵌套"而放行，闸又白做了。改成 `AsyncLocalStorage`：store 沿 await 链传递，兄弟调用各自独立。
- **② 17 处直驱点包 `withNav`**：`flow_collect_plan`(3)、`flow_collect`(1)、`flow_follow`(4+2 处 hopTo)、`flow_platform`(1)、`atom_tunnel`(3)、`tool_prep`(1)、`skills.js`(`gotoWithTimeout` + `goToGoal` 两个主驱动点)。拿不到闸时**如实返回 `BLOCKED`**（ActionResult 场景）或 `false`（boolean 场景），不假装成功。只包 `withNav`，**没有改 atom_* 的判定语义**。
- **③ 止血**：`restoreGoalModes` 在 `bot.pathfinder.isMoving()` 为真时**延后恢复**（200ms 轮询，最多等 5s 兜底，`timer.unref()` 不吊住进程），避免模式一醒就去改 goal。

### E1
`flow_follow.follow` 同时认 `deadlineMs`（优先，注册表用的就是这个）与 `timeoutMs`（老调用点），
超时改为 `fail('TIMEOUT', …)`（原来 `ok({reason:'timeout'})`）。

### E2
`executor` digdown 增 `blockedBy` 记录；收尾时 `dug === 0 && 当前 y > targetY` → `{ok:false, code:'BLOCKED', …}`。

## 六、给下游 / 需要知道的行为变化

1. **`withNav` 拿不到闸时会如实失败**：直驱点现在可能返回 `BLOCKED`（ActionResult 场景）或 `false`（boolean 场景）。
   这是有意的——比"硬抢 goal 把别人的导航弄坏"好。若上层只想"尽力而为"，按 `retryable: true` 重试即可。
2. **`AsyncLocalStorage` 是新依赖**（`node:async_hooks`）：只在 Node 侧生效。`nav_core` 是 bot 端模块，不进 web 包，不违反 web 侧约束。
3. **`restoreGoalModes` 不再同步**：路径还在动时最多延后 5 秒再放模式；`unref()` 保证不吊住进程。
   如果将来有调用点依赖"函数返回即模式已恢复"，要改成等待。
4. **`runSteps` 语义收紧**：全部失败且 `doneSteps===0` → `ok:false`。此前依赖"ok:true 但 failed 非空"的调用方需要看 `code`。
   `digTunnel` 因此也首次具备"真失败"的返回（原来它要么抛 ReferenceError、要么假成功）。
5. **`follow()` 超时改成 `TIMEOUT` 失败码**：原来返回 `ok({reason:'timeout'})`。注册表的 `deadlineMs` 现在真的生效了。
6. **`surveyArea` 默认 24**：模型拿到的图与统计仍是 9×9 降采样，只是扫描范围小了；需要更大范围请显式传，但**上限 32**。
7. **E2 的 `BLOCKED`**：`digdown` 在"正下方是液体/读不到方块且一格没降"时返回失败。上层若原先靠"ok 且 dug=0"判断，需要改用 `code`。
