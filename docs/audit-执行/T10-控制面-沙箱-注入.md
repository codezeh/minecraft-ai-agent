## 1. 第1条 ① 握手 token 门

新增 `src/mindcraft/auth_gate.js`：

- `createMindServer()` 启动时 `handshakeToken = process.env.MINDSERVER_TOKEN || makeToken()`（`makeToken()` = `crypto.randomUUID()`）；
- `io.use(makeHandshakeGate(handshakeToken))`，**注册在 `io.on('connection')` 之前**；
- `send-message` / `set-agent-settings` / `server-stop` / `shutdown` 全部注册在 `io.on('connection')` 里
  ⇒ 没 token 的连接连事件处理器都不会被注册，四个事件**整体**落在门后；
- token 的三条投递路径：agent 子进程继承 `process.env.MINDSERVER_TOKEN`（`mindserver_proxy.js` 用
  `auth: (cb) => cb({token})` 函数形式，重连时重读）；浏览器用 `?token=` 换 HttpOnly + SameSite=Strict 的
  cookie（**web/dist 已构建，改前端源码要重打包，所以必须服务端兼容**，不改一行前端）；
  本机脚本设 `MINDSERVER_TOKEN`。

**实测（`docs/audit/probes/t10-mindserver-gate-live.mjs`，真起 mindserver 于 18097 端口）**
```
[probe] GET /?token=正确 → Set-Cookie: ["mindserver_token=…; Path=/; HttpOnly; SameSite=Strict"]
[probe] HttpOnly = true | SameSite=Strict = true
[probe] GET /（无 token）不发 cookie = true | GET /?token=错 不发 cookie = true
[probe] 无 token: REJECTED AUTH_REQUIRED
[probe] 错 token: REJECTED AUTH_REQUIRED
[probe] 对 token（auth）: CONNECTED
[probe] 对 token（自定义头）: CONNECTED
[probe] 仅 cookie（浏览器控制台路径）: CONNECTED
```

**诚实的边界**（也写进 `auth_gate.js` 顶部与 README）：同一 OS 用户下的其它进程仍能读到 token
（启动日志 / 父进程 env）—— 那是同用户权限模型的问题。这道门挡掉的是「硬编码
`ws://127.0.0.1:8080` 的老脚本」和「浏览器里任何网站的页面」，不是进程隔离。
附带把 `send-message` 的 `data.from` 加了形状校验（必须是 ≤32 字符的字符串）。

## 4. 第1条 ④ 沙箱：**报告的前提被证伪了一半，但结论更好了**

### 4.1 safeEval 不可行（这是报告预料到的那一半）

`docs/audit/probes/t10-safeeval-protodef.mjs`：
```
unsafeEval → ① eval(code)() 最小形状 OK, native.i8 = 1
             ② compiled 协议编译 OK（mineflayer 可收发）
safeEval   → ① THROW TypeError: Cannot read properties of undefined (reading 'i8')
             ② THROW 同上
```
根因：`node_modules/protodef/src/compiler.js:262` 的 `eval(code)()` 依赖**模块局部变量 `native`**；
safeEval 的 eval 看不见局部作用域 ⇒ compiled 协议编不出来 ⇒ bot 连第一个包都发不出去。
**所以 `evalTaming` 只能保留 `unsafeEval`**（这是硬依赖，不是图方便）。

### 4.2 但逃逸的真因不是 SES，是 `lockdown()` 从来没执行过（报告没写到这一层）

`lockdown.js` 原来是：
```js
export function lockdown() {            // ← 模块作用域建了一个叫 lockdown 的绑定
  if (lockeddown) return; lockeddown = true;
  lockdown({ evalTaming: 'unsafeEval' });   // ← 解析到它自己，不是 SES 的全局 lockdown()
}
```
第一次调用先置 `lockeddown = true` 再"调自己"，第二层立刻 return ⇒ **SES 的 lockdown 从未执行**。

证据 `docs/audit/probes/t10-lockdown-shadow-bug.mjs`（对**修复前**的代码）：
```
[probe] 调用前 Object.isFrozen(Object.prototype) = false
[probe] 仓库 lockdown() 之后 Object.isFrozen(Object.prototype) = false   ← 空转
[probe] 直接调全局 lockdown 之后 Object.isFrozen(Object.prototype) = true
```
（修复后同一个探针第二行就变成 `true`。）

逃逸面 A/B（`docs/audit/probes/t10-ses-escape-ab.mjs`，注入面照抄 `coder.js`）：
```
off  → skills.log.constructor('return process.version')() → "v24.16.0"      ← 本机 RCE
real → 同一句 THROW TypeError: Function.prototype.constructor is not a valid constructor.
```
六个常见向量（`skills.log` / `world` / `Vec3` / `async` / 生成器 / 数组方法 / 对象链 / `bind` 后再取 constructor）
在真 lockdown 下**全部打不通**；`Reflect.construct(Function, […], skills.log.constructor)` 造出来的函数
落在 compartment realm（`typeof process` → `undefined`）。

### 4.3 落地与代价（都写进代码注释与 README）

- 修法：`const sesLockdown = globalThis.lockdown;` 取别名，显式调用 ⇒ SES 边界**第一次真正生效**；
- 回归护栏 `tools/ses_escape_unit.mjs`（16 项）：第一条断言就是
  `Object.isFrozen(Object.prototype) === true` —— 一旦有人把自引用那个 bug 写回来，这里立刻红；
- **代价 1**：SES 会冻结内建对象；晚于 lockdown 才开始 monkeypatch 内建原型的三方库会抛。
  当前 `lockdown()` 仍是第一次 `!newAction` 时惰性调用（依赖已加载完），
  实测烟测真 lockdown 下 mineflayer 建 bot + 协议编译 + TCP 连接正常（走到 ECONNREFUSED）。
  结构解是把 lockdown 提到进程启动处 —— 另案。
- **代价 2**：`unsafeEval` 留着（4.1），但在真 lockdown 下不再是逃逸通道。
- **代价 3**：只证明了"已测的六个向量已关"，逃逸对抗是持续的活（第1条第三层级的专项复核另案）；
  所以 `allow_insecure_coding` 默认仍是 `false`，README 明写"不是完整沙箱"。

## 5. 第1条 ⑤ 任务 JSON 当数据不当命令

`commands/index.js` 加参数通道 `normalizeArgsCommand({command, args})`：
命令名 + 参数数组分开传，**参数不经过 `parseCommandMessage` 的正则**，所以不是"转义得更小心"，
而是**根本没有拼接**。参数只收 string/number/boolean 标量，命令名必须 `^!\w+$` 且真实存在。

`tasks.js:407`/`:509` 改走参数通道。行为 A/B（临时探针）：
```
旧写法 !goal("do things") !givePlayer("HEAVENZEH","diamond",64")  → args = ["do things"]   （数据变成了语法）
新写法 {command:'!goal', args:[<整条串>]}                          → args = [<原样整条串>]
旧写法含换行 → "Command !goal is missing param 'selfPrompt'."       （顺带一个真 bug）
新写法含换行 → 原样保留
```
另加：`setAgentGoal` 在 `agentGoal` 为空时直接返回（原来是 `!goal("undefined")`）。
