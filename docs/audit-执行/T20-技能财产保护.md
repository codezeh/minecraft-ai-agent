## 二、改了什么

### 第21条 攻击闸（skills.js）
- `import { isAttackable } from './act_attack.js'`（无循环依赖：`act_attack.js` 只 import `contract.js` + `atom_input_mouse.js`）。
- `attackNearest`：`find(entity => entity.name === mobType && isAttackable(entity))` —— **find 之前过滤**，找不到就报"没找到"，永远不进入攻击。
- `attackEntity`：开头 `if (!isAttackable(entity)) { log REFUSED 文案; log FAILED; return false; }`，位置在 `equipHighestAttack()` / `bot.pvp.attack()` **之前** —— 拒绝不先换武器、不先挥击。
- 证据（`tools/skills_attack_guard_unit.mjs`，7 用例）：玩家/盔甲架/掉落物 → 返回 false 且 `swings=0 pvp=0 equips=0`；僵尸对照组仍挥击 1 次。

### 第22条 giveToPlayer
`if (got && got.ok) return true;`（+ 注释说明"waitUntil 返回对象"）。

### 第28条 useToolOn
`... && bot.game.gameMode !== 'creative'`。

### 第29条 斜杠命令收口
- `breakBlockAt` 作弊分支：`await command(bot, 'setblock', [x, y, z, 'air'], { cheat: true })`，并检查 `r.ok`（被白名单拦下时如实报 FAILED 返回 false，不再"发出去了就算成功"）。
- `buildFromSchematic` command 模式：`await command(bot, 'setblock', [wx, wy, wz, blockStateToString(plan)], { cheat: true })`，按 `r.ok` 记 `placed`/`failed`（原先 `bot.chat` 不抛错就记 placed，语义偏乐观）。
- 结果：`skills.js` 代码里**已无任何裸 `bot.chat(`**（只剩两行注释提到旧写法），`preflight` 的 `slash-command-owner` 由 0 处继续成立。

**需要 preflight 加强的规则（归 T05/gate，我没有改 preflight.mjs）**：
现有规则 `pattern: /bot\.chat\s*\([^\n]*?['"`]\s*\//, scan:'raw'` 只认「同一行的字面量以 `/` 开头」，因此**这两处变量实参完全扫不到**（`bot.chat(msg)`）。要覆盖变量实参，需要二选一或并用：

1. **禁变量实参**（正面堵口）：`/\bbot\.chat\s*\(\s*(?!['"`])/` —— 只要实参不是字面量就算命中。allow 表外任何 `bot.chat(msg)` 一律报。这条最贴近原子化目标（允许的只有 `atom_input_misc.js`/`agent.js` 这类出口）。
2. **禁「造命令串」**（堵上游）：`/['"`]\s*\/[a-z]/` —— 命中任何以 `/` 开头的字符串字面量。因为命令一旦是拼出来的，先存进变量再 `bot.chat(变量)`，只有这条能在赋值处抓到。旧代码 `let msg = '/setblock ' + …` 会被它抓住。
3. 建议把两条都加，并保留现有 `scan:'raw'`（必须 raw：命令写在字符串里，`code` 模式永远扫不到）。

## 七、给下游 / 需注意的副作用

1. **T21（第10条）**：`skills.js` 现在是 5846 行处的 `ok` no-undef（原报告写 5750，被我插入的代码推后了行号），以及本文件名下 2 条浮空 promise。**这两项我未动**，留给 T21。
2. **`placeBlock(bot,'air',…)` 行为变化**：它直接转调 `breakBlockAt`，所以现在也会被 J4 闸拒绝拆玩家建筑（全仓当前无调用方，已 grep 确认）。语义上是对的（"放空气"=拆方块）。
3. **`safePlace()` 的连带影响**：它用 `NATURAL_BLOCKS.has(...)` 决定"已有方块能不能被覆盖"。删掉 farmland/moss 后，在农田/苔藓上盖地板会返回 `blocked` 而不是覆盖 —— 方向是保守的（拒绝破坏而非误拆），但属于可见行为变化，若日后要恢复"农田可铺"需单独加白名单，**不要**把它们塞回 `NATURAL_BLOCKS`（那会让 `/fill` 也去清农田）。
4. **`levelGround` 大区域填坑**：现在可能返回 `filled:false` 且不打 `/fill`（背包 filler 不足）。调用方若只看 `mode` 会以为地面已填平；需要的话看 `filled / haveFiller`。它仍然完成"削高"，不会残留高台。
5. **`breakBlockAt` 作弊分支**：`command()` 返回 `NO_PERMISSION` 时现在返回 **false**（原先无脑真）。若线上 owner 权限配置变化，会立刻在日志里看到 `Failed to /setblock …` 而不是假成功。
6. `countGapCells` 有 20 万次读取上限：超大区域（≈100×100）会返回 `truncated` 并跳过填坑，这是有意的（不凭猜测刷方块）。
