## 二、第27条：闸门与被索引的文档都盯着已作废的对象

### 2.2 缺陷 B：**闸门本身盯的是已作废对象**（报告没提）

`tools/preflight.mjs` 的「交接文档漂移检查」：

```js
const DOC = 'docs/交接文档.md';       // ← 一份自称作废、不再更新的文档
...
} else if (codeTs > docTs) { console.log('  ! 交接文档可能过时…') }
else { console.log('  ✓ 交接文档不比代码旧'); }
```

**它在检查"一份自称作废的文档是否比代码新"。** 那份文档本来就不再更新，所以这道门
要么恒亮红灯（永远"过时"），要么在有人随手改它时恒绿 —— 无论哪种，**都不衡量真实漂移**。
又一个"检查通过"与"检查没意义"同形。

**现在**：`DOC = 'docs/架构交接-总.md'`（权威），并把历史快照单独列出、只作提示、不参与判定：

```
  · docs/交接文档.md 是历史快照（最后一次提交 2 天前），只作对照，不参与判定
```

注意它**现在真的会报"过时 1 天"** —— 这是真话（权威文档 11-04，代码 11-05），不是恒真判断。

### 2.3 缺陷 C：裸常量棘轮被开了 9 个空名额 + 身份比对被总数掩盖

报告说「`audit_rules` 的裸常量棘轮被放宽了 9 个名额」。实测确认：基线 14 条里
**9 条指向已删除的模块**（`atom_dig` / `atom_move` / `atom_perceive`×2 / `task_collect`×4 / `tile_map`）。

但**为什么放宽了整整一个月没人察觉**——这是第二个缺陷，报告没写：

```js
if (violations.length > base.count) {      // ← 只有总数超标才比对身份
    const fresh = violations.filter(v => !known.has(...));
}
```

死条目把 `base.count` 撑到 14，而实际违规是 12 → **12 < 14，身份比对根本不执行**。
于是死条目腾出来的 9 个名额，被 **7 处真实新增**悄悄占掉：

```
act_craft.js:346(4.5) / act_dig.js:36(5.1) / atom_read.js:45(1.62) /
atom_tunnel.js:271(0.6) / nav_pathfinder.js:298(0.6) /
query_perceive.js:73(5.1) / query_tree.js:216(4.5)
```
（这 7 个文件在基线日期 2026-10-24 之后都被改过 —— 是既有欠账，不是本轮引入）

**两个错误互相掩护**：死条目制造缓冲，身份比对的门槛让缓冲不被检查。
单独看都不致命，合起来就是一个从 10-24 起持续吸收新欠账的黑洞。

**修法（三条）**：

1. **存在性断言**：每一条登记项必须 `existsSync(file)`，否则报死条目并判失败。
2. **身份比对无条件化**：只要有"名单里没有的"违规就报新增，**与总数无关**；总数只留作兜底。
3. **基线重建为 12**：删 9 条死条目，把 7 处如实补登记（队长裁决：**补登记，不现在修** ——
   给常量补 `// rule:Rx-xx` 出处是判断活，写错等于在注释里留假证据）。

> **报告预期"剔掉 9 条死条目后棘轮自动缩到 5"不成立，实测 12**（5 处 skills 老欠账 + 7 处被掩盖的新增）。
> 关键是它从**沉默的债**变成了**可见的债**：基线 12 = 现状 12，此后任何新增都会被无条件抓出。

## 六、第29条闸门加强：slack 命令规则能看见变量实参了

### 6.1 原来漏在哪

```js
pattern: /bot\.chat\s*\([^\n]*?['"`]\s*\//,   // 要求「同一行里先有字面量 /」
```

`bot.chat(msg)`（变量实参）**扫不到** —— 而 `skills.js` 那两处历史事故正是这种形态：
先 `let msg = '/setblock ' + …`，再 `bot.chat(msg)`。**规则只能看见"已经写成字面量"的形态，
最该防的间接形态正好在盲区里。**

### 6.2 现在两条规则（`patterns: [...]`，同一份 allow 名单）

```js
/\bbot\.chat\s*\(\s*(?!['"`])/                  // ① 禁止 bot.chat 传非字面量（变量/表达式）
/['"`]\s*\/(?![a-z]*[\\/-])[a-z]{2,}/           // ② 禁止在字符串里拼斜杠命令
```

**② 我按实测收窄了一档，理由可复现**：T20 给的原样 `['"`]\s*\/[a-z]` 在全仓命中 **77 处**，
其中大量是假阳性 —— 文件路径（`'/bots/'`、`'/action-code/'`）、正则字面量的 flag（`"/g`）、
shell 命令（`espeak "..."`）。把规则做成噪音源，下一个人就会给它加豁免加到失效。
收窄为「斜杠后 ≥2 个小写字母，且后面不紧跟 `/` 或 `-`」后：**77 → 57**，路径/flag 类假阳性清零，
真命令（`/setblock`、`/skin clear`、`/op`、`/ride`）全部保留。

> 过程中还抓到一个自己挖的坑：只排 `/` 挡不住 `'/action-code/'`（字母后有连字符），
> 所以负向前瞻加了 `-`。这是靠"对着真实代码跑一遍"发现的，不是靠想。

### 6.3 收紧 `chat-via-openchat` 的豁免（要真阳性，不靠放宽）

**`skills.js` 已从 allow 名单摘掉**。摘的依据是实测：`grep "bot\.chat("` 在该文件命中 2 处，
**两处都在注释里**（第 13、1063 行），代码里是 0 —— T20 已把最后两处直发改成 `command(...)`。
豁免已经没有存在理由，留着只会让"以后有人再写一句 bot.chat 直发"不被看见。

## 七、新增1：§3 会扫注释（误报源，根治）

### 7.1 事故

board 在 `board_store.js` 注释里写了一个 `{ ok:false, code:'XXX' }` 形式的**举例**，
T02 收窄后的正则把它当未注册码 → preflight 直接红 → **skills 的提交被拒，而双方代码都没错**。
绕法是"把注释改成散文"，但那等于把代价转给每个写注释的人，下一个人还会踩。

### 7.2 修法：扫描前剥注释（保留字符串）

```js
const t = maskJsSource(raw2, { strings: false });   // 只剥注释，字符串内容保留
```

**为什么保留字符串**：字符串里动态拼出来的码同样危险（`cmd('...')`），剥掉就是自废探测力。

### 7.3 深坑：`maskJsSource` 本身会被正则字面量带偏（已修）

做这件事时先验证了现有剥注释器，发现它在 `commands/index.js` 上**漏掉 82 行注释** ——
根因：该文件第 59-60 行两个正则字面量里含 `"`（`/!(\w+)…"[^"]*"…/`），
旧实现把 `"` 当成字符串开头，一路"吞"到下一个 `"`，于是后面的 JSDoc 全被当成字符串内容。

**修法：让 `maskJsSource` 认得正则字面量** —— 用"前一个非空白字符"判断 `/` 是正则开头还是除号，
并处理字符类 `[...]`（里面的 `/` 不结束正则）与 flags。

验证：**166 个源文件，剥注释后残留注释行 = 0**（修前 `commands/index.js` 泄漏 82 行）。

### 7.4 剥注释后扫码数不得下降

修前 33 → 修后 **33**（没有因为剥注释而漏掉任何码）。

### 7.5 正反样本（已入自检）

| 样本 | 必须 |
| --- | --- |
| `// 例：{ ok: false, code: 'FAKE_IN_COMMENT' }` | 不计入 ✅ |
| `/* 块注释 { ok: false, code: 'FAKE_IN_BLOCK' } */` | 不计入 ✅ |
| `return { ok: false, code: 'FAKE_REAL' };` | 抓到 ✅ |
| `const s = "{ ok: false, code: 'FAKE_IN_STR' }";` | 抓到 ✅（剥注释 ≠ 剥字符串） |
| 含引号正则之后：`const r = /"[^"]*"/g; … code: 'FAKE_AFTER_REGEX'` | 抓到 ✅（防整段错位） |

> 踩坑记录：我第一次的验收样例用了 `T05_PROBE` 这种**带数字**的假码，而捕获组是 `([A-Z_]+)`
> 不允许数字 → 两边都"没报错"，差点误判成"修复失效"。**样例本身不合格会骗过验收** ——
> 换成纯大写码名 `FAKE_REAL_CODE` 后两个方向都正确。
