## 二、第26条：0x08 假绿灯

### 2.1 病灶

`tools/preflight.mjs:183` 的两个正则各带一个 **0x08（退格）字节**前缀：

```
/\x08fail\(\s*'([A-Z_]+)'/g
/\x08code:\s*'([A-Z_]+)'/g
```

正则要求"字面退格"才匹配 ⇒ 对正常源码**永不命中** ⇒ `used2` 恒空 ⇒ `missing2` 恒空 ⇒ 恒打印「✓ 错误码审计通过」。`:933` 的 `SAW_A_SECTION` 另有一处 0x08，但只坏了三条备选之一（`A·策略`），另两条完好。

### 2.2 修复

- `:183` 两处 0x08 → `\b`。
- `:933` 一处 0x08 → `\b`。
- 两块正则**提成具名常量**（`CODE_AUDIT_REGEXES`、`SAW_A_SECTION`），提到文件上部集中定义 —— 自检脚本要能**从源码里抽出真身**去喂样本（否则测试只能证明"副本没写错"）。

### 2.3 修好之后暴露了什么（这一步是关键证据）

只把 0x08 换成 `\b`、**判据不动**，复跑立刻从"全绿"变成点名：

```
  ✗ 有 1 个错误码没注册：DIED
      DIED ← src\agent\library\control.js
启动自检失败：1 处有问题。不要重启 agent。      ← exit 1
```

这道门上线以来第一次真的开了口。—— 也就是说：**修复前的"全绿"完全是假的，它就是靠 0 命中装出来的绿。**

### 2.4 裁决：收窄判据，不注册 DIED

**裁决：不把 `DIED` 加进 `CODES`，而是收窄判据。** 依据：

1. **`DIED` 是另一套词汇表。** 它只出现在任务板的**停止/结果码**位置，从没进过 `fail()`：
   - `control.js:188` `code: 'DIED',`（停止计划里的 stop code）
   - `control.js:192` / `:443` `result: { code: 'DIED', at: now }`（写进任务板的结果数据）
   - 全仓 `fail('DIED'` = **0 次**
2. **加进 `CODES` 是有害的。** `CODES` 是 `fail()` 与 `assertResult()` 用来校验 **ActionResult** 的合法码集合。把 `DIED` 塞进去，等于宣布「`DIED` 是个合法的 ActionResult 错误码」—— 语义错的，而且会让以后真正误用 `DIED` 的地方不再被拦。
3. **报告自己也这么判。** §S20：`test_codes` 报 `DIED` 这件事**口径错了**（把 `code:` 数据载荷当错误码）。第26条与 S20 同源。

**收窄方式**（`code:` 这个键在仓库里有三种含义，只有第一种该受 CODES 约束）：

| 用法 | 例子 | 该不该进 CODES |
| --- | --- | --- |
| (a) ActionResult 错误码 | `{ ok: false, code: 'WINDOW_CLOSED', message }` | **该** |
| (b) 任务板停止/结果码 | `code: 'PREEMPTED'` / `result: { code: 'DIED', at }` | 不该 |
| (c) 纯数据载荷回显 | `failed.push({ pos, code: 'NO_SUPPORT' })` | 不该 |

所以第二条正则从宽口径 `code:` 收紧为**「对象里带 `ok:` 的 code 字面量」**：

```js
/\{\s*ok:\s*(?:true|false)[^{}]{0,300}?\bcode:\s*'([A-Z_]+)'/g
```

**收紧后没有损失探测力**（实测，162 个源文件）：

| 扫描口径 | 捕获码数 | 未注册 |
| --- | --- | --- |
| `fail()` 单条 | 25 | 0 |
| `ok:` 字面量单条 | 20 | 0 |
| 两条合并（**采用**） | **33** | **0** |
| 修复前的宽口径 `code:` | 28 | 1（DIED，即误报） |

即：收窄后**扫到的码更多**（33 > 28，因为 `fail()` 那条现在真的在命中）、误报归零。

### 2.5 顺带补的护栏：0 命中也不能算绿

这是第26条**真正的教训** —— 病灶换个形式还会再来。所以在 §3 打 ✓ 之前加了一道：

```js
const gotCodes = gotSrcFiles && requireScanned('3 错误码审计', used2.size, '错误码用法（正则可能又坏了）', …);
```

并用绿字自证：`✓ 错误码审计通过（扫到 33 个码，均已注册；CODES 共 38 个）`。

> 与已有的 `t99` 护栏的区别：`t99` 只保证「扫到了 162 个**源文件**」；0x08 那次 `files2=162`、`used2=0`，照样绿。这道新护栏保证「正则**真的抓到了码**」。两者是不同层，缺一不可。

## 三、第34条：§1「部分加载 = 成功」

### 3.1 病灶

`tools/preflight.mjs:72-80`：

```js
} else {
    // 其他错误（缺少 bot 实例之类）在导入阶段不致命   ← 什么都不记
}
...
if (failed === 0) {                                   ← 只看"有没有报致命错"
    console.log(`  ✓ 所有模块导入成功（${loaded}/${files.length}）…`);
}
```

既非 `ReferenceError` 也非"缺模块"的导入失败，**既不计 failed 也不计 loaded**，于是 `loaded < files.length` 时仍打 ✓ 并 `exit 0`。

### 3.2 修复

1. 静默跳过改为**记账**（`skippedByOther`，含文件名/错误类型/消息）。
2. 判据改为 `loaded === files.length`；不满足则 `failed++` 并**点名差了几个、差的是谁**。
3. 保留 `!gotModules` 分支：0 个模块时由 `requireScanned` 报，不再打印「0/0 全部成功」（否则又是一次假绿）。

### 3.3 反向验证（造一个静默失败，证明新判据真的会红）

临时塞入 `src/agent/_t02_neg/boom.js`（抛 `TypeError` —— 既非 ReferenceError 也非缺模块），跑完即删：

```
  ✗ 只导入了 122/123 个模块，差 1 个 —— 不能算"导入成功"
     "静默跳过"不等于"导入成功"：这些模块报了非致命错，根本没加载进来。
     · _t02_neg/boom.js [TypeError] t02 negative sample
EXIT: 1
```

同一场景下**旧代码会打印「✓ 所有模块导入成功（122/123）」并 exit 0**。清理已核验（`ls src/agent | grep -c _t02_neg` = 0）。

## 四、配套单测 `tools/preflight_regex_unit.mjs`

### 4.1 它防的是什么

不是"正则写错了"，而是**「扫描器坏了，却报出和『检查干净』一模一样的结果」**。这类 bug 靠人眼看输出永远发现不了，必须有个东西专门证明「扫描器还看得见」。

### 4.2 三条设计约束（避免写成自证式断言）

1. **正则从生产源码里抽，不抄副本。** 脚本用正则从 `tools/preflight.mjs` 抽出 `CODE_AUDIT_REGEXES` 与 `SAW_A_SECTION` 两块常量的**字面量文本**再求值，然后喂样本。抄一份副本过来断言"副本能匹配"，只证明我没打错字。
2. **每条正则都喂正反两面**：能命中（正例）+ 不该命中（反例）。只有正例时，一个"永远匹配"的坏正则也能通过。
3. **整文件控制字符扫描**：0x08 这一族不留余地 —— preflight 里出现任何 C0 控制字符（除 `\n`/`\t`）即红。

### 4.3 它真的能抓住原 bug（反向验证）

拿修复前的版本（`git show HEAD:tools/preflight.mjs`）喂给它：

```
  ✗ 源码里没有控制字符（0x08 退格等）
     发现 3 处：第 183 行：0x08；第 183 行：0x08；第 933 行：0x08
  ✗ 抽不出 CODE_AUDIT_REGEXES（常量被改名/改成动态拼接了？）
  ✗ 抽不出 SAW_A_SECTION（§6 的指纹正则被改名了？）
✗ 有红项：0 通过，3 失败。      ← exit 1
```

**它不是一个自证式断言：对着坏文件它是红的。** 对修复后的文件 16/16 全绿。

### 4.4 已知局限（写在输出里，不藏着）

`fail('GHOST')` 出现在**注释**里也会被算作"使用了这个码"。这是这条正则的固有局限（无 AST 解析）。取向是**宁左勿右**：误报会被人看一眼否掉，漏报会让 `fail()` 在运行期 throw。这条局限作为一条显式 ✓ 项打印出来，不装作不存在。
