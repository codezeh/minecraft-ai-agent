1. **不能只看端口**：Paper 在插件加载前就监听 25565，bot 6s 冲进去被

2. **不能立刻重启**：Paper 关服要等 chunk 系统停（10s+），端口关了进程还在，
   抢端口会启动失败 → 启动前先等旧 java 退干净

### 修掉的真 bug（都会让人以为"功能没做"）

1. **命令参数必须用双引号**：`src/agent/commands/index.js` 的 `commandRegex` 只认
   数字/布尔/`"双引号字符串"`，单引号整段被丢 → 报 `missing param 'type'`。
   快捷指令已全部改双引号。
2. **`readFails` 默认 10 分钟 TTL**：诊断要看历史全量，已显式传 `ttlMs: Infinity`（否则失败点少一半）。
3. **vite 代理写 `localhost` 连不上**：mindserver 只绑 IPv4，Node 18+ 把 localhost 解析成 `::1` → 改 `127.0.0.1`。
4. **vite dev server 会自己崩**：watcher 撞上编辑用的 `.tmpdir/.tmp` 文件抛 EBUSY → 已排除 `**/.*`、`**/*.tmp`、`poc/`、`dist/`。
5. **server.properties 是 CRLF**：用 `^...$` 逐行正则解析会得到 0 个键（RCON 配置读不到）→ 改 `indexOf('=')` 切分。

## 3. 3D 地形：已验证可行（这是本轮新增的重点）

### 3.1 数据在哪、长什么样

`mindcraft/bots/deepseek/map/terrain3d.db`（8.8 MB，SQLite）

```sql
CREATE TABLE surf (            -- 可站立面；主键含 y → 一列可以有多层
  x INTEGER, z INTEGER, y INTEGER, t INTEGER,
  PRIMARY KEY (x, z, y)) WITHOUT ROWID;
CREATE TABLE chunk_index (cx, cz, x0, z0, x1, z1, cells, scanned_at);
CREATE TABLE fail (x, z, y, hits, last_at);   -- 寻路失败点，带次数
```

实测（我刚查的）：

| 指标 | 值 |
|---|---|
| 可站立面 | **35,926 条** |
| 独立列 (x,z) | 18,744 |
| **多层列** | **10,598（57%）** — 最多 12 层 |
| bbox | x[-242..-45] · z[-272..-139] · y[25..95]（约 198×134×70） |
| 已扫描区块 | 93 |
| 失败点 | 662 条（记录了 hits 次数，bbox 比地形范围大） |

类型码 `t`（`terrain3d.js:27` `T`）：

| t | 含义 | 建议配色 |
|---|---|---|
| 0 | SOLID 实心可站 | 橄榄绿 `#5c8a4a` |
| 1 | WATER 水面 | 蓝 `#2f6dd0` |
| 2 | LAVA 岩浆（禁行） | 红 `#e0483a` |
| 3 | BUILT 玩家建筑 | 橙棕 `#c98b3e` |
| 4 | LEAVES 树叶 | 绿 `#3fa34d` |
| 5 | CLIMBABLE 可攀爬（**不是落脚点**） | 黄 `#d8b23c` |
| 6 | SUBMERGED 水下地面（执行层不会潜水→代价极高） | 青 `#2a8f8f` |

> 5 和 6 的语义别搞混：5 是"能置身其中上下移动"，6 是"能站但上方有水"。
> 图上必须区分色，否则看的人会误判"这里能走"。

### 3.3 正式面板怎么接（三条路，建议 A）

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A. 复用现有 canvas 2D 渲染器（推荐）** | 把 poc 的渲染逻辑搬进 `TerrainView.vue`，数据改成走 socket 实时拉 | 零依赖、已验证、代码少；遮挡是"画家算法"近似（够用，且已能看出层次） |
| B. Three.js `InstancedMesh` | 真 3D：正确遮挡、光照、可放人物/路径模型 | 多 ~600 KB 依赖 + 更多代码；**升级触发条件**：面数 >10 万、或需要沿路径做动画、或你嫌 A 不够好看 |
| C. 只做 2.5D 高度图 | 取每列最高面画热力/等高 | 最省事，但**丢掉 57% 的多层数据**——这个库的价值就在 3D，不建议 |

A 和 B 都收在同一个组件边界后面（`TerrainView` 的入参是 `{faces, bbox, marker}`），
所以 A→B 是可替换的，不会牵连其它页面。

### 3.4 新接口（P1，需要后端加）

```
agent socket:  get-terrain(opts, cb)
  opts: {x0, z0, x1, z1, yMin?, yMax?, lod?}     // lod: 1=全量 2=每2列取样
  cb:   {ok, bbox, faces: <Int16Array x,z,y · Uint8Array t，base64>, count, lod, ms}
```

实现：`terrain3d.boxSurfaces(mapDir, x0, z0, x1, z1, yMin, yMax)` —— **函数已经有了**，
不新增 owner，只加一层"打包 + ack"。

体积控制（关键）：
- 全量 36k 面 JSON ≈ 1.2 MB；改 `Int16Array`+`Uint8Array`+base64 ≈ **250 KB**。
- 默认拉"她周围 96×96、lod=2" ≈ 9k 面 ≈ 60 KB；放大再拉细，**按需 LOD**。
- 地图数据**不进 1 Hz 状态流**（沿用现有 `request-map` 的按需思路）。

## 5. 事件流：ring buffer 怎么接（比想象中省事）

`executor.js` 与各原子层**已经有** `onEvent` 回调，事件已经是结构化对象：

```
{type:'dig', y, name}                    {type:'digdown', y, name}
{type:'place', ok, code, y}              {type:'scan3d', cells, ms, chunks}
{type:'plan-fail', round, code}          {type:'oscillation', round, at, times}
{type:'height-miss', want, got, diag}    {type:'unsafe-landing', x,y,z}
{type:'liquid-pass', name, y}            {type:'clear-feet'|'clear-head', name, ok}
```

现状：调用方把事件直接 `console.log` 掉了（`actions.js:146/424/443` 等）。

**所以不用到处埋点**，只要：
1. 新建 `src/agent/library/trace_bus.js`：`push(e)` 写入 200 条 ring buffer，带自增 `seq`；
2. 把那 6 处 `console.log` 的 lambda 换成 `traceBus.collect`（顺带保留日志）；
3. `mindserver_proxy.js` 加两个 handler：`get-events(sinceSeq, cb)` + 新事件 `emit('agent-event', e)`。

留给前端的就是"接上就能画"。**这是 P1 里性价比最高的一项。**

## 6. 配置向导的 paper 层（你要的"都要"）

现有事实：`文件/start.bat` 里写死了 `java -Xms1G -Xmx2G -XX:+UseG1GC -jar server.jar nogui`，
JDK 在 `.tools\jdk-21.0.12.1+1\bin\java.exe`，MC 1.21.8，端口 25565，RCON 25575。

要做的（新增 `mindcraft/src/mindcraft/proc_control.js`，挂在 mindserver 上）：

| 能力 | 实现要点 |
|---|---|
| 状态探测 | 端口 25565 是否可连 + 进程是否活着（内存里存 pid，不写文件） |
| 启动 | `spawn(java, [...], {cwd: 'server'})`，沿用 start.bat 的参数；**先探端口再启动**，防重复起服 |
| 就绪判定 | 抓 stdout 里 `Done (xx.xxxs)! For help, type help`，别用固定 sleep |
| 优雅停止 | RCON 发 `stop`（密码在 `server/config/server.properties`），**不要直接 kill**，否则存档可能损坏 |
| 日志 | stdout/stderr 进 ring buffer（同 §5 复用），面板可看尾部 |
| 崩溃重启 | 首版**不做**自动重启（会掩盖问题），只显示"已退出(exit code)" |

风险与红线：
- 绝不对整个 node 进程树 blanket kill（`经验教训` 里明确说过会误杀用户的其它进程）。
- 起服失败必须把最后 50 行 stdout 直接摊在面板上，否则"点了没反应"。
- Windows 上 java 子进程要 `detached:false` + 显式 `kill` 兜底，避免僵尸。

两套接线：
- dev：`pnpm dev` → 5173，proxy `/socket.io` → `localhost:8080`（`ws:true`）
- prod：`pnpm build` → `dist/`，mindserver 加 3 行 `app.use('/console', express.static(...))` + SPA fallback

实现约束（都踩过或算过）：
- socket **单例**；`listen-to-agents` 只发一次（服务端按 socket 计数）。
- `state-update` 1 Hz 全量 → store 字段级 diff，别整块 re-render。
- 地图/地形**不进**状态流，按需拉 + loading 态 + 失败保留上一帧。
- 断线：顶部红条 + 数值置 `-`，**不清空对话**，重连自动 `listen-to-agents`。
- 贴图 `onerror` 回落文字，别出现破图。
- 不做 3D 世界渲染（`render_bot_view` 因原生 `canvas` 依赖已关）。

## 9. 验收标准

**控制台**
1. 5173 打开 3 秒内出 agent 卡，数值与游戏内一致。
2. 她在游戏里走动，坐标/朝向 1 秒内跟上。
3. 断开 mindserver → 红条 + 数值 `-`，不白屏；恢复后自动接上。
4. 背包是真实物品贴图，未知物品回落文字。
5. 点"跟过来"→ 游戏内真的开始跟。
6. 1 Hz 连续 10 分钟，Performance 无 >50 ms 长任务、内存不持续增长。

**3D 地形**
7. `/terrain` 打开 2 秒内出地形，能拖动旋转/滚轮缩放，不卡死。
8. 高度切片能把洞穴和地表分开看（拿 `(-8,-15)` 那片有洞的区域验）。
9. 颜色与 `t` 一致：岩浆红、水面蓝、水下地面青、可攀爬黄（不能把 5 和 6 混成同色）。
10. 失败点红色标记出现在 `fail` 表坐标上，半径随 hits 变大。
11. 拉取失败（bot 未上线/DB 锁）时显示原因，不留空白画布。

**向导**
12. 能列出 profiles、改 3 项设置并重启生效。
13. paper 未启动时显示"未运行"；点启动 → 面板出现真实启动日志；就绪后状态变"运行中"。
14. 已在运行时再点启动 → 提示"已在运行"，**不会起第二个服**。
15. 停止走 RCON `stop`，服务端日志出现正常关闭序列（不是强杀）。

**回归**
16. 旧面板 `http://localhost:8080` 在 `/console` 上线后行为不变。

## 10. 风险

| 风险 | 处置 |
|---|---|
| 无鉴权，只绑 localhost | 谁都不许改成 `0.0.0.0`；手机访问另立任务（反代 + 白名单） |
| socket.io 版本 | 后端 4.7.2 → 前端锁 `socket.io-client@^4.7` |
| 3D 面数增长 | LOD + 按需拉取；>10 万面再上 Three.js（方案 B） |
| `terrain3d.db` 正被 bot 写入（WAL） | 读走 `boxSurfaces`（同一进程内，正常并发）；导出脚本用**临时副本**，别直连原库 |
| paper 起服把存档搞坏 | 只走 RCON `stop`；禁 kill；先探端口 |
| 改 mindserver.js | 只新增 handler + 一处 static，不动已有事件语义 |
| 后端仍在重构中 | 前端只依赖 socket 契约与 `boxSurfaces`，不 import 内部模块 |
