## 一、这个项目是什么

Minecraft 陪伴 AI（mineflayer bot，Paper 1.21.8）。目标不是"全自动玩家"，而是能在 4 个真实场景里可靠工作：

| 场景 | 验收标准 | 状态 |
|---|---|---|
| **S0** 陪坐 30 分钟 | 不崩、不断连、位移<2格、memory<20KB | ✅ 已通过 |
| **S1** 跟着走 5 分钟 | 跟丢>8格且持续>3秒 的次数 ≤1 | ⚠️ 基本可用 |
| **S2** 砍 8 个橡木 | 8 分钟内、报数=背包实际增量 | ⚠️ **进行中**（当前 3/3 能成，8 个未验） |
| **S3** 3×3 平台 | 10 分钟内、9 格全对 | ✅ 已通过 |

## 三、已确认的游戏规则（别再猜了）

### 3.1 交互距离 —— 三层，别混

| 层 | 阈值 | 是否限制 | 依据 |
|---|---|---|---|
| Paper 服务端 | **基本不校验** | ❌ | 实测 6.11 格也能挖成功 |
| mineflayer `canDigBlock` | 5.1 | ❌ `dig()` 不调用它 | 源码 |
| **pathfinder `GoalLookAtBlock`** | **4.5 + 射线必须命中** | ✅ **唯一真限制** | 源码 `goals.js:158` |

**结论**：`digBlock` 用 **5.1 + 只判距离**；若用 `GoalLookAtBlock` 记得传 `reach: 5.1`。

### 3.2 挖方块不需要视线（实测）

中间挡一层 `oak_leaves`，`raycast` 命中的是树叶，但 `bot.dig` **照样挖到后面的原木**。

### 3.3 方块不会塌

原木、木头、石头都不受重力（受重力的只有 sand/gravel/anvil/concrete_powder）。
**所以"砍伐顺序"对完成度零影响**——我之前的 `tree_strategy.js`（树型+从上/从下砍）**没有物理依据，应删**。

### 3.4 叶子不用砍

`leaves` 有 `distance:1..7` 状态，原木砍光后离原木>6 格的叶子自动枯萎。

### 3.5 原木不需要工具

`oak_log.harvestTools` 为空 → 徒手也能挖（3 秒）。斧头只是加速（铁斧 0.5 秒）。
**但石头必须用镐**（`harvestTools` 只有 877~902 六种镐，斧头挖不了）。

### 3.6 其他常量

| 项 | 值 |
|---|---|
| 玩家身高/眼高/宽 | 1.8 / 1.62 / 0.6 |
| 跳跃高度 | 1.25 格（能上 1 格台阶） |
| 行走/冲刺 | 4.317 / 5.612 格每秒 |
| pathfinder 单次 goto | **13~15 秒**（与距离关系不大） |
| 区块扫描 8×8 | 27~41 ms |
| 玩家可达速度 | 3.75 格/秒（人类直走） |

## 五、目标架构（已和你对齐的部分）

### 5.1 核心模型：不是四段流水线，是「循环 + 断言 + 降级」

```
枚举目标 → 取一项 → 查状态（已做/已失败/黑名单）
        → 执行原子（自带前置断言）
        → 校验后置（读世界，不信返回值）
        → 失败按错误码降级 → 下一项
```

**为什么不是「找路→辨别→确认→行动」**：那条路把"失败后的回退"藏起来了，而今天 12 次修复里最大的单类恰恰是**失败降级错**（3 次）。

### 5.2 统一的数据结构

```js
// 目标项
{ kind: 'block'|'entity'|'cell', pos, expect: 'air'|'oak_log', state: 'todo'|'done'|'failed' }

// 原子返回
{ ok, code, message, data: { target, from, dist, count, costMs, extra: {} } }

// 降级策略（现在是散在各处的 if-else）
{ OUT_OF_REACH: 'restep', NO_PATH: 'restep', NO_ITEM: 'abort', BLOCKED: 'retry' }
```

### 5.3 最终只有 7 个动作原子

```
moveTo(target, tol)         pre: 有路        post: 到达
digBlock(pos)               pre: 可挖+≤5.1    post: 是空气
placeBlockAt(pos, item)     pre: 有料有支撑   post: 是该方块（读世界）
equipItem(name)             pre: 背包有       post: 手持
openContainer(pos)          pre: 是容器       post: 窗口开
useBlock(pos)               pre: 可交互       post: 状态变
attackEntity(entity)        pre: 在范围       post: 目标死/远离
```

**`use` 必须按方块类别分派**（容器7种/工作站12种/门4种/床2种/农作物4种），不能一个泛化原子。

### 5.4 `use` 首版拆 4 个（你已确认）

容器 / 工作站 / 门 / 床。
**交易、骑乘、喂食**：首版不做，但**代码里已有的话保留**（`skills.tradeWithVillager` / `showVillagerTrades` 已存在）。

## 七、踩过的坑（别再踩）

### 7.1 我犯的错（按严重度）

| 错 | 后果 |
|---|---|
| **凭空想象游戏规则**（"树会塌"、"树型决定砍法"） | 写了没用的 `tree_strategy.js` |
| **没查项目已有的东西** | 无视 `skills.js` 87 个函数和官方插件，重写 3000+ 行 |
| **在 678 行里打补丁** | 24 小时改 12 次，8 个 bug |
| **测试服通过就当真** | 5 个 bug 到真实丛林才炸 |
| **漏 import 当"改完了"** | `MEMORY_CODE_VERSION`、`resolveCollectTarget`、`reachDistanceTo` 各崩一次 |
| **反复调参不读源码** | 交互距离改了 3 次（4.3→4.5→5.1）才对 |

### 7.2 技术坑

| 坑 | 解法 |
|---|---|
| `/tp` 会让服务端以 `invalid_player_movement` 踢人 | 用 `spreadplayers` 或让 bot 自己走；`spigot.yml` 的 `moved-wrongly-threshold: 0.0625` 很敏感 |
| 测试账号继承上次的 NaN 位置被秒踢 | 每次用新账号名（`p` + 时间戳） |
| `setblock`/`fill` 之后要等 1.5~2 秒才读到新方块 | 加 sleep |
| `bot.blockAt` 必须传 `Vec3`，否则 `pos.floored is not a function` | 用项目的 `blockAt` 包装 |
| `getBlock` 需要 chunk 相对坐标（0..15） | 区块扫描时注意 |
| 记忆会写下基于 bug 的错误结论 | `MEMORY_CODE_VERSION` 版本戳，版本变了就丢经验类记忆 |
| 任务执行中写记忆会把"命令刚发出"当成"失败" | `actions.executing` 为真时跳过摘要 |

### 7.3 必须遵守

- **改完先跑 `node tools/preflight.mjs`**（两层：模块导入 + 假 bot 跑关键函数，能抓漏 import）
- **不要 blanket kill node 进程**（会杀掉用户的 SillyTavern）
- **只认主服真机结果**，测试服（25566）过了不算
