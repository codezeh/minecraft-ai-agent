# 原子接口标准（v1）

> 配套 [原子动作规格-v2.md](原子动作规格-v2.md) 与 [字段标准.md](字段标准.md)。
> 那两份管**返回什么**，这份管**怎么传进去**。
> 制定：2026-10-24

---

## 0. 扫出来的 9 类矛盾

| # | 矛盾 | 严重度 |
|---|---|---|
| 1 | `place` 返回的 `block` 在成功/失败时是两个意思 | **高**（静默出错） |
| 2 | 二维坐标有三种名字：`posXZ` / `reached` / `{x,z}` | **高** |
| 3 | 目标标识用 `target`/`block`/`item`/`kind` 四种平铺字段 | **高** |
| 4 | 坐标传参有 4 种形状：`(x,y,z)` / `(x,z)` / `(pos)` / `(entity)` | 中 |
| 5 | 可达距离四个名字：`maxReach` / `reach` / `tol` / 无 | 中 |
| 6 | 超时三套名字和默认值：`timeout` / `extraMs` / `verifyMs` | 中 |
| 7 | `item` 与 `block` 混用（参数叫 item、返回叫 block） | 轻 |
| 8 | `equipItem`/`dropItem` 没有 `opts`，无法统一扩展 | 轻 |
| 9 | 有的原子有前置 `interrupt` 检查，`atom_items` 没有 | 轻 |

## 1. 三条原则

| # | 原则 |
|---|---|
| I1 | **目标一律传 `{kind, ...}` 描述对象**，不许拆成位置参数 |
| I2 | **同名必须同义**：一个字段名在成功和失败时只能表示同一个东西 |
| I3 | **所有可调参数进 `opts`**，且同名同义、同单位（毫秒） |

## 2. 目标描述对象

### 2.1 五种目标

```js
{ kind: 'point',  pos: {x, y, z} }        // 走到某点（可只给 x/z）
{ kind: 'block',  pos: {x, y, z}, name? } // 挖/放/交互某个方块
{ kind: 'entity', entity }                // 攻击某实体
{ kind: 'player', name: 'xxx' }           // 面向某个玩家（由 locate 解析）
{ kind: 'self' }                          // 她自己
```

**为什么统一**：现在 `moveTo(bot,x,y,z)` 三个数、`moveToXZ(bot,x,z)` 两个数、
`digBlock(bot,pos)` 一个对象——同一个"位置"有四种传法，加第五个原子时没有参照。

### 2.2 位置坐标

| 形状 | 什么时候用 | 名字 |
|---|---|---|
| `{x, y, z}` 整数 | 方块坐标（dig/place/use/container） | `pos` |
| `{x, z}` 整数 | 只要水平位置的移动 | `posXZ` |
| `{x, y, z}` 浮点 | 实体位置 | `entityPos` |

**不许传 Vec3**：跨模块传递会变成隐式依赖（且曾经导致 `pos.floored is not a function`）。

### 2.3 新签名

```js
moveTo(bot, target, opts)              // target: {kind:'point', pos:{x,y,z}} 或 {kind:'point', posXZ:{x,z}}
digBlock(bot, target, opts)            // target: {kind:'block', pos}
placeBlockAt(bot, target, blockName, opts)  // target: {kind:'block', pos}
useBlock(bot, target, opts)
openContainer(bot, target, opts)
attackEntity(bot, target, opts)        // target: {kind:'entity', entity}
equipItem(bot, itemName, opts)         // opts.destination = 'hand' | 'head' | ...
dropItem(bot, itemName, count, opts)
```

**兼容性**：目标的"扁平写法"（直接传 `{x,y,z}`）**允许**，由统一的
`normalizeTarget()` 归一成 `{kind:'point'|'block', pos}`。这样 17 处调用方
可以分批迁，而不是一次全改。

> 这条是有意的例外：字段标准里我们决定"不留旧名"，因为`data` 是新增的、读取方少；
> 而坐标传参是**存量 17 处调用**，一次全改无法定位问题。区别在于：旧名是**读**，
> 坐标是**写**——读错了会静默，写错了会立刻报错。

## 3. 参数命名（`opts`）

| 概念 | 唯一名字 | 默认 | 单位 |
|---|---|---|---|
| 可达距离 | `maxReach` | 按原子定（见下） | 格 |
| 停止容差（移动） | `tol` | 1（moveTo）/ 2（XZ） | 格 |
| 超时 | `timeout` | 按原子定 | **毫秒** |
| 后置校验等待 | `verifyMs` | 800 | 毫秒 |
| 能否挖掘 | `canDig` | false | — |
| 能否搭方块 | `scaffold` | false | — |

**废除**：`reach`（→ `maxReach`）、`extraMs`（→ `verifyMs`）、`allowBreak`（→ 用 `canDig` + `scaffold` 组合）。

### 3.1 各原子的默认值（写进代码，不许各处自己定）

| 原子 | `maxReach` | `timeout` | 依据 |
|---|---|---|---|
| `digBlock` | `digReach()` = 5.1 | 按 `digTime*2+500` | 规则 R3-01 |
| `placeBlockAt` | 4.3 + 1 | 3000 | 放置比挖掘保守 |
| `useBlock` / `openContainer` | `GOAL_LOOK_AT_DEFAULT_REACH` = 4.5 | 3000 / 4000 | 规则 R2-02 |
| `attackEntity` | 3.0 | 8000 | 近战 |
| `moveTo` | —（用 `tol`） | 30000 | — |

**超时默认值不同是有意的**：开箱子 4 秒、开门 3 秒，这是实测的正常上限；
统一成 30 秒会让失败检测变迟钝。**单位必须都是毫秒**，这一点不许有例外。

## 4. 目标标识（返回字段）

现在四种平铺字段（`target`/`block`/`item`/`kind`）统一成：

```js
target: { kind: 'block'|'entity'|'item', name: 'oak_log' }
```

### 4.1 修复 `block` 的双重含义

| 场景 | 现在 | 改成 |
|---|---|---|
| `placeBlockAt` 成功 | `block: 'oak_log'`（放的） | `placedBlock: 'oak_log'` |
| `placeBlockAt` 被占 | `block: 'dirt'`（那里的） | `occupiedBy: 'dirt'` |
| `digBlock` 成功 | `block: 'stone'`（挖掉的） | `dugBlock: 'stone'` |

**理由**：同名不同义是最危险的一类矛盾——`block: 'dirt'` 到底是"我放了 dirt"
还是"那里已经是 dirt"，只能靠读代码判断。

### 4.2 其余字段

| 原子 | 字段 |
|---|---|
| `openContainer` | `containerKind`, `slots`, `containerSlots`, `title` |
| `useBlock` | `useKind`（door/bed/workstation/crop），`state` |
| `attackEntity` | `killed`, `hpLeft`, `target` |
| `equipItem` | `equipped`（物品名）, `count` |
| `dropItem` | `dropped`, `left` |

---

## 5. 中断检查（统一）

每个原子**入口**必须检查 `bot.interrupt_code`，包括 `atom_items`（现在没有）。

`atom_items` 的两个函数是同步的、极快，理论上不需要中断；但为了行为一致，
加一行检查成本可忽略。

---

## 6. 机器检查（进 `contract_audit`）

| 规则 | 检查方式 |
|---|---|
| 不许出现 `block:` 作为返回字段 | 正则扫 `atom_*.js` 的 `ok({...})` / `fail(..., {...})` |
| `atom_*.js` 的 `export async function` 必须接受 `opts` | 签名扫描（`equipItem`/`dropItem` 例外，它们进第 2 阶段） |
| 参数名不许出现 `reach:` / `extraMs:` / `allowBreak:` | 正则扫 |
| 返回里不许出现 `reached:`（二维坐标） | 正则扫 |

## 8. A 步执行结果（2026-10-24）

### 实际改动

| 项 | 改动 |
|---|---|
| #1 `block` 双义 | `place` 成功 → `placedBlock`；被占 → `occupiedBy`；超时 → `occupantNow`；`dig` → `dugBlock` |
| #2 二维坐标 | 统一 `posXZ`；`path_short` 的 `reached` 已列入禁止清单（下轮改） |
| #3 目标标识 | `attack` → `target:{kind:'entity', name}`；`container` → `containerKind`；`use` → `useKind` |
| #5 参数名 | `attack` 的 `reach` → `maxReach` |
| #6 超时 | `dig` 的 `extraMs` → `verifyMs`；`moveToXZEx` 的 `allowBreak` → `tryBreak` |

### 新增 `normalizeTarget()`（`atom_contract.js`）

接受两种写法，让 17 处存量调用方**不用一次全改**：

```js
// 新写法
digBlock(bot, { kind: 'block', pos: { x, y, z } })
// 旧写法（照常工作）
digBlock(bot, { x, y, z })
```

已接入 `digBlock` / `placeBlockAt` / `useBlock` / `openContainer`。

### 机器检查（已进 preflight）

| 规则 | 状态 |
|---|---|
| `ok({ block: ... })` → 必须用 `placedBlock`/`dugBlock` | ✅ 已拦截 |
| `block: item` / `block: target.name` → 必须用 `occupiedBy` | ✅ 已拦截 |
| `ok({ kind: '...' })` 平铺 → 必须用 `containerKind`/`useKind` | ✅ 已拦截 |
| `opts.reach` / `extraMs` / `allowBreak` | ✅ 已拦截 |
| `reached: {x,z}` → 必须用 `posXZ` | ✅ 已拦截（存量待 B 步清） |

### 验证

| 项 | 结果 |
|---|---|
| 7 个原子测试 | ✅ 80/80 |
| `preflight` | ✅ 全绿（字段标准：通过） |
| `fieldAudit` | ✅ 0 处违规 |

### 保留的例外（有意为之）

`block: block.name` 在 `fail()` 里是**诊断上下文**（"哪个方块挖不动"），不算歧义，予以放行。
只有 `block: item`（放的）和 `block: target.name`（被占的）才被拦截。

## 9. B 步执行结果（2026-10-24）：14 处调用方迁完，兼容分支已删

### 迁移清单

| 文件 | 改动 |
|---|---|
| `task_collect.js` | `moveTo` × 4、`digBlock` × 4 |
| `task_follow.js` | `moveTo` × 2 |
| `task_platform.js` | `moveTo` × 1、`placeBlockAt` × 1 |
| `path_short.js` | `moveToXZEx` × 1 |
| `commands/actions.js` | `placeBlockAt` × 1 |
| `tools/atom_*.mjs` | 7 个测试全部切到新签名 |

**`normalizeTarget` 的裸坐标兼容分支已删除**：现在只接受 `{kind, ...}` 描述对象。
再传裸坐标会立刻返回 `NO_TARGET`，不会静默降级。

### 新增机器检查

| 规则 | 说明 |
|---|---|
| `moveTo(bot, x.x, ...)` | 原子调用必须传 `{kind, pos}` |
| `digBlock(bot, { x: ..., })` | 裸坐标对象一律拦截 |

### B 步顺带扫出的新增两类矛盾（已修）

| # | 矛盾 | 证据 | 修法 |
|---|---|---|---|
| 10 | **原子间调用传错形状**：`useBlock` 的工作站分支给 `openContainer` 传 Vec3，而后者只收描述对象 | 测试报「目标位置无效」 | 改成 `{kind:'block', pos:{...}}` |
| 11 | **同一原子的不同成功路径字段不一致**：`place` 的 `existed:true` 分支没有 `support`；`attack` 的 `killed:true` 没有 `hpLeft` | 上层用同一读取路径拿到 `undefined` | 所有成功路径补齐相同字段集 |

**第 10 类是这次扫描最有价值的发现**：原子改成对象签名后，原子**之间**的调用最容易漏——
它们不经过外部调用方，编译期也查不出来。

### 补齐的命名一致性

| 原子 | 改动 | 理由 |
|---|---|---|
| `equipItem` | `item` → `equippedItem` | 对齐 `placedBlock` / `dugBlock`（名字说清动作） |
| `dropItem` | `item` → `droppedItem` | 同上 |
