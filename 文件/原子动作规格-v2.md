## 0. 通用契约（所有原子共用）

### 0.1 返回值

```js
{ ok: true,  code: 'OK', message: '', data: {...} }        // 成功
{ ok: false, code: '<12选1>', message: '人话', data: {...} } // 失败
```

`code` 只能取自 `atom_contract.js` 的 12 个（`OK/NO_TARGET/NO_PATH/OUT_OF_REACH/NO_TOOL/NO_ITEM/OCCUPIED/NO_SUPPORT/BLOCKED/TIMEOUT/INTERRUPTED/INTERNAL`）。
**不许新增同义词**（"FAILED"/"NOT_FOUND"/"TOO_FAR" 一律不许）。

### 0.2 data 字段白名单

| 字段 | 类型 | 口径 |
|---|---|---|
| `pos` | `{x,y,z}` 整数 | 方块/格子坐标 |
| `dist` | number | **方块中心 → 眼睛** 的直线距离 |
| `count` / `want` | number | 已完成 / 目标 |
| `failed` | `[{pos,code,message}]` | 失败明细 |
| `costMs` | number | **本原子自身**耗时（不含调用方重试） |
| `step` | number | 复合技能里的步骤序号（1 起） |
| `partial` | boolean | 只用于 moveTo：超时/失败但有推进 |
| `existed` | boolean | 只用于 place：目标已经是该方块 |

表外字段 = 违规。确实需要新字段时，**先改这张表**再加代码。

### 0.3 四条硬性要求

| # | 要求 | 理由（都是踩过的坑） |
|---|---|---|
| A | **前置断言**：不满足条件立刻返回明确 code，不尝试 | 否则会在基岩上耗 8 秒，或对着空气挖 |
| B | **后置校验**：做完必须**读世界**确认，不信返回值 | 幽灵方块让「挖完」变假成功；服务端不回应时不报错 |
| C | **单一副作用**：一个原子只干一件事 | `digBlock` 不管走过去、不管捡东西——那是复合层 |
| D | **可中断**：每 100ms 量级检查 `bot.interrupt_code` | 玩家说停必须真停 |

### 0.4 不许做的事

- 不许在原子内部重试（重试属于策略层）
- 不许在原子内部循环找目标（那是复合层）
- 不许直接写 `bot.entity.position`（会和服务端位置不同步 → 被踢）
- 不许硬编码游戏常量：距离/眼高从 `rules.runtime.js` 取（`digReach()` / `EYE_HEIGHT`）

### 0.5 测试要求

每个原子必须有独立测试脚本 `tools/atom_<名字>.mjs`，在**测试服 25566**（超平坦）跑：

- 至少覆盖「正常成功」+「每个失败码各一次」
- 输出格式统一：`PASS <用例> <证据>` / `FAIL <用例> <实际>`
- 退出码：全过 0，有失败 1

## 1. moveTo —— 移动

```js
moveTo(bot, x, y, z, opts) -> { ok, code, data: {pos, dist, partial?, costMs} }
```

| 段 | 内容 |
|---|---|
| **前置** | `interrupt_code` 已置 → `INTERRUPTED`；坐标非有限数 → `INTERNAL` |
| **执行** | `pathfinder.goto(GoalNear(x,y,z,tol))`，**不 await**，轮询 100ms |
| **后置** | 到达判据：`到目标中心距离 ≤ tol + 0.6`；否则 `NO_PATH` |
| **partial** | 超时或失败但推进 ≥3 格 → `ok + partial:true`（借鉴 Baritone 的 partial path：让上层从当前位置重规划，而不是整段作废） |
| **失败码** | `INTERRUPTED` / `TIMEOUT` / `NO_PATH`（无路或没走到）/ `BLOCKED`（goal 被别的动作改掉）/ `INTERNAL` |
| **opts** | `tol=1`、`timeout=30000`、`canDig=false`、`scaffold=false` |

**已验证行为**（2026-10-24，主服实测）：局部超时但在推进时返回 `partial`，上层可以直接续跑；`pathfinder.stop()` 必须在超时分支调用，否则下一次 `goto` 报 "Path was stopped"。

## 2. digBlock —— 挖掉一个方块

```js
digBlock(bot, pos, opts) -> { ok, code, data: {block, pos, costMs} }
```

| 段 | 内容 |
|---|---|
| **前置** | 无方块 → `NO_TARGET`；不可挖（基岩/水/岩浆/空气）→ `NO_TARGET`；**眼睛到方块中心 > `digReach()`** → `OUT_OF_REACH` |
| **执行** | 自动换最优工具（`pathfinder.bestHarvestTool`）；挖不动且没有更好工具 → `NO_TOOL`；超时按 `digTime*2+500ms` → `TIMEOUT` |
| **后置** | `waitGone` 轮询 80ms，最多 `extraMs=1500`，确认变成空气；否则 `TIMEOUT`「挖了但还在」 |
| **失败码** | `NO_TARGET` / `OUT_OF_REACH` / `NO_TOOL` / `TIMEOUT` / `INTERRUPTED` / `INTERNAL` |

**关键规则（勿改）**：
- 可达判据**只看距离，不查视线** —— R3-02 实测：中间挡一层树叶，`raycast` 命中树叶，但 `bot.dig` 照样挖到后面的原木。加视线检查会让整片丛林被判"够不着"。
- 距离阈值取 `digReach()`（=5.1，保守值）。R3-01 实测服务端在 6.10 格仍接受，但不要贴着边界跑。

## 3. placeBlockAt —— 放一个方块

```js
placeBlockAt(bot, pos, item, opts) -> { ok, code, data: {block, pos, support, existed?} }
```

| 段 | 内容 |
|---|---|
| **前置** | 已经是该方块 → `ok + existed:true`（幂等）；目标不可替换（非 air/草/水/藤等）→ `OCCUPIED`；背包没有 → `NO_ITEM`；无支撑面 → `NO_SUPPORT` |
| **支撑** | 按「下 → 四侧 → 上」顺序找；**不在箱子/门/床/告示牌/按钮/拉杆等可交互方块上放**（放了会打不开） |
| **执行** | `bot.placeBlock`，面朝支撑面；不往自己脚下/身上放 |
| **后置** | 复核该位置真的变成 `item`（幽灵方块） |
| **失败码** | `NO_TARGET` / `OCCUPIED` / `NO_ITEM` / `NO_SUPPORT` / `OUT_OF_REACH` / `TIMEOUT` / `INTERRUPTED` / `INTERNAL` |

**绝不拆已有方块**：目标是别的方块时返回 `OCCUPIED` 让上层换地方，不代替上层做决定。

## 4. equipItem —— 换手持/护甲

```js
equipItem(bot, name, destination='hand') -> { ok, code, data: {item, count} }
```

| 段 | 内容 |
|---|---|
| **前置** | 背包没有 → `NO_ITEM` |
| **执行** | `bot.equip` |
| **后置** | `destination==='hand'` 时核对 `bot.heldItem.name === name`；不符 → `NO_ITEM`「没换上」 |
| **失败码** | `NO_ITEM` / `INTERNAL` |

配套 `dropItem(bot, name, count)`：丢出 n 个，`data.dropped` 是实际丢出的数量（可能小于请求）。

## 5. openContainer —— 打开容器（use 第 1 类）

```js
openContainer(bot, pos, opts) -> { ok, code, data: {kind, pos, slots?, windowTitle} }
```

**覆盖方块**（按注册表判定，不写死名单）：`chest` / `trapped_chest` / `barrel` / `ender_chest` / `hopper` / `dropper` / `dispenser` / `shulker_box` / `furnace` 系 / `smoker` / `blast_furnace` / `brewing_stand` / `enchanting_table` / `crafting_table` / `anvil` 系 / `stonecutter` / `smithing_table` / `loom` / `cartography_table` / `grindstone` / `lectern`

| 段 | 内容 |
|---|---|
| **前置** | 方块不是容器 → `NO_TARGET`；距离 > 4.5（`GOAL_LOOK_AT_DEFAULT_REACH`）→ `OUT_OF_REACH`；已有窗口开着 → `BLOCKED` |
| **执行** | `bot.openContainer(block)` 或 `bot.openBlock`（工作站类无 GUI 的走 `useBlock` 分支） |
| **后置** | `bot.currentWindow` 非空，且 `windowTitle`/槽位数与方块类型匹配 |
| **失败码** | `NO_TARGET` / `OUT_OF_REACH` / `BLOCKED` / `TIMEOUT` / `INTERRUPTED` / `INTERNAL` |

**为什么单独一个文件**：打开容器有副作用（占住窗口、得关），归到泛化 `use` 里会和门/床/工作站的语义搅在一起。

## 6. useBlock —— 交互（use 第 2~4 类）

```js
useBlock(bot, pos, opts) -> { ok, code, data: {kind, pos, state} }
// kind: 'door' | 'bed' | 'workstation' | 'crop'
```

| kind | 覆盖 | 前置 | 后置（读世界） |
|---|---|---|---|
| `door` | `*_door` / `*_trapdoor` / `*_fence_gate` | 可交互、距离 ≤4.5 | `open` 属性翻转 |
| `bed` | `*_bed` | 是床、在白天/夜晚行为不同 → 只做"上床/下床" | `bot.isSleeping` 变化 |
| `workstation` | 熔炉/工作台/铁砧/砂轮/织布机/切石机 | 无 GUI 的直接右键，有 GUI 的走 `openContainer` | 目标方块状态或窗口开 |
| `crop` | 小麦/胡萝卜/马铃薯/甜菜根 | `age` 达到成熟 | 收获后该格变 air 或 age 归零 |

| 段 | 内容 |
|---|---|
| **前置** | 不认识的方块 → `NO_TARGET`（**不猜**）；距离 > 4.5 → `OUT_OF_REACH` |
| **分派** | 按注册表名判 kind，**不许一个泛化动作硬套**（容器/门/床/农作物的语义差太远） |
| **失败码** | `NO_TARGET` / `OUT_OF_REACH` / `BLOCKED`（已被占用/无法交互）/ `TIMEOUT` / `INTERRUPTED` / `INTERNAL` |

**首版范围**：门 / 床 / 工作站 / 农作物四类。
**明确不做**（但代码里 `skills.js` 现成的保留）：交易、骑乘、喂食。

## 7. attackEntity —— 攻击实体

```js
attackEntity(bot, entity, opts) -> { ok, code, data: {target, hp?, killed?} }
```

| 段 | 内容 |
|---|---|
| **前置** | 实体无效/已消失 → `NO_TARGET`；距离 > 3.0（近战）→ `OUT_OF_REACH`；当前有窗口开着 → `BLOCKED` |
| **执行** | `bot.pvp.attack(entity)`；没有 pvp 时退回 `bareAttack` |
| **后置** | 实体 `isValid === false` 或距离 > 8 → 视为结束；否则 `TIMEOUT` |
| **失败码** | `NO_TARGET` / `OUT_OF_REACH` / `BLOCKED` / `TIMEOUT` / `INTERRUPTED` / `INTERNAL` |

**硬前置：必须加载 `mineflayer-pvp`。** 实测（2026-10-24）：不加载时走 `bareAttack` 兜底，
对着 2 格外的僵尸连打 8~11 秒**一滴血不掉**；加载后 3 秒打死。所以这不是"优化项"，是前置条件。

**实体类别判据（实测踩过）**：mineflayer 的 `entity.type` 用 minecraft-data 的 category ——
僵尸是 `'hostile'`，牛是 `'animal'`，**不是 `'mob'`**。写 `type === 'mob'` 会把僵尸全排除。
可攻击判据：`type ∈ {hostile, animal, passive, mob, water_creature, ambient}` 或带 `health` 字段，
并排除 `player / item / projectile / 载具 / 装饰实体`。

**血量读不到是正常的**：mineflayer 默认不把 `Health` metadata 暴露到 `entity.health`（实测恒为 `undefined`）。
所以死亡判据不能依赖血量，要用 `isValid`（客户端）或 RCON 查询（服务端权威）。

### 本轮修掉的 2 个真 bug（都是 NaN 传播）

| bug | 后果 | 修法 |
|---|---|---|
| `moveTo` 入口不校验坐标 | 位置为 NaN 时 `advanced` 变成 NaN（日志出现「只前进 NaN 格」） | 入口加 `isFinitePos` 守卫 |
| `moveTo` / `moveToXZ` **出口**不校验 | `NaN > tol+0.6` 为 false → **静默判为"到达"**，不可达目标返回 `ok` | 出口加 `Number.isFinite(dist)` 守卫 |

第 2 条尤其危险：它让"走不到"变成"走到了"，上层会基于假状态继续做事。
这个 bug 只有把测试断言从「必须返回 NO_PATH」改成「不许谎称到达」才暴露出来。

### 测试基础设施的教训

| 现象 | 根因 | 修法 |
|---|---|---|
| 修一个坏一个 | 所有测试共享同一个持久世界的坐标 | 每个测试分配独立区域（-500/-400/-300/-200） |
| `setblock` 后读到 air | 客户端还没收到方块更新 | `setAndConfirm`：写完校验，不生效重试 |
| 大范围 `fill` 导致被踢 | 1361 个方块更新让客户端处理不过来，位置包延迟 → `Invalid move` | 不改造地形；超平坦本身是平的 |
| 生存模式频繁被踢 | 超平坦世界里生存模式位置包更敏感 | 测试用 creative + `stopFlying()`（物理与生存一致） |

### `partial` 的正确理解（曾误判为 bug）

目标不可达但推进了 >3 格时，`moveTo` 返回 `ok + partial:true`。这是 Baritone 的 partial path 设计
（让上层从当前位置续跑，而不是整段作废），**不是 bug**。

正确的验收断言是：
- 不许**谎称到达**（`ok` 且 `partial` 不为 true）
- 返回的 `distFeetToPoint` 必须与实际距离一致

**测试环境**：测试服 25566（超平坦，可自由造场景）。主服 25565 只用于 S2/S3 真实地形验收。

### 测试服环境调整（本次必需）

| 项 | 原值 | 现值 | 原因 |
|---|---|---|---|
| `server-test/server.properties: difficulty` | `peaceful` | `normal` | 和平难度下敌对生物一生成就被移除 |
| `server-test/server.properties: spawn-monsters` | `false` | `true` | Paper 里这个开关**连 `summon` 也拦**，僵尸连 `entitySpawn` 事件都不触发 |

**这不是可选项**：不改这两个值，`atom_attack` 的测试无法进行（实测僵尸 `summon` 返回成功，但客户端 `entitySpawn` 从不触发、服务端 `@e[type=zombie]` 查不到）。
